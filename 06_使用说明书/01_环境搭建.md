## 0. 先记住四条环境铁律

1. **全程禁用 conda/venv 装环境与跑仿真**（HIT 原话："conda 会对 ros2 gazebo 等硬件相关工具的环境变量造成巨大篡改，导致难以解释的错误"）。已装 conda 的先：
   ```bash
   conda deactivate
   conda config --set auto_activate false    # 禁止自动激活 base
   ```
   唯一例外：ArduPilot 官方脚本自建的 venv 自动管理，不用管。
2. **Jetson 上 pip 保持 `numpy<2`**——装 onnx 曾把 numpy 升到 2.2.6，系统 cv2（numpy1 ABI）直接炸（`numpy.core.multiarray failed to import`）。解法：`pip install "numpy<2.0.0" --force-reinstall`。
3. **Jetson 直连 GitHub 不通**——默认路线是 Windows 中转（scp/tar over ssh）；Watt Toolkit 加速是备选路线（§3）。
4. **pip 一律走清华镜像**（PyPI 直连会 hang）：`pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple`。

## 2. Linux 基础（只列本项目天天用的）

- **隐藏文件**：名字前面带点的文件（如 `.bashrc`）用 `ls -a` 或文件管理器"查看隐藏文件"才可见；
- **`source` 与执行脚本不是一回事**：`source setup.bash` 在当前 shell 生效（环境变量留下），`bash setup.bash` 是子进程（退出即失效）——ROS 环境必须 `source`；
- **`~/.profile` vs `~/.bashrc`**：登录 shell 读前者、交互非登录读后者；改完 `source ~/.profile`（**最前面的小点不能丢**，`. ~/.profile` 等价）；
- **vi 最小操作**：`i` 插入 → 编辑 → `Esc` → `:wq!` 保存退出；
- **中文环境**（可选，只给台式开发机；⚠️ 机载 Jetson 不建议改系统语言——远程排障时英文报错更好搜）：
  ```bash
  sudo apt install language-pack-zh-hans language-pack-gnome-zh-hans
  sudo update-locale LANG=zh_CN.UTF-8
  # 重启生效；输入法装 fcitx 拼音：
  sudo apt-get install fcitx-bin fcitx-table
  # 系统设置 → 区域和语言 → 键盘输入法系统选 fcitx → 应用到整个系统 → 重启
  ```
- ⚠️ **非交互 ssh 不读 .bashrc**：远程拉节点前显式 `source /opt/ros/humble/setup.bash` + FASTRTPS profile（实测坑）。

## 3. GitHub 加速（Watt Toolkit，备选路线）

> 默认走 Windows 中转（§0 铁律 3）；需在 Linux 侧直接 clone 时用 HIT 验证过的 Watt Toolkit 路线。

```bash
sudo apt update
sudo apt install libnss3-tools jq zenity       # 依赖
curl -sSL https://steampp.net/Install/Linux.sh | bash
```

装好后软件内勾选 GitHub 一键加速。三个已知坑（HIT 实录）：

| 坑 | 解法 |
|---|---|
| 桌面 `.desktop` 没有可执行权限 | `gio set ./Watt\ Toolkit.desktop metadata::trusted true` + `chmod +x` |
| Firefox 报 github.com 证书隐患（HSTS） | Watt Toolkit → 加速设置 → 打开证书文件夹 → 把 `SteamTools.Certificate.cer` 导入 Firefox 证书颁发机构并勾选信任 |
| git clone 报 `server certificate verification failed` | **一劳永逸**：根证书装进系统 CA——`sudo cp <证书路径>/SteamTools.Certificate.cer /usr/local/share/ca-certificates/watt-toolkit.crt && sudo update-ca-certificates`；**应急**：`git -c http.sslVerify=false clone ...`（仅当次有效） |
| Python 脚本下载 GitHub 内容仍报 SSL | `export SSL_CERT_FILE=/etc/ssl/certs/ca-certificates.crt` + `export REQUESTS_CA_BUNDLE=同值`（写 ~/.bashrc） |

**验收**：`git clone --depth 1 https://github.com/ArduPilot/ardupilot_gazebo` 成功。

## 4. SSH 与免密（Windows ↔ Jetson）

### 4.1 Linux 侧（Jetson 出厂已开 sshd）

```bash
ssh -V                                    # 查 OpenSSH 客户端
sudo apt install openssh-server           # 没有才装
sudo systemctl enable --now sshd          # 开机自启 + 立即启动
sudo systemctl status sshd                # 验收：active (running)
```

安全加固（`sudo nano /etc/ssh/sshd_config`）：`PermitRootLogin no`（禁 root 直登），改完 `sudo systemctl restart sshd`。

### 4.2 Windows 侧免密（本项目定案做法）

```powershell
# 1. 生成密钥（一路回车）
ssh-keygen -t ed25519
# 2. 公钥装入 Jetson —— 不要在 MobaXterm 里手敲（括号粘贴坑）
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh nvidia@<Jetson IP> "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
# 3. 配别名（编辑 C:\Users\<你>\.ssh\config）：
#    Host jetson
#      HostName <Jetson IP>
#      User nvidia
```

**验收**：`ssh jetson` 免密直进。

⚠️ 两条实测：① **走局域网别走 USB RNDIS**（虚拟网卡阵发丢包 60%+，仅应急）；② Jetson 出厂 sudo 密码是 `nvidia`，装完环境建议改掉。热点切换会导致 IP 变更——连不上先 ping 新 IP / python 并发扫 22 端口定位，更新 ssh config。

## 5. WSL2（可选：Windows 侧 Linux）

1. `Win + R` → `optionalfeatures` → 勾选"适用于 Linux 的 Windows 子系统"+"虚拟机平台" → **重启**；
2. PowerShell（管理员）：
   ```powershell
   wsl --install -d Ubuntu-22.04 --location D:\WSL\Ubuntu
   ```
   `-d Ubuntu-22.04` 指定 LTS 版；`--location` 装到非系统盘；
3. ⚠️ 首次安装可能不弹用户名/密码设置终端——**重启电脑后重跑同一条命令**即进入用户创建；
4. 装完 `sudo apt update && sudo apt upgrade -y`；`/mnt/c/...` 透视 Windows 文件，`cd ~` 回 Linux 家目录干活。

**验收**：`wsl -l -v` 显示 Ubuntu-22.04 VERSION 2。

## 8. ArduPilot SITL（源码编译）

### 8.1 源码与依赖

```bash
sudo apt update && sudo apt install -y git wget python3-pip python3-venv gcc-multilib g++-multilib python-is-python3
cd ~
git clone --recurse-submodules https://github.com/ArduPilot/ardupilot.git   # 约 1.5GB 含子模块
cd ardupilot
git checkout Copter-4.5 && git submodule update --init --recursive   # 稳定分支；铁律：记录 git 号
Tools/environment_install/install-prereqs-ubuntu.sh -y     # 官方依赖一键（自建 venv 自动管理）
. ~/.profile
```

⚠️ Jetson 实录差异：GitHub 不通 → Windows 浅克隆（`--depth 1`）tar 推送；浅克隆无 tags → 编译时 `git describe` 失败 → **本地打 tag**；Windows 中转源码可能带 CRLF → `sed -i '1s/\r$//' waf-light`（shebang 变 `python3\r` 会 exec 127）；`python` 命令不存在 → `apt install python-is-python3`。

### 8.2 编译 SITL

```bash
cd ~/ardupilot
./waf configure          # waf 别名失效就用 ./waf
./waf build --target bin/arducopter
# 成功标志：Build commands succeeded；产物 build/sitl/bin/arducopter
```

（Jetson 实测 6min29s。）`~/.profile` 加别名：`alias waf="$HOME/ardupilot/modules/waf/waf-light"`。

### 8.3 验证

```bash
cd ~/ardupilot/Tools/autotest
python3 ./sim_vehicle.py -v ArduCopter --console --map
```

成功标志：Console/Map/ArduCopter 三窗口，14550 出 MAVLink。
⚠️ 两条实录：① 非登录 shell 的 PATH 无 `~/.local/bin` → sim_vehicle 报 mavproxy.py 不存在并 "Killing tasks"（arducopter 可能成孤儿）——脚本显式 `export PATH=$HOME/.local/bin:$PATH`；② 新版 SITL 配 Gazebo 必须显式 `--model JSON`（配 gazebo-iris）或 `--model quad`（纯 SITL）。

## 9. Gazebo Harmonic + ardupilot_gazebo 插件

### 9.1 装 Gazebo Harmonic

> 版本定案：Ubuntu 22.04 的 LTS Fortress **与 ArduPilot 不兼容**；Classic 11 配置失败 → **Harmonic**。

```bash
sudo apt-get update
sudo apt-get install curl lsb-release gnupg
sudo curl https://packages.osrfoundation.org/gazebo.gpg --output /usr/share/keyrings/pkgs-osrf-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/pkgs-osrf-archive-keyring.gpg] http://packages.osrfoundation.org/gazebo/ubuntu-stable $(lsb_release -cs) main" | sudo tee /etc/apt/sources.list.d/gazebo-stable.list > /dev/null
sudo apt-get update
sudo apt-get install gz-harmonic
```

（之后 `apt update` 有一条 keyring warning 属正常。）验收：`gz` 打印命令帮助列表。

### 9.2 编译 ardupilot_gazebo 插件

```bash
sudo apt update
sudo apt install libgz-sim8-dev rapidjson-dev
sudo apt install libopencv-dev libgstreamer1.0-dev libgstreamer-plugins-base1.0-dev \
  gstreamer1.0-plugins-bad gstreamer1.0-libav gstreamer1.0-gl

git clone https://github.com/ArduPilot/ardupilot_gazebo      # Jetson：Windows 克隆后 scp/tar 推送
cd ardupilot_gazebo
mkdir build && cd build
cmake .. -DCMAKE_BUILD_TYPE=RelWithDebInfo
make -j4        # 产物 libArduPilotPlugin.so
```

### 9.3 环境变量（关键，两个坑都在这）

```bash
echo 'export GZ_SIM_SYSTEM_PLUGIN_PATH=$HOME/ardupilot_gazebo/build:${GZ_SIM_SYSTEM_PLUGIN_PATH}' >> ~/.bashrc
echo 'export GZ_SIM_RESOURCE_PATH=$HOME/ardupilot_gazebo/models:$HOME/ardupilot_gazebo/worlds:${GZ_SIM_RESOURCE_PATH}' >> ~/.bashrc
source ~/.bashrc
```

- ⚠️ **`GZ_SIM_RESOURCE_PATH` 尾部不能留空分号**：空尾项会毁掉整个解析、**所有模型静默加载失败**（世界只剩 clock/stats，GUI 空实体树）——写进启动器时用条件追加；
- 上游 launch/脚本硬编码的 `/home/accelerate/` 要改成实际路径。

### 9.4 验证（含 NVIDIA 渲染三连）

```bash
# 终端1：Gazebo + 示例世界
gz sim -v4 -r ~/ardupilot_gazebo/worlds/iris_runway.sdf
# 终端2：SITL 连 Gazebo
cd ~/ardupilot/Tools/autotest
python3 ./sim_vehicle.py -v ArduCopter -f gazebo-iris --model JSON --map --console
# 起飞四连（一行一行输，别整段粘贴）：mode guided / arm throttle / takeoff 10
```

NVIDIA 独显机器画面全白/卡死时：

```bash
export __NV_PRIME_RENDER_OFFLOAD=1
export __GLX_VENDOR_LIBRARY_NAME=nvidia
export __VK_LAYER_NV_optimus=NVIDIA_only
# 还不行（最后一招，CPU 软渲染，重但能跑）：
export LIBGL_ALWAYS_SOFTWARE=1
```

`arm throttle` 后 Console 要看到 `Got COMMAND_ACK: COMPONENT_ARM_DISARM: ACCEPTED`，没看到就重发。
**本项目日常不需要手动走 §9.4**——`reset_sim.sh`/`fc_task.sh` 已封装好（讲解见 [06_机载软件](06_机载软件.md) §5，操作见 [07_仿真操作](07_仿真操作.md)）。

## 12. 卸载 Gazebo（错装版本清理）

```bash

```
