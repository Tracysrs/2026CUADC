## 0. 先记住四条环境铁律

1. **全程禁用 conda/venv 装环境与跑仿真**（HIT 原话："conda 会对 ros2 gazebo 等硬件相关工具的环境变量造成巨大篡改，导致难以解释的错误"）。已装 conda 的先：
   ```bash
   conda deactivate
   conda config --set auto_activate false    # 禁止自动激活 base
   ```
   唯一例外：ArduPilot 官方脚本自建的 venv 自动管理，不用管。
2. **Jetson 上 pip 保持 `numpy<2`**——装 onnx 曾把 numpy 升到 2.2.6，系统 cv2（numpy1 ABI）直接炸（`numpy.core.multiarray failed to import`）。HIT 在 SITL 端踩到同款（NumPy 1.x 模块跑在 2.2.6 上），解法同源：`pip install "numpy<2.0.0" --force-reinstall`。
3. **Jetson 直连 GitHub 不通**——默认路线是 Windows 中转（scp/tar over ssh）；Watt Toolkit 加速是备选路线（§3）。
4. **pip 一律走清华镜像**（PyPI 直连会 hang）：`pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple`。

## 2. Linux 基础（只列本项目天天用的）

- **隐藏文件**：名字前面带点的文件（如 `.profile`、`.bashrc`）文件管理器里"查看隐藏文件"才可见，或 `ls -a`；
- **`source` 与执行脚本不是一回事**：`source setup.bash` 在当前 shell 生效（环境变量留下），`bash setup.bash` 是子进程（退出即失效）——ROS 环境必须 `source`；
- **`~/.profile` vs `~/.bashrc`**：登录 shell 读前者、交互非登录读后者；改完 `source ~/.profile`（注意**最前面的小点不能丢**，`. ~/.profile` 等价写法）；
- **vi 最小操作**（改配置文件够用）：`i` 进入插入 → 编辑 → `Esc` → `:wq!` 保存退出；
- **中文环境**（可选，改编自 HIT 配置中文.docx）：
  ```bash
  sudo apt install language-pack-zh-hans language-pack-gnome-zh-hans
  sudo update-locale LANG=zh_CN.UTF-8
  # 重启生效；输入法装 fcitx 拼音：
  sudo apt-get install fcitx-bin fcitx-table
  # 系统设置 → 区域和语言 → 键盘输入法系统选 fcitx → 应用到整个系统 → 重启
  # Ctrl+空格 切换中/英文
  ```
  ⚠️ **机载 Jetson 不建议改系统语言**——远程排障时英文报错更好搜；本文中文配置只给台式开发机。

## 3. GitHub 加速（Watt Toolkit，备选路线）

> 本项目默认走 Windows 中转（§0 铁律 3）；若需要在 Linux 侧直接 clone（如台式开发机），用 HIT 验证过的 Watt Toolkit 路线。

```bash
sudo apt update
sudo apt install libnss3-tools jq zenity       # 依赖
curl -sSL https://steampp.net/Install/Linux.sh | bash
```

装好后软件内勾选 GitHub 一键加速。三个已知坑（HIT 实录）：

| 坑 | 解法 |
|---|---|
| 桌面 `.desktop` 没有可执行权限 | `gio set ./Watt\ Toolkit.desktop metadata::trusted true` + `chmod +x` |
| Firefox 报 github.com 证书隐患（HSTS） | Watt Toolkit → 加速设置 → 打开证书文件夹 → 把 `SteamTools.Certificate.cer` 导入 Firefox 的证书颁发机构并勾选信任 |
| git clone 报 `server certificate verification failed` | **一劳永逸**：把根证书装进系统 CA——`sudo cp <证书路径>/SteamTools.Certificate.cer /usr/local/share/ca-certificates/watt-toolkit.crt && sudo update-ca-certificates`；**应急**：`git -c http.sslVerify=false clone ...`（仅当次有效） |
| Python 脚本下载 GitHub 内容仍报 SSL（urllib 用自己的 CA 包） | `export SSL_CERT_FILE=/etc/ssl/certs/ca-certificates.crt` + `export REQUESTS_CA_BUNDLE=同值`（写 ~/.bashrc 免每次） |

**验收**：`git clone --depth 1 https://github.com/ArduPilot/ardupilot_gazebo` 成功。

## 4. SSH 与免密（Windows ↔ Jetson）

### 4.1 Linux 侧（Jetson 出厂已开 sshd；通用 Linux 按 HIT SSH 教程）

```bash
ssh -V                                    # 查 OpenSSH 客户端
sudo apt install openssh-server           # 没有才装
sudo systemctl enable --now sshd          # 开机自启 + 立即启动
sudo systemctl status sshd                # 验收：active (running)
```

安全加固（`sudo nano /etc/ssh/sshd_config`）：改 `Port 22`（可选）、`PermitRootLogin no`（禁 root 直登），改完 `sudo systemctl restart sshd`。

### 4.2 Windows 侧免密（本项目定案做法）

```powershell
# 1. 生成密钥（一路回车）
ssh-keygen -t ed25519
# 2. 公钥装入 Jetson —— 不要在 MobaXterm 里手敲（括号粘贴坑）
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh nvidia@10.66.24.217 "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
# 3. 配别名（编辑 C:\Users\<你>\.ssh\config）：
#    Host jetson
#      HostName 10.66.24.217
#      User nvidia
```

**验收**：`ssh jetson` 免密直进。

⚠️ 项目实测两条：① **走局域网别走 USB RNDIS**（虚拟网卡阵发丢包 60%+，仅应急）；② Jetson 出厂 sudo 密码是 `nvidia`，装完环境建议改掉。

## 5. WSL2（可选：Windows 侧 Linux）

> 适用：想在 Windows 上本地跑 ROS/轻量测试、不想装双系统。改编自 HIT 安装 WSL2.docx。

1. `Win + R` → `optionalfeatures` → 勾选"适用于 Linux 的 Windows 子系统"+"虚拟机平台" → **重启**；
2. PowerShell（管理员）：
   ```powershell
   wsl --install -d Ubuntu-22.04 --location D:\WSL\Ubuntu
   ```
   `-d Ubuntu-22.04` 指定 LTS 版；`--location` 装到非系统盘（默认 C 盘会被依赖撑爆）；
3. ⚠️ 实录坑：首次安装可能不弹用户名/密码设置终端——**重启电脑后重跑同一条命令**即进入用户创建；
4. 装完 `sudo apt update && sudo apt upgrade -y`；`/mnt/c/...` 是透视 Windows 文件，`cd ~` 回 Linux 家目录干活。

**验收**：`wsl -l -v` 显示 Ubuntu-22.04 VERSION 2。

## 8. ArduPilot SITL（源码编译）

改编自 HIT Gazebo 仿真环境教程 §2，融合我们 Jetson 实录（09-07/09-10）。

### 8.1 源码与依赖

```bash
sudo apt update && sudo apt install -y git wget python3-pip python3-venv gcc-multilib g++-multilib python-is-python3
cd ~
git clone --recurse-submodules https://github.com/ArduPilot/ardupilot.git   # 约 1.5GB 含子模块
cd ardupilot
git checkout Copter-4.5 && git submodule update --init --recursive   # HIT 推荐稳定分支（我们 Jetson 上编译的是当时 master，铁律：记录 git 号）
# 官方依赖一键脚本（自动建 venv，无需手动干预）：
Tools/environment_install/install-prereqs-ubuntu.sh -y
. ~/.profile
```

⚠️ 我们 Jetson 的实录差异：GitHub 不通 → Windows 浅克隆（`--depth 1`）tar 推送；浅克隆没有 tags 会导致编译时 `git describe` 失败 → **本地打 tag**；Windows 中转的源码可能带 CRLF → `sed -i '1s/\r$//' waf-light`（shebang 变 `python3\r` 会 exec 127）；`python` 命令不存在 → `apt install python-is-python3`。

### 8.2 编译 SITL

```bash
cd ~/ardupilot
./waf configure          # waf 别名失效就用 ./waf（检查 ~/.profile / ~/.bashrc）
./waf build --target bin/arducopter
# 成功标志：Build commands succeeded；产物 build/sitl/bin/arducopter
```

（Jetson 实测 6min29s。）`~/.profile` 里加 waf 别名：`alias waf="$HOME/ardupilot/modules/waf/waf-light"`。

### 8.3 验证

```bash
cd ~/ardupilot/Tools/autotest
python3 ./sim_vehicle.py -v ArduCopter --console --map
```

成功标志：Console/Map/ArduCopter 三窗口，14550 端口出 MAVLink。
⚠️ 我们实录两条：① 非**登录 shell 的 PATH 无 `~/.local/bin`** → sim_vehicle 报 mavproxy.py 不存在并 "Killing tasks"（杀全家，arducopter 可能成孤儿）——脚本里显式 `export PATH=$HOME/.local/bin:$PATH`；② 新版 SITL 配 Gazebo 必须显式 `--model JSON`（配 gazebo-iris）或 `--model quad`（纯 SITL）。

## 9. Gazebo Harmonic + ardupilot_gazebo 插件

### 9.1 装 Gazebo Harmonic

> 版本选择（HIT 结论，我们 09-09 复核）：Ubuntu 22.04 的 LTS 是 Fortress 但**与 ArduPilot 不兼容**；Classic 11 配置失败且不好用 → **Harmonic**。

```bash
sudo apt-get update
sudo apt-get install curl lsb-release gnupg
sudo curl https://packages.osrfoundation.org/gazebo.gpg --output /usr/share/keyrings/pkgs-osrf-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/pkgs-osrf-archive-keyring.gpg] http://packages.osrfoundation.org/gazebo/ubuntu-stable $(lsb_release -cs) main" | sudo tee /etc/apt/sources.list.d/gazebo-stable.list > /dev/null
sudo apt-get update
sudo apt-get install gz-harmonic
```

（之后每次 `apt update` 有一条 keyring warning 是正常现象——HIT 原话，密钥加入方式较原始。）
验收：输入 `gz` 应打印命令帮助列表。

### 9.2 编译 ardupilot_gazebo 插件

```bash
# 依赖（Harmonic 对应 libgz-sim8）
sudo apt update
sudo apt install libgz-sim8-dev rapidjson-dev
sudo apt install libopencv-dev libgstreamer1.0-dev libgstreamer-plugins-base1.0-dev \
  gstreamer1.0-plugins-bad gstreamer1.0-libav gstreamer1.0-gl

git clone https://github.com/ArduPilot/ardupilot_gazebo      # 我们 Jetson：Windows 克隆后 scp/tar 推送
cd ardupilot_gazebo
mkdir build && cd build
cmake .. -DCMAKE_BUILD_TYPE=RelWithDebInfo
make -j4        # 产物 libArduPilotPlugin.so
```

### 9.3 环境变量（关键，两个坑都在这）

```bash
echo 'export GZ_SIM_SYSTEM_PLUGIN_PATH=$HOME/ardupilot_gazebo/build:${GZ_SIM_SYSTEM_PLUGIN_PATH}' >> ~/.bashrc
echo 'export GZ_SIM_RESOURCE_PATH=$HOME/ardupilot_gazebo/models:$HOME/ardupilot_gazebo/worlds:${GZ_SIM_RESOURCE_PATH}' >> ~/.bashrc
source ~/.bashrc
```

- ⚠️ **`GZ_SIM_RESOURCE_PATH` 尾部不能留空分号**：路径列表出现空尾项会把整个解析搞坏、**所有模型静默加载失败**（世界只剩 clock/stats，GUI 空实体树）——我们在 Windows pixi 版实测（09-10），写进启动器时用条件追加；
- 上游 launch/脚本里硬编码的 `/home/accelerate/`（原作者用户名）要改成实际路径（`start_cuadc_sim.sh` 同病）。

### 9.4 验证（含 NVIDIA 渲染三连）

```bash
# 终端1：Gazebo + iris_runway 示例世界
gz sim -v4 -r ~/ardupilot_gazebo/worlds/iris_runway.sdf
# 终端2：SITL 连 Gazebo
cd ~/ardupilot/Tools/autotest
python3 ./sim_vehicle.py -v ArduCopter -f gazebo-iris --model JSON --map --console
# 起飞四连（一行一行输，别整段粘贴）：
#   mode guided / arm throttle / takeoff 10
```

NVIDIA 独显机器画面全白/卡死时（HIT 实录 + 我们 Jetson `DISPLAY=:0` 同理）：

```bash
export __NV_PRIME_RENDER_OFFLOAD=1
export __GLX_VENDOR_LIBRARY_NAME=nvidia
export __VK_LAYER_NV_optimus=NVIDIA_only
# 还不行（最后一招，CPU 软渲染，重但能跑）：
export LIBGL_ALWAYS_SOFTWARE=1
```

export 只对当前终端有效，每次新终端要重跑（写 ~/.bashrc 可持久化）。
⚠️ Map 窗口没出现飞机图标先耐心等；`arm throttle` 后 Console 要看到 `Got COMMAND_ACK: COMPONENT_ARM_DISARM: ACCEPTED`，没看到就重发（HIT 实录：他们环境里 set_mode/arm 偶发不生效需重试——我们的状态机脚本已做重试与确认）。

**本项目日常不需要手动走 §9.4**——`reset_sim.sh`/`fc_sitl_mission.sh` 已把"裸跑 SITL（砍掉 MAVProxy）+ 无头 GZ + 门禁"封装好（逐段讲解见 05 系统模块 §5.5，操作见 03 操作模块 §5）。

## 12. 卸载 Gazebo（错装版本清理）

> 改编自 HIT 卸载gazebo教程.docx（作者"下错过好几次版本"的总结）。针对 apt 安装的 Gazebo。

```bash
# 1. 找到所有相关包（把输出喂给 AI 写移除命令也行，注意别误删 gzip）
dpkg -l | grep -E "gazebo|gz"
sudo apt remove <上面列出的 gz-* / gz-harmonic 包>
# 2. 验证卸干净没有
which gz          # 无输出 = 干净；有输出（如 /usr/bin/gz）继续：
dpkg -S /usr/bin/gz          # 顺藤摸瓜定位残留包，再 remove
# 3. 最终清理
sudo apt autoremove --purge
rm -rf ~/.gz
sudo rm -rf /usr/share/gz      # 若存在
```

## 14. 自查题

1. 为什么装环境/跑仿真前要 `conda deactivate`？（conda 篡改 ros2/gazebo 环境变量，产生难解释的错误）
2. Jetson 直连 GitHub 不通的两条出路？（Windows 中转 scp/tar——默认；Watt Toolkit 加速——备选）
3. `GZ_SIM_RESOURCE_PATH` 最阴的坑是什么？（尾部空分号 → 所有模型静默加载失败）
4. 浅克隆 ArduPilot 编译会卡在哪？（无 tags → git describe 失败 → 本地打 tag）
5. geographiclib 不装会怎样？（mavros 全球位置数据全 NaN）
6. WSL2 装完没弹用户名设置？（重启电脑重跑安装命令——实测）
7. uninstall 后 `which gz` 还有输出说明什么？（有残留包，`dpkg -S /usr/bin/gz` 顺藤摸瓜）
