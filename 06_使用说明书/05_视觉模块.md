## 0. 模块全景

要训/要部署的模型三件：

| 模型 | 架构 | 数据 | 用途 | 状态 |
|---|---|---|---|---|

## 1. 相机硬件与成像基线

### 1.1 相机规格（BL-500W-335 板机）

| 项 | 规格 |
|---|---|
| 传感器 | 1/2.8"，2.0μm 像元，2592×1944 最高 |
| 镜头 | 2.8mm 定焦，D105° / H81.8° / V66° |
| 输出 | UVC（USB2.0），MJPG / YUY2 |
| 关键帧率 | 1080p@30 (MJPG)、640×480@30 (YUY2) |
| 曝光控制 | 自动曝光/自动白平衡可关；亮度/增益/曝光等 12 项可调 |
| 供电/功耗 | 5V，≤160mA |

用途：下视安装（检筒 + H 圆 + 俯拍标识）。仿真里对应 iris_d435i 的下视 RGB-D（`/d435i/*` 四路话题）。

### 1.2 曝光基线（含未解红线）

**设计基线**（实飞依据）：

- **快门 ≤1/500s**：6m/s 飞行速度下 1/250s 运动模糊 6.4px，直接吃掉小目标；
- **手动锁曝光**参考值 `exposure 120 / gain 64 / 50Hz 工频抗闪`；
- **禁自动曝光**：场地灯光变化时自动曝光会瞬间"失明"，检测全丢；
- 帧率 ≠ 快门速度：30FPS 的相机每帧曝光仍可能 1/60s——**先锁快门再谈帧率**。

> ⚠️ **开放风险（待拍板）**：09-13 上机实测，本台 BL-500W-335 **手动曝光不受控**——`exposure_time_absolute` 写入被接受但固件无视（20~2047 全程亮度不变），无厂商扩展单元可绕。"锁快门 ≤1/500s" 当前无法执行。处置三选一待拍板：换固件工具路径 / 换相机 / 实证户外日光下 AE 短曝光足够稳后豁免。**现行 bench 方案**：手动模式（固件固定短曝光）+ `brightness=48` 补亮 + 开灯拍摄。另：v4l2 控制必须在开流**前**写（流中写入掉 ~1fps 怪模式），`camera_node.py` 已固化此顺序。

### 1.3 对准平面与高度来源

- 高度只用飞控相对高度（TFmini 4m 以下辅助），**不用气压**（2~5m 桨风 ±0.5m 跳变）；
- 瞄准的是**桶口平面**：`alignment_z = 目标参考高 − 0.30m`（筒高 0.30m）。

## 3. 云端训练（AutoDL）

> **现行路线 = yolov8n COCO 预训练直训**（deliver_v2 全流程验证，SSOT §8.2）。旧 v1→v2 微调链已停用（上游类别表为旧 GHS 表）；`run_v2_training.sh` 与《AutoDL租卡训练指南v2.md》保留作租卡操作流程参考。**Jetson 上不训练。**

### 3.1 全流程（五步）

1. **租实例**：autodl.com 充 ¥20 → 按量计费 → **RTX 4090** → 镜像 **PyTorch 2.x + Python 3.10（CUDA 12.x）** → JupyterLab；
2. **上传**（到 `/root/autodl-tmp/`）：数据集 zip + 一键训练脚本（必传）；
3. **一键训练**：`cd /root/autodl-tmp && bash run_v2_training.sh`（脚本含 GPU 检查→装 ultralytics→解压校验→训练→逐类验收判读→打包 deliver，全程 30~60 分钟）；
4. **取结果**：下载 deliver 包——先看 `val_report.txt`（逐类 P/R/mAP50）+ best.pt + dataset_version.md + 混淆矩阵；
5. **停止计费**：下载完**立刻关机**（按量计费关机即停）。**忘记关机是新手烧钱第一名**。

### 3.2 参数铁律（写死在脚本，勿改）

| 参数 | 值 | 原因 |
|---|---|---|
| `epochs` | 150（直训 100ep 亦验证过） | — |
| `lr0` | 从头训 0.01 / 微调 **0.001** | 微调学习率必须降 10 倍，否则冲毁底子 |
| `flipud` | 0.5 | 俯视图上下翻转 = 白赚的增强 |
| `hsv_h` | **0.005** | **色相就是类别特征**（红=易燃、橙=爆炸品）；默认 0.015 制造标签噪声 |
| `close_mosaic` | 10 | 最后 10 轮关 mosaic，贴合真实分布 |

### 3.3 验收判读速查

| 线 | 标准 |
|---|---|
| 逐类 mAP50 | **≥0.90（逐类无豁免）** |
| 漏检率 | <5%（召回 ≥0.95） |

排障：单类偏低先看混淆矩阵和谁混（火焰三件套/白底系是重灾区）→ 确认该类 val 实例数（每类仅 9~32 个，偶发波动正常）；小目标漏检普遍偏高 → `imgsz=1280` 重训并**同步改导出/推理尺寸**；单类断崖 0 → 八成标签类别号错位。

### 4.3 部署铁律

- **engine 与"权重 + 设备"双绑定**：导出一次约 9 分钟——**换权重必须重建 engine；比赛日绝不可现场构建**；
- **黑帧预热**：启动流程固定跑 3 张 CUDA 假图再上岗（吃"上场 1 分钟"规则红利：赛前 suspend，唤醒即跑）；
- **`numpy<2`** 与 **pip 清华镜像**两条 Jetson 铁律（01 册 §0）；
- 上场口径：预加载模型 → 黑帧自检 → suspend → 上场唤醒到首帧 <10s。

### 4.4 systemd 自启（已上线）

- 文件：`03_机载软件/systemd/cuadc-perception.service` + 启动脚本 + `fastrtps_udp_only.xml`；
- 安装一次：单元文件 → `/etc/systemd/system/`，然后 `sudo systemctl enable --now cuadc-perception`；
- 行为：开机自动加载 engine + 3 帧预热后待命（启动→就绪 8~9s 实测）；engine 缺失/SHA 不符拒启，每 10s 重试（fail-closed）；
- 查看：`journalctl -u cuadc-perception -f`（"引擎就绪"行有耗时）；
- **UDP-only profile 必须带**：同机跑仿真栈时 SHM 被搅乱导致节点图不可见（09-12 实测），UDP-only 后恢复。

### 4.5 图像传输定案（压缩透传是唯一可用路）

| 传输方式 | 实测 | 结论 |
|---|---|---|
| raw `Image`（1080p BGR，6MB/帧） | 单帧序列化/发送 ~1s，全链 **1Hz**；RELIABLE 还被慢订阅端流控堵死 | **不可用** |
| JPEG 重编码 `CompressedImage` | ~17Hz（重编码吃 ~20ms/帧） | 可用但没必要 |
| **相机原生 MJPEG 直透**（`CONVERT_RGB=0`，~65KB/帧） | **30fps 全链稳定**，零编码零二次压缩 | ✅ **定案** |

配套三件（缺一不可）：

1. 发布端 QoS **best_effort**；订阅端必须 `image_qos_reliable: false` 匹配——**失配 = 一帧都收不到**；
2. 判读节点订阅 `<image_topic>/compressed`（`image_compressed: true`；生产 yaml **src+install 双份**同步）；
3. `camera_node.py`：v4l2 控制在**开流前**写，每次 `open()` 后自动重设。

## 5. 感知输出与接口契约（感知侧）

> 契约权威文档：`03_机载软件/接口契约.md`（v1.3）。**改接口必须**：双方同意 → bump 版本号与哨兵 → 同步改校验脚本 → 更新契约文档。

### 5.1 检测话题 `/perception/drop_buckets_body`

`geometry_msgs/PoseArray`，每个 Pose = 一个白筒候选，**机体系（frame_id=`cuadc_body_flu`）**：

| 字段 | 复用含义 | 说明 |
|---|---|---|
| `position.x/y/z` | 筒口中心机体系坐标（米） | x 前 y 左 z 上 |
| `orientation.x` | **筒口直径估计**（米） | 状态机用来对号 15/20/25cm |
| `orientation.y` | **置信度** [0,1] | 后处理四件之后的质量分 |
| `orientation.z` | **契约版本哨兵** | 所有 pose 必须一致；不一致 = 违约整帧拒用 |
| `header.stamp` | **取帧时刻** | 不是发布时刻！ |

硬性要求：频率 ≥25Hz；**空帧也必须发**；单帧 ≤8 个；同帧去重（中心距 <2cm）在感知端完成；QoS best_effort。

### 5.2 发布端标准写法（真感知必须复用此语义）

```python
def on_timer(self):
    # 关键契约：stamp = 取帧时刻（= now − 注入延迟），不是发布时刻
    capture_time = self.get_clock().now() - Duration(seconds=self.delay_s)
    msg = PoseArray()
    msg.header.stamp = capture_time.to_msg()
    msg.header.frame_id = self.frame_id          # 'cuadc_body_flu' 哨兵
    for ...:
        pose.orientation.x = d      # 复用：筒口直径（m）
        pose.orientation.y = c      # 复用：置信度 [0,1]
        pose.orientation.z = self.version  # 复用：契约版本哨兵
        msg.poses.append(pose)
    self.bucket_pub.publish(msg)
    # 心跳与检测同源同节奏，空帧也发（fail-closed：停发 = 故障 = 禁投）
    hb = Header(); hb.stamp = capture_time.to_msg(); hb.frame_id = 'node_name'
    self.heartbeat_pub.publish(hb)
```

三要点：① stamp 减去 pipeline_delay 模拟"取帧在先"；② orientation 字段复用带哨兵；③ **心跳与检测同节奏**——消费方靠心跳新鲜度判故障。

### 5.3 时间戳约定（P0.4）

1. `header.stamp` = **图像取帧时刻**（相机驱动回调瞬间）；
2. 管线延迟上界 1.5s、未来戳容差 0.05s、odom 包围两帧最大间隔 0.2s（违反即丢帧，绝不外推）；
3. 所有节点读写 stamp 前换本节点时钟类型（`use_sim_time` 下相减抛异常的隐形坑）。
原理与量级论证见 [09_算法与系统原理](09_算法与系统原理.md) §4。

### 5.4 契约校验（感知端上机门槛）

```bash
ros2 run cuadc_perception check_vision_contract.py --ros-args -p duration_s:=10.0 -p min_rate_hz:=15.0
```

### 5.5 侦察判读消息定义（`cuadc_interfaces/msg/`）

```text
# ReconClassification.msg —— 融合判读输出（组员据此填单）
std_msgs/Header header           # stamp = 融合窗口末帧的取帧时刻
uint32 viewpoint_seq             # 对应 capture_request 的 point.x 序号
ReconMarker[] markers            # 本窗口结论，可空数组

# ReconMarker.msg —— 单个物理标识结论
# class_id = 附件11 的 10 类（0..9，与训练集 data.yaml 顺序一致）
uint32 marker_index      # 本架次内稳定序号
int32 class_id           # 0..9；-1 = 拒识留空（留空 0 分，错填 -100）
float32 confidence       # 融合窗口内该类置信度中位数
float32 margin           # top1-top2 中位数
uint32 frames            # 支持该结论的帧数
bool ambiguous           # true = 竞争被拒识（地面站转人眼备份）
string evidence_path     # 证据目录
```

QoS：Reliable(10)——低频结构化结果一条不许丢（与检测流 best_effort 相反）。

## 6. 侦察判读工程（分类模型的使用侧）

- **帧级拒识双阈值**：top1 < **0.7** 丢；top1−top2 < **0.3** 丢（火焰三件套 6/8/9、白底系 2/4/5/7 是易混重灾区）；**留空是合法答案**（留空 0 分，错填 −100）；
- 灰区 ROI 从**全分辨率原图**裁剪放大重推一次（不在 640 缩图上裁）；
- **证据落盘**：侦察态 1s/张 JPEG + 每条结果存"裁剪图+类别+置信度"JSONL（原子写）；**磁盘剩余 <512MB 告警停证**；
- 标记级融合规则（≥5 帧同意/置信中位数 ≥0.8/票数 ≥3× 次高类）见 09 册原理卷 §10。

### 6.1 桌面真机判读验证操作卡（①~⑨）

> 场景：相机已接 Jetson（`/dev/video0`），**不飞**，真实标识摆在镜头前验证"取流→推理→融合判读→证据落盘"全链。
> 边界：桌面近距离视角 ≠ 4m 俯拍，**本卡验证链路通与判读通道活**；类别精度结论以现场实拍验证集为准。

**① 前置检查（30 秒）**

```bash
ssh jetson   # 下文默认在 Jetson 上、已 source /opt/ros/humble/setup.bash
pgrep -f "camera_node[.]py" && echo 相机在跑 || echo 相机未起
ros2 topic hz /camera/image_raw/compressed   # 期望 ~30Hz
```

pgrep 列出**两个以上 PID = 重复实例**（双实例抢 /dev/video0）——先全清再起一个（kill 与启动分两条命令）。相机没起就拉起（非交互 ssh **不读 .bashrc**，source 必须内联）：

```bash

export FASTRTPS_DEFAULT_PROFILES_FILE=$HOME/cuadc_udp_profile.xml   # 与生产同 profile

sleep 5 && tail -2 /tmp/camera_node.log   # 期望"就绪 … ctrls[auto_exposure=1,brightness=48]"
# 就绪行 "67540x1" 怪分辨率不是故障：MJPG 透传下 frame=一行原生 JPEG 字节 ≈65KB/帧
```

日志仍刷"打不开或读不到帧" = 设备不在 USB 总线（`lsusb` 应见 Realtek 0bda:5180；无 → 查线材/供电/重插；设备重回总线后**节点自动恢复，别反复杀节点**）。

**看画面（机身屏幕，按 q 退）**：前提 Jetson 接屏已登录桌面。自查 `DISPLAY=:0 timeout 3 xdpyinfo >/dev/null 2>&1 && echo X_OK`；然后
`DISPLAY=:0 nohup python3 ~/camera_view.py > /tmp/camera_view.log 2>&1 < /dev/null &`。


看识别框（绿=过门控/橙=灰区/红=拒识）同款换 `detect_view.py`。

**② 关生产服务（防双判读打架）**：systemd 的 `cuadc-perception` 与 bench 实例都订阅 capture_request，会双份判读。桌面验证只留一套：`sudo systemctl stop cuadc-perception`（验完 start 收回）。

**③ 起 bench 判读实例**

```bash
source /opt/ros/humble/setup.bash && source ~/cuadc_ws/install/setup.bash

  --ros-args -r __node:=hazard_recon_bench \

  -p require_recon_state:=false > /tmp/recon_bench.log 2>&1 < /dev/null &
sleep 8 && grep "真判读就绪" /tmp/recon_bench.log
```

三开关含义：`image_compressed`（吃压缩图）；`image_qos_reliable:=false`（与相机 best_effort 匹配）；`require_recon_state:=false`（桌面不发状态机话题，关掉"仅侦察态产出"门）。

**④ 摆靶（摆得好坏直接决定有没有结论）**

| 摆法要点 | 原因 |
|---|---|
| **开灯**，标识朝上、正对相机 | 暗屋 AE 拉长曝光掉帧率；倾斜贴纸失真 |
| 距镜头 **0.5~1.5m**（镜头朝下放地上） | 模型 imgsz=640，标识占画面 **1/10~1/4** 边长最稳 |
| 摆进画面**正中**再发请求 | 2.8mm 广角边缘畸变大 |
| 一个窗口只摆**一个**标识 | 融合按标记关联 |
| 摆好后**保持静止**到窗口结束 | 融合要 ≥5 帧同意，晃动会稀释 |

⚠️ 桌面特写检不出 ≠ 模型坏——**桌面特写严重偏离训练分布**（4m 俯拍训练），按本表摆靶即模拟俯拍几何。

**⑤ 发侦察请求（seq 必须递增）**

```bash
timeout 4 ros2 topic pub -r 1 /cuadc/recon/capture_request \
  geometry_msgs/msg/PointStamped "{point: {x: 3.0}}"   # 下次改 x: 4.0、5.0 …
```

- `point.x` = viewpoint_seq，**重发同号直接忽略**——`-r 1` 跑 4 秒只有第一次生效，其余刷"重复忽略"属正常；
- **不要用 `--once`**：多订阅者时只送达第一个匹配的（其余收不到）；短循环让 DDS 送达全员；
- 发布器也要带 **UDP-only profile**（与生产服务匹配）；窗口 4s 后自动收口。

**⑥ 读结果（三处互印）**

```bash
ros2 topic echo /cuadc/recon/classification      # 判读消息
tail -f /tmp/recon_bench.log                     # 判读日志
ls -t ~/recon_evidence/ | head -3                # 证据落盘（frame_*.jpg + JSONL）
```

| 输出 | 含义 | 处置 |
|---|---|---|
| class_id 与实物一致，confidence ≥0.8 | ✅ 全链判对 | 换下一个 |
| `无结论` 且无"判定丢弃" | 拒识或没检出 | 看证据图复核摆靶，查日志帧打点 |
| `ambiguous: true` | 易混类竞争被拒识 | 预期行为——**赛场上这就是拒识保命逻辑在干活** |

**⑦ 排障速查**

| 现象 | 原因/处置 |
|---|---|
| `ros2 topic hz` 没有话题 | 相机没起（①）或 QoS 不匹配（忘 `image_qos_reliable:=false`） |
| 话题只有 ~1Hz | 走了 raw（yaml 没开压缩图）；或暗屋 AE 长曝光（开灯） |
| bench 起不来 `ModuleNotFoundError: cuadc_interfaces` | 忘了 `source ~/cuadc_ws/install/setup.bash` |
| 请求发了没反应 | seq 重复（换新号）；`--once` 只达首个订阅者；或节点没就绪 |
| "当前状态 ？非侦察态" | bench 忘了 `require_recon_state:=false`；测生产则发状态 `…/mission_state … RECON_SURVEY` |
| 证据目录没生成 | 磁盘 <512MB 停证或 `evidence_enabled` 关着 |
