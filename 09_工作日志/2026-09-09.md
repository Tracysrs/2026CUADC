| M4 | 后右 | 顺时针 | 反桨(R) |

## 二、验收过程

1. **工具**：新写 `03_工具/飞控调试/motor_test.py`——`MAV_CMD_DO_MOTOR_TEST`
   逐电机 25% 油门转 1s（飞控须 DISARMED，脚本自检），支持指定输出口。
2. **第一轮**：四个电机**全部反向**（顺顺逆逆），即出厂恰为 Betaflight 默认方向
   （FR/RL=顺，FL/RR=逆）——全反模式，不是接线错位。
3. **修正**：每个电机三根相线中对调任意两根（×4）。
4. **复测**：M3 单独复核后用户确认——**逆、逆、顺、顺，全对** ✅。

## 三、踩坑：电机测试命令的编号不是输出口

`MAV_CMD_DO_MOTOR_TEST` 的 param1 是**测试序列号**，不是输出口：固件走
`motor_test.cpp → output_test_seq()`，按 `_test_order` 找电机（`AP_MotorsMatrix.cpp:466`）。
Quad X 序列=从右前顺时针：**M1(前右)→M4(后右)→M2(后左)→M3(前左)**。
发 1,2,3,4 实际点亮输出口 M1,M4,M2,M3——表现为"顺时针绕圈"，容易被误判为接错线
（实测观察"前右→后右→后左→前左"正是固件设计行为，反证接线正确）。
脚本内已固化 `OUT2SEQ={1:1,2:3,3:4,4:2}` 换算，按输出口 M1→M4 测试。

## 一、接线定案（依据 04_手册 V6X 手册 + SSOT P1-3）

- 电调信号 → **M1~M4**（IO 侧 PWM）；好盈 XRotor 40A 是 OPTO 无 BEC：电调红线悬空
  包好，飞控只由 PMU 供电，别指望电调给 5V

## 二、供电排障：飞控读数 0.00V

- 现象：电池已接、电调鸣叫（主电到位），但飞控电压 0.00V
- 根因：**PMU 的 6pin 小线没插飞控**——PMU 串在主电路上有电，但与飞控的数据/
  供电链路没建立
- 修复：插 POWER1 → 22.92V 正常。参数侧本来就对（BATT_MONITOR=8 + CAN 驱动），
  不要用 MP 的模拟电源模块向导
- 经验：**主电到位听电调鸣叫，PMU 链路看飞控电压读数**，两个维度独立排查

## 九、解锁试跑：被固件强制层拦截 + 参数机制学费（同日晚，接 §八）

> 目标：临时放宽解锁检查让真飞控解锁跑一遍任务流程，事后恢复参数。工具
> `fc_armrun.sh`（状态机路径）/`fc_armtest.sh`（直接解锁路径），现场日志已归档。

- **结论：解锁被固件强制层拒绝——`Arm: Need Position Estimate`**。可跳过层五项
  （罗盘/加速度计/电池/Radio failsafe/GPS 细项）经 `ARMING_SKIPCHK=-1` 已全部跳过，
  但 GUIDED 声明需要位置（`requires_position()`），EK3 位置源=GPS（未接）→ EKF
  无位置无原点 → `position_ok()`=false → 强制拒绝。源码证据：`AP_Arming_Copter.cpp:467`
  位于 `mandatory_position_checks()` 内 + `AP_Arming.cpp:123` 注释
  "mandatory and non-ARMING_SKIPCHK items"。旧固件 `ARMING_CHECK=0` 无 GPS 硬解锁
  的口子在 4.7（Dec-2025 参数迁移）已收紧
- 状态机路径同样到不了解锁：卡 `WAIT_NAV_STABLE`——`navigation_ready()` 需要
  odom 流，真机无 GPS 时 mavros local_position/odom 根本不出流（与 SITL 的关键
  差异，SITL 有仿真 GPS）
- **参数临时改+恢复闭环验证 ✅**：ARMING_SKIPCHK -1↔0、FS_THR_ENABLE 0↔5，
  恢复后读回 0/5；解锁指令未成功过、电机未转，飞控与试验前状态一致
- 桌面解锁的唯一口子：切 STABILIZE 等非位置模式（强制检查按模式豁免）→ 仅能
  验证解锁机构，任务链不跑（状态机只认 GUIDED）；是否做待定
- **真解锁/全流程硬依赖位置源**：GPS（NEO-3）到货或将来 VIO 接入
- 这轮学费（全部实证，脚本已固化规避）：
  ① mavros 参数列表同步（~17s，mavros.log 出现 "parameters list received"）完成前，
  rcl 参数镜像读回陈旧默认值、set 静默失败——必须先等同步再做参数操作
  ② 此版 mavros 服务改名：`/mavros/param/set` 是 **`mavros_msgs/srv/ParamSetV2`**
  （`force_set` + `value.type=2/integer_value`）；读参数没有 `/mavros/param/get`，
  用 `/mavros/param/get_parameters`（rcl GetParameters，请求字段名是 `names`）
  ③ ros2-daemon 陈旧缓存会让 topic echo/service call 的 DDS 发现阶段挂死
  （报 "rcl node's context is invalid"）——先 `ros2 daemon stop` 重置，起完节点后
  `ros2 daemon start` 预热 + 一次 `ros2 service list` 热身
  ④ `kill` 杀 `ros2 run` 包装进程不杀节点子进程 → 孤儿 mission 节点残留；
  清理用 `pkill -f "cuadc_mission_[n]ode"`（`[n]ode` 正则防 pkill 自匹配杀掉自己，
  与 §八 pgrep 坑同源）

# 追加会话：接收机接线调研（§六排障线，PPM IN 针序定案 + 掉电根因基本锁定）

> 依据：官方引脚总图 doc.cuav.net v2/pinouts.png 放大核对 + FS-iA6B 官方手册。

- **V6X PPM IN 座 3 针 = GND / PPM IN / 5V+**（GH1.25；DSM/SBUS 是另一 5 针座，
  含 SPEKTRUM_3V3 3.3V 针，勿给 iA6B 供电）
- FS-iA6B 侧：PPM 走 **CH1 针**（丝印 PPM/CH1，舵机序 S/+/−，信号/VCC/GND），
  供电 4.0~8.4V，取 PPM IN 座 5V+/GND 即可（§六待查②答案：三线全接）
- **掉电根因基本锁定：针序镜像，直通杜邦线=电源反接**。接收机中间针是 VCC、
  两端是 S 和 GND；飞控中间针是信号、两端是 GND 和 5V+——直排对接则 RX 的 GND
  撞上飞控 5V+、RX VCC 撞上信号针，恰解释"信号线一碰接收机掉电"（§六疑似的
  "错位怼到 5V/GND"实为**不错位的直通线才是错的**）
- 正确映射（对角线式）：RX S→PPM IN、RX +→5V+、RX −→GND；接线前仍按 §六待查①
  上电实测：万用表找出唯一 ~5V 针（5V+）、通地针（GND），剩下即信号
- 若接线修正后 RC_CHANNELS 仍全 0，再查遥控器菜单 RX SETUP 的 PPM 输出项
  （多数批次 CH1 默认出 PPM，固件版本有差异）
