## 一、硬件验收（§1.2 基线的上机核对）

  `/dev/video1` 是同相机的元数据节点（不用）；格式表与 11_设备参数 §8 逐项一致
  （MJPG 最高 2592×1944@30，YUYV 仅 640×480@30）；
- 控制项齐全：亮度/增益/白平衡/50Hz 抗闪可设；**自动曝光/自动白平衡可关**成立；
- ⚠️ **手动曝光不受控（飞行红线，未解）**：`exposure_time_absolute` 写入被接受但
  固件无视（20→2047 亮度均值纹丝不动），无厂商扩展单元可绕。§1.2 "锁快门
  ≤1/500s" 当前无法执行——飞行前必须解决（换固件工具路径 / 换相机，或实证户外
  日光下 AE 短曝光足够稳后豁免）。已回写 01 视觉模块 §1.2 警示框。

## 二、三个大坑（全部实测定位，已回写 06 坑清单 §5）

1. **raw Image 6MB/帧 = 全链 1Hz（本日最大坑）**：1080p BGR 裸图在 rclpy+FastDDS
   下单帧序列化/发送 ~1s；RELIABLE 还会被慢订阅端流控堵死。定点实验：同环路发
   1 字节假数据 = 30fps → 锁定发布管线。**解法定案：发 CompressedImage，且直接
   透传相机原生 MJPG（CONVERT_RGB=0）——零编码零二次压缩，~65KB/帧全链 30fps**
   （JPEG 重编码版只有 17Hz，弃）。→ 01 视觉模块新 §4.5 图像传输定案；
2. **QoS 失配 = 一帧都收不到**：发布 best_effort 后，订阅端 RELIABLE（原默认
   `image_qos_reliable: true`）与之不兼容。生产 yaml 已补
   `image_compressed: true` + `image_qos_reliable: false` 两行（src+install 双份）；
3. **v4l2 控制必须开流前写**：流激活中写 set-ctrl 掉 ~1fps 怪模式；且控制值跨
   会话持久、设备重开会回默认。camera_node 固化"先写控制再 VideoCapture +
   每次 open() 后重设"顺序。另：暗屋 AE 拉秒级长曝光同样掉到 1fps——bench 口径
   = 手动模式 + `brightness=48` + 开灯拍摄。

# 会话三（追加）：M2 视觉在环（CV 真感知）——链路全通、锁定实证一次，终验收挂起

> 承接 09-12 收稿清单第 1 项。当日战果：**渲染世界 + gz-transport Python 直连 +
> CV 白桶真感知节点全链打通，真图像检测曾完成一次 3 筒锁定**（M2B）；随后四轮
> 验收被环境因素连环打断（渲染光照漂移 / 残留飞行控制冲突 / 热点切换断连），
> CV 通道本身的最终调参挂起。深夜 Jetson 离线，本会话收稿。

## 一、方案与资产（全部已入库/部署）

- **桥接定案**：Jetson 无 ros_gz 包（apt 无 humble-ros-gzharmonic）→ 改用
  **gz-transport13 Python 绑定直订 `/d435i/image`**，零安装绕开桥接坑。三个
  使用要点：必须 `PROTOCOL_BUFFERS_PYTHON_IMPLEMENTATION=python`；subscribe
  签名 `(msg_type, topic, callback)`；rgbd 相机像素格式 int==3 才是 RGB8。
- **渲染世界**：飞行世界加入 Sensors 系统（ogre2），相机 30→10Hz、848×480→
  640×360（实测 RTF 0.49 与渲染无关，是 Jetson 基线——历史 5 轮 M3 本就在此
  RTF 下跑，无需放宽任务超时）。
- **CV 节点** `bucket_cv_perception_node.py`（已注册 colcon）：LAB 白桶分割 +
  fitEllipse + 单目解算 → 契约 PoseArray（stamp=最新 odom 戳−延迟、直径补偿、
  哨兵、空帧照发），与真值替身同契约，mission 零改动切换。
- **验收脚本** `fc_sitl_m2.sh`：[0] 强清残留（僵尸任务节点会共享 mavros 发
  disarm 把新任务在空中打下来——STATUSTEXT 铁证）+ 与 fc_sitl_m3 同构七步。
- **排障工具**：`stamp_probe.py`（双话题对戳）、`img_dump.py`（gz 相机抓帧）、
  `perception_probe.py`（感知话题全量录制）、`mavlink_sniffer.py`（5763 抓
  CMD/STATUSTEXT 定责 disarm 来源）。

## 二、实证战绩

1. **契约链路通 + 真图像锁定一次**（M2B 诊断轮）：任务侧仅 1 帧启动期拒收，
   "目标集冻结(normal, 3 筒)"由真图像检测达成——gz 相机→CV→契约→BucketMap→
   锁定全链为真。
2. **标定悬停**（mavros 服务手飞）：轴向全对（x +0.56 vs 期望 +0.57 / y −0.71
   vs −0.61），直径偏小 ~15% → `diam_compensation=1.15` 补偿。先验校验白捡
   一功：起飞坪白盘（13 万像素）与白色场地标线（圆度 0.14 / 反算直径 1.0m）
   全被直径/圆度门正确拒掉。
3. **SEARCH 沉降期**（search_settle_s=8）：起飞后 EKF 飞行中罗盘对齐期间喂图
   会凑出假航迹锁错目标（M2B 首目标 (25.5,-4.7) ≠ 桶位的根因）；真值替身误差
   自相消免疫此问题，真视觉一上来就暴露——已修入 mission_node + yaml。

## 三、卡点与环境教训（终验收挂起的原因）

1. **渲染光照漂移**：Jetson 重启后 ogre2 回退软渲染（libEGL nvidia-drm 告警），
   场景亮度被压平（全帧 L 挤进 [97,159]），白桶对场地对比度 ≤2 个灰度——固定
   阈值差 1 全灭，改相对阈值（帧中位数+偏移）也受制于"中位数≈最大值"的极端
   情况。世界文件 `scene.ambient` 1.0→0.4 后对比度恢复正常（白桶 L230 vs 场地
   145），但随后抓帧分析显示检测门限仍对光照/角度敏感——经典 CV 对渲染条件
   的鲁棒性有限。
2. **并发控制冲突**：本机同夜在跑真相机线（camera_node 三实例 + hazard_recon，
   见会话二），仿真飞机多次被残留指令留在 GUIDED 悬停（FCU 保持最后目标点
   特性），导致 M2K 启动即"飞机已武装"安全失败；已发紧急 disarm 收场。
   **教训：仿真飞行实验与真机线共用 Jetson 时必须先 `pgrep -af _node` 清场，
   确认 FCU disarmed 再开跑。**
3. 网络：热点切换导致 IP 变更（10.66.24.217 → **10.234.165.217**，SSH config
   已更新）+ 断连多次杀后台链路（setsid/nohup 双保险已成熟应对）。
