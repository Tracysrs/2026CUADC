# 06 · 坑清单与排障手册

## 怎样使用本文

- **遇到报错/怪现象**：§0 家规先过一遍 → 按主题搜关键词 → 命中后跳对应模块文档看定案 → 仍不行翻 `09_工作日志/` 原始记录；
- **排障通用心法**（来自 12 天实录）：先分层隔离（设备单机 → 接线 → 参数 → 链路），每次只改一个变量，用判别式探针（如数传单向通用"注入测试"判别）而不是靠猜；
- **材料边界**：每条坑都标注了实锤日期/场景，均为实测结论非推测；同类坑在不同设备上复现的（pkill 自匹配等）标注了"多次实证"。

> 全部来自实战日志（09-01 ~ 09-12）与 HIT 冠军队的翻车记录，按主题分类。
> **排障流程**：先在这里搜关键词 → 对应模块文档（[01 视觉](01_视觉模块.md) / [02 结构](02_结构与硬件模块.md) / [03 操作](03_操作模块.md) / [04 算法](04_算法模块.md) / [05 系统](05_机载系统与仿真模块.md)）看定案 → 还不行翻 `09_工作日志/` 原始记录。
> 各模块文档内的 ⚠️ 是就近预警；本文是全量查询处。

## 0. 家规（最高优先级）

1. **任何新线缆，上电前必过万用表，两头逐针**——连续三案（PPM 针序镜像、数传单向通、RTK 5V 反接）全是线缆；
2. 所有串口 **TX/RX 交叉** + **GND 共地**；线缆无流控线时必须关流控（`BRD_SER2_RTSCTS=0`）；
3. 连飞控前**先关 Mission Planner**；COM 号重启会漂移——扫口，不是变砖；
4. 改 `.gitignore` 后必须 `git status --short` 核对再提交；
5. 每一版代码先过 SITL 再上真机；真机首测拆桨 + 安全员 + 人工接管手段。

## 1. 串口与连接

| 坑 | 现象 | 解法/规避 |
|---|---|---|
| Mission Planner 占口 | 脚本连不上 COM5 | 跑 pymavlink 脚本前先杀 MissionPlanner.exe（MP 开着但没占口时可直接连，逐次确认） |
| COM 号漂移 | 重启后 COM5 消失 | `Get-PnpDevice -Class Ports` 先扫口；**不是变砖** |
| 软重启卡 bootloader | MAVLink 软重启后 COM 口变"无名 USB 设备" | 拔插 USB 即恢复，参数不丢 |
| USB RNDIS 丢包 | Jetson SSH 频繁超时、ICMP 60%+ | 全部改走局域网 WiFi；USB 网卡仅应急 |
| ModemManager 抢串口 | udev 事件后串口 EBUSY 约 20s | `sudo systemctl disable --now ModemManager` |
| udev ATTRS 匹配不生效 | 规则值核对无误但别名建不起来 | 改 **ENV 属性匹配**（`ID_SERIAL_SHORT` + `ID_USB_INTERFACE_NUM`） |
| 接电池瞬间串口抖断 | SerialException | 脚本对断连容错重连 |
| TELEM2 UART 全 0 字节 | 五波特率全静默 | 判定物理接线问题（待查）；临时用 USB ttyACM0；无流控线必须 `BRD_SER2_RTSCTS=0` |

## 2. ArduPilot 4.7-beta 参数

| 坑 | 现象 | 解法 |
|---|---|---|
| 懒加载参数组 | RNGFND1_*/PLND_TYPE 导入后"消失"或不存在 | **参数导入两遍，中间重启**；反向：禁用后子参数从表里消失（1086→1071 是这个原因，不是丢参数） |
| 参数改名 | 写 WPNAV_SPEED 等旧名无效果 | 新命名 WP_SPD / LAND_SPD_MS / FS_GCS_ENABLE / BATT_LOW_VOLT…；写不存在的名**静默忽略**（回读超时而非报错） |
| ATC_ANGLE_MAX 单位 | 写 3500 触发 PreArm "must be >= 10 and <= 80" | 这版单位是**度**，写 35 |
| FRAME_CLASS 默认 0 | 电机映射乱 | 新固件默认 0=未定义，必须显式 FRAME_CLASS=1 / FRAME_TYPE=1 |
| BATT 命名陷阱 | BATT_LOW/BATT_CRT 不存在 | 实名 BATT_LOW_VOLT / BATT_CRT_VOLT |
| 孤儿参数埋雷 | 飞控上残留基线外的值（MOT_SPIN_MIN=0.03 拒解锁） | 每次连机做回读核验（03 操作模块 §2.2）；基线 diff 逐项对账 |
| 解锁被强制层拒 | `Arm: Need Position Estimate` | GUIDED 需要位置估计属 mandatory 检查，ARMING_SKIPCHK=-1 也跳不过；桌面验证解锁用 STABILIZE |
| RC_SPEED 超规格 | 电调不响应/异常 | 默认 490Hz 超好盈 50~450Hz，改 200 |
| 裸 MAVLink 校准指令被吞 | COMMAND_ACK ACCEPTED 但静默不执行 | **校准一律走 Mission Planner GUI** |
| 写参数后立刻重启 → 参数丢失 | "External=0 被固件强制回写"式灵异现象 | 真凶是存储竞态：**写参数后等 5 秒再重启**（脚本固化 sleep(5)+复读） |
| 校准后自动重启卡死 + 假 PreArm | USB 枚举在但固件不应答；Baro/Battery 假告警 | **断电复位一招清**（ESC 校准后实测），不是坏件 |
| COMMAND_ACK 早于 STATUSTEXT | 只抓 ack 漏掉拒绝原文，误判解锁成功 | 抓拒绝原文要**听满整个窗口**再退出 |

## 3. MAVLink / pymavlink

| 坑 | 解法 |
|---|---|
| `MAV_CMD_DO_MOTOR_TEST` 的 param1 是测试序列号不是输出口 | Quad X 序列 = 前右→后右→后左→前左；脚本已固化 `OUT2SEQ={1:1,2:3,3:4,4:2}`，按输出口测试 |
| 未解锁时 PWM 输出口静默 | 先发 `MAV_CMD_DO_SET_SAFETY_SWITCH_STATE`(5300) param1=1 解**会话**安全锁（BRD_SAFETY_DEFLT 只管开机默认）；固件内部临时 arm 并抑制失效保护 |
| 只插 USB 不接电池测电机无效 | 电调无主电：FC 接受指令但电机不转，还触发电池失效保护——**电机测试必须接电池** |
| 新版 pymavlink `param_set_send` 签名收紧 | 用原始 `mav.param_set_send` + `param_request_read_send` 回读对账，**写完必读** |
| pymavlink --user 安装无 `pymavlink.tools` 子模块 | CLI 用 `python3 -m pymavlink.mavftp`；其 `cmd_get` 是异步的，自写脚本用同步 `cmd_list` |
| dataflash 回拉 | `python3 -m pymavlink.mavftp --device /dev/cuadc-fc --burst_read_size 239 get /APM/Logs/x.BIN 本地`（实测 ~815KB/s） |

## 4. MAVROS / ROS 2

| 坑 | 解法 |
|---|---|
| ArduPilot 不流送遥测（mavros 连上但没数据） | ArduPilot 见 **GCS 心跳**才开始流送 → mavros 开 `gcs_url:=tcp-l://0.0.0.0:14550` + `gcs_pump.py` 心跳泵（先发后收） |
| 4.7 无 SR0_* 参数，写了静默忽略 | MAVROS `set_message_interval` 服务逐条订阅 7 条消息 @10Hz（脚本已固化） |
| DDS 多网卡发现跑错口（WiFi+RNDIS） | `export ROS_LOCALHOST_ONLY=1` |
| mavros 参数同步前操作无效 | 参数列表同步约 17s（log 出现 `parameters list received`），完成前 set 静默失败、读回陈旧值 |
| `/mavros/param/get` 不存在 | 此版读参数用 `/mavros/param/get_parameters`（字段名 `names`）；set 是 `ParamSetV2` |
| ros2-daemon 陈旧缓存 | topic echo / service call DDS 挂死（"context is invalid"）→ `ros2 daemon stop` 重置 + 热身 |
| `ros2 topic echo --once` 当连接探针 | DDS 发现慢，30s 全 miss 但链路其实秒连——以任务节点过 WAIT_FCU 为准（三次实证） |
| rclpy 回调里 `rclpy.shutdown()` 死锁 | 改 Future + `spin_until_future_complete` 或自定义异常退出；工具类输出重定向必须 `sys.stdout.flush()` |
| `pkill -f`/`pgrep -f` 自匹配自杀/误报 | `[x]` 括号技巧（`pkill -f "cuadc_mission_[n]ode"`）或 kill/start 拆两条、写成脚本文件（多次实证）。**09-12 第三变体**：ssh 远程命令行里"脚本内是括号写法 + 同一命令行其他位置含明文关键字"（如 nohup ros2 run 段）照样匹配到外层 shell 自杀——含 kill 的操作必须单独一条 ssh，且整条命令行不得出现明文关键字 |
| `&&` 长链被 `&` 整体后台化 | ssh 远程命令 `source … && source … && nohup X & Y` 的 `&` 会把整条 `&&` 链（含 source）丢进后台，Y 在未 source 的前台裸跑（09-12 实测 rclpy 找不到）——多步远程操作写成脚本文件 scp 过去执行，别内联 |
| `timeout` 只杀直接子进程 | `ros2 run` 的孙进程变孤儿占住管道 → 文件重定向 + `pkill -9` 兜底 |
| 脚本 `set -u` 与 ROS setup.bash 冲突 | 禁用 `-u`（`AMENT_TRACE_SETUP_FILES` 未绑定报错） |
| `use_sim_time` 下 rclcpp::Time 相减抛异常 | 所有 stamp 入队前统一换节点时钟类型（已写死 mission_node.cpp） |
| 无 GPS 时真机无 odom 流 | 真机 mavros local_position/odom 不出流（SITL 有仿真 GPS）——状态机停 WAIT_NAV_STABLE 属预期 |
| ssh 会话挂住 / 后台进程占 stdin | setsid + `</dev/null` 断开继承的 fd；放后台任务主动收尾 |

## 6. 电气与机械

| 坑 | 根因/解法 |
|---|---|
| 飞控电压读 0.00V（电池已接、电调在叫） | PMU 6pin 小线没插飞控。**主电到位听电调鸣叫，PMU 链路看飞控读数**，两维度独立排查 |
| 舵机完全不动 | 双重根因：①仅 USB 供电时 BEC 无输入；②手册实锤"飞控不为舵机供电"，A1~A8 +/− 悬空，好盈 OPTO 又无 BEC → 全系统无 5V 源。**必须 UBEC 注入 A1 母线并共地** |
| 接收机"信号线一碰就掉电" | **PPM IN 针序镜像**：飞控中间针是信号、接收机中间针是 VCC——直通杜邦线 = 电源反接。对角线式接：RX S→PPM IN、RX +→5V+、RX −→GND |
| 电机四台全反 | 出厂电调方向 = Betaflight 默认，不是接线错位；相线对调任意两根修正 |
| 电调红线 | 好盈 OPTO 无 BEC，红线悬空包好，别插飞控 |
| iA6B 出厂 failsafe="保持" | FS-i6 端改 **No pulses**，否则关遥控飞控察觉不到断链 |
| 解锁门槛设太高 | BATT_ARM_VOLT 24.5 时只有近满电能解锁；取 22.5（区间推理 22.5~23.8） |
| 搜索高度 | 4.2m 检不出桶，**2.0m 起步** |
| 云台供电 | 输入上限 16.8V，6S 满电 25.2V 直连必烧 → 独立 12V 小降压；先装相机再上电，通电静置 20s 勿晃 |
| 电机测试无效（只插 USB） | 电调无主电 → 必须接电池（见 §3） |

## 7. 数据与训练

| 坑 | 解法 |
|---|---|
| 连续帧随机切分 → 验证泄题 | 按**视频片段**整段切分（build_real_data.py 固化） |
| data.yaml 写了 path 键 | 换机器路径全错 → 不写 path，以 yaml 所在目录为根 |
| 色相增强默认 0.015 | 色相即类别特征（红=易燃）→ `hsv_h=0.005`，否则制造标签噪声 |
| 类别表凭记忆/抄 GHS | 附件11 是扫描件，必须**逐页转图比对**定表（09-12 勘正：曾误植 GHS 集合，id 2~5 错位）→ 训练集 data.yaml / 判读 class_id / 填单口径三处同源对表 |
| 微调用从头训学习率 | 微调必须 `lr0` 降 10 倍（0.001） |
| 公开危化数据集类别体系不一致 | 只当背景负样本，不直接训练；类别以**附件 11 十类**为唯一基准 |
| 自动曝光 | 场地灯光变化瞬间"失明" → 手动锁曝光（快门 ≤1/500s，参考 120/64/50Hz） |
| 分类 ROI 在 640 缩图上裁 | 灰区 ROI 从**全分辨率原图**裁剪放大重推 |

## 9. SITL / Gazebo（合并 09-10~09-12 仿真线全部实测）

| 坑 | 现象/原因 | 解法 |
|---|---|---|
| **SITL 读 stdin，ssh 断开即"幽灵死亡"** | 无 segfault/无 oom/journal 无痕，飞几分钟就死 | `sleep infinity \|` 管道保 stdin（reset_sim 已内置 setsid + stdin keeper） |
| **启动不稳定窗** | reset 后 sketch 静默 in-process 重启（"ArduPilot controller has reset" = 帧计数倒退），分钟级~10 分钟自愈；mavros.log 见 `Accels inconsistent`/`TM: Time jump` | `fcu_ready.py` 心跳稳定窗门禁（默认 30s 窗/600s 超时）；**勿反复 reset** |
| **SERIAL0(5760) 单客户端 + 泄漏抢槽** | 泄漏的 mavros 自动重连抢槽 → 下次任务全程 `mode:''` | reset_sim 清泄漏进程 + 任务脚本起跑前自检；探活/旁听走 5762 |
| ardu.log "Waiting for connection" 假信号 | 那是 SERIAL0 等 TCP 客户端，与 Gazebo 握手无关 | 判联机一律 `fcu_ready.py --window 10` |
| ardu.log 块缓冲 | stdout 重定向后 tail 看到几分钟前的历史 | 启动行加 `stdbuf -oL`（已修） |
| 新版 SITL 不指定 model | 启动失败 | 显式 `--model quad`（gazebo-iris 走 JSON 接口 9002/9003） |
| SITL 源码 CRLF / 浅克隆 | waf shebang 失效 / git describe 失败 | sed 剥 CR；本地打 tag |
| eeprom FRAME_CLASS=0 | 重建二进制后旧参数区失效，"Check frame class and type" | fly.py 启动自检修复（1/1）；改 frame 后重启飞控；`-w` 会抹参数已从启动脚本移除 |
| 5760 端口竞争 | MAVROS 与 fly.py 并行互踢 | 5760 独占；旁听走 5762/5763 |
| takeoff 返回 UNSUPPORTED(4) | ① 不在 GUIDED ② EKF 高度已疯（坠机污染） | 先设模式、按 command id 过滤 ACK；修好地面后 SITL 也要重启 |
| **起飞后一直爬升（30s 爬 55.8m）** | NAV_TAKEOFF param7 按 **ABOVE-HOME** 解释，误传 AMSL+8 | CommandTOL param7 直接给相对家点高度（fly.py 已修） |
| 落地判定提前放弃 | `recv_match` 一次迭代只吃一条消息，循环次数秒耗尽 | 改时间窗轮询 + `max_rel<20 且 landed` 判据 |
| 裸 SITL 只发心跳 | MAVROS 外的客户端零数据流 | REQUEST_DATA_STREAM ALL @10Hz（fly.py 已内置）/ set_message_interval |
| 场地模型无碰撞体 → 穿地自由落体 | 高度掉 -275km，起飞被拒的真正根源 | 飞行 world 内联 400×200m 碰撞地面（cuadc_rescue_flight.sdf，已去渲染系统） |
| 出生插地物理弹飞 | 换机架没重标出生高度 | 按"脚底贴地"重标（ZD550：0.195→0.29 共 5 处） |
| 动力"转不到目标转速" | cmd_max 饱和：稳态力矩超上限静默截断（推力差 -8%） | 先算满转速阻力矩再定 cmd_max（ZD550 取 ±4.0） |

## 10. 数传 / RTK 专项

| 坑 | 根因/解法 |
|---|---|
| 数传"完全无数据"实为**单向通** | TX/RX 没交叉：地面注入 PARAM_REQUEST_READ 飞控应答正常 = 半根线通 → 对调信号线秒通（09-11 实锤） |
| MP 的 **SiK 电台页全空、无法配置** | 两个坑叠加（09-12 实锤）：① 选错口——配置页选成 COM5（那是飞控 USB，AT 指令发给飞控当然不应答），必须选 COM10 地面电台；② **MP 1.3.83 电台页与 X-Rock 固件不兼容**——即使 COM10+57600+链路静默全对，加载设置也必崩"端口被关闭"（RFD900.TSession 流程缺陷）。→ **定案别用 MP 电台页**：机载端断电静默后跑 `check_radio.py` 核身（ATI 应答 X-Rock 4.0），改参数用 3DR Radio Config 工具 |
| 电台 AT 探测后**对一切指令全哑** | X-Rock 4.0 固件被不支持的 AT 指令挂死（ATI5 实锤，发完即挂）→ **重插地面 USB 棒**恢复；探测只用白名单：`+++\r`、`ATI`~`ATI4`、`ATO`（check_radio.py 已内置） |
| 数传烧功放 | 无天线发射 → **天线先拧紧再上电** |
| RSSI 低/间歇断 | 碳架屏蔽/电源线干扰 → 天线露出机架边缘；邻场同频改 Net ID |
| RTK rover 灯不亮 | 6P 针序与 Pixhawk GPS 标准完全相反，直通 = 5V 反接 → 原配线或自制转换（映射见 02 结构模块 §7.2），万用表逐针 |
| RTK rover Type C 无 NMEA | Type C 仅供电/APP 通道，NMEA 走 6P UART |
| GPS2_BAUD 读不到 | 这版固件无此参数，GPS 口波特率跟底层串口 SERIAL4（改 SERIAL4_BAUD） |
| RTK "Fixed 但整体偏移" | 比 Float 更危险 → 基站全程禁动；对基准点复测 |
| LoRa 长浮不 Fix | 多径/遮挡 → 基站架高 1.5~2m、远离反射面 |

## 11. HIT 冠军队教训 checklist（SSOT §10.2，评审用）

1. 坐标系三件套：任务原点记录、ENU/罗盘航向转换（`yaw_ENU=90°−compass`）、锁航向——最大坑，他们翻车两个月；
2. 同帧去重/独立性判据**必须真正生效**（他们参数写了没用，两瓶投一点）；
3. 丢视觉禁止按冻结坐标盲投；
4. 搜索高度 2.0m 起步 + 手动锁曝光；
5. 舵机 ACK ≠ 命中：载荷在位检测 + 推力轴线与瓶质心同轴 <5mm 评审；
