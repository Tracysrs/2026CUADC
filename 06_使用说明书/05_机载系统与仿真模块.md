## 3. MAVROS 链路详解（"连上了但没数据"的完整答案）

### 3.1 三个必要条件（缺一没数据）

1. **ArduPilot 见到 GCS 心跳才开始流送遥测**，mavros 不冒充 GCS → mavros 开 `gcs_url:=tcp-l://0.0.0.0:14550` 桥 + `gcs_pump.py` 心跳泵（**必须先发后收**）；
2. **4.7-beta 没有 SR0_* 流送参数**（写了被静默忽略）→ MAVROS `set_message_interval` 服务逐条订阅，7 条消息与 MAVLink message_id：

| message_id | 消息 | 内容 |
|---|---|---|
| 1 | SYS_STATUS | 传感器健康/电池 |
| 30 | ATTITUDE | 姿态 |
| 32 | LOCAL_POSITION_NED | 本地位移/速度（odom 源） |
| 33 | GLOBAL_POSITION_INT | 全球位置/相对高度 |
| 74 | VFR_HUD | HUD 汇总 |
| 147 | BATTERY_STATUS | 电池详情 |
| 245 | EXTENDED_SYS_STATE | 起降状态 |

执行后 odom 出流 4.7Hz，状态机立刻过导航门禁；
3. 多网卡（WiFi+RNDIS）组播跑错口 → `export ROS_LOCALHOST_ONLY=1`。

### 3.2 一键验证

```bash
bash 02_飞控与硬件/调试工具/fc_dryrun.sh [秒数]      # 链路验证 + 状态机干跑（无桨不解锁），日志 /tmp/cuadc_fc_dryrun_*/
```

手动形态：

```bash
ros2 launch mavros apm.launch fcu_url:=/dev/cuadc-fc:115200 gcs_url:=tcp-l://0.0.0.0:14550
python3 scripts/gcs_pump.py                    # 另开终端：心跳泵
```

实测记录（09-09）：MAVROS 起动 2s 收心跳；心跳泵触发流送后遥测全通（CAN PMU 电压/电流正常）；SetMode GUIDED 回读生效。

### 3.3 MAVROS 2.14 版本特性（脚本已固化）

- 参数列表同步约 17s（mavros.log 出现 `parameters list received`），完成前 **set 静默失败、读回陈旧值**——先等同步再做参数操作；
- `/mavros/param/set` 是 `mavros_msgs/srv/ParamSetV2`（`force_set` + `value.type=2/integer_value`）；读参数用 `/mavros/param/get_parameters`（请求字段名 `names`），**没有** `/mavros/param/get`；
- DDS 挂死先 `ros2 daemon stop` 重置，起完节点 `ros2 daemon start` 预热 + 一次 `ros2 service list` 热身；
- **判断连接别用 `ros2 topic echo --once`**（起动高压期 DDS 发现慢，30s 全 miss 假阴性）——以任务节点通过 WAIT_FCU 为准，或 pymavlink 直探。

### 4.2 设计约定（为什么这样分层）

- **逻辑规范与 ROS 解耦**：`drop_logic.py` 不 import ROS、不做坐标变换（输入输出全是世界系）——可离线单测/回放/蒙特卡洛；C++ 消费端逐函数镜像，移植后跑同一套仿真口径回归；
- **契约先行**：感知↔状态机↔侦察的消息在写代码前定死（接口契约.md），双哨兵 + fail-closed；
- **参数三方一致**：代码声明 = 代码加载 = YAML，三方核对；改节点名必须同步 YAML 顶层键。

### 4.3 与参考代码（HIT 公开版）的关键差异

| 点 | 公开版 | 本实现 | 依据 |
|---|---|---|---|
| 坐标系锁定 | 藏在导航就绪态里 | `LOCK_FRAME` 独立态，航向 2s 内变 ≤2° | 罗盘漂移为 HIT 失利根因 |

## 5. SITL / Gazebo 仿真体系

### 5.1 组件架构（定案）

```
Windows（SSH 远程）
   ▼
Jetson
 ├─ arducopter SITL（裸起，eeprom 每轮重置）──JSON 9002/9003──► gz server（无头）
 │        │                                        （物理+ArduPilotPlugin+飞行world）
 │        └─ tcp 5760 ◄── MAVROS ◄── cuadc_mission 状态机（auto_arm_on_guided）
 ├─ gz GUI（gz sim -g，独立进程挂到活 server）──► :0 显示器
 └─ fly.py（30 秒级起飞冒烟，直连 tcp 5760，不依赖 MAVProxy）
```

- **MAVProxy 层全部砍掉**：它只当转发器还挑链接状态，裸跑 SITL（`arducopter` 二进制 + `--defaults` 参数链）反而稳定；MAVROS fcu_url 用 `tcp://127.0.0.1:5760`（MAVROS2 不认 udpin://）；
- 裸 SITL 只发心跳 → 一切消费端必须自己要数据流（MAVROS 走 set_message_interval，pymavlink 走 REQUEST_DATA_STREAM）；
- 端口地图：9002/9003 = 飞控↔Gazebo JSON；5760 = SERIAL0 MAVLink（**单客户端**）；5762/5763 = SERIAL1/2 第二三出口（探活/旁听用）。

| B 接管保护 | TAKEOFF 中切 ALT_HOLD | 立即 PILOT_OVERRIDE 停发退让 |
| C 断定位 | SIGSTOP 冻结 SITL | `MISSION_FAILURE: Odometry stale` 安全落地 |

三个连环坑（已固化进脚本）：DDS 多网卡 → `ROS_LOCALHOST_ONLY=1`；GCS 心跳泵（§3.1）；CLI 偶发 DDS 挂死 → `timeout 15` + 3 次重试；脚本禁 `set -u`；pkill 模式写 `arducopte[r]` 防自匹配。`run_sitl.sh` 默认 `use_sim_time:=false`（HIT 包默认 bridge 无 /clock）。

### 5.5 仿真脚本逐段讲解（`04_仿真/仿真环境/jetson/` = Jetson `~/sim_scripts/`）

**reset_sim.sh——全栈重置**（关键三段）：

```bash
# [杀] 泄漏的 mavros/任务节点/fly.py 也必须清：泄漏的 mavros 会自动重连并抢走
# SERIAL0(5760) 单客户端槽，下一次任务的 mavros 就会永远 mode:''
pkill -9 -f "mavros"; pkill -9 -f "cuadc_mission"; pkill -9 -f "fly.py"

# [起 SITL] 三个关键参数：
#   rm -f eeprom.bin           → 每轮参数确定性（否则上一轮的残参数污染）
#   sleep infinity | stdbuf -oL arducopter →
#     stdin keeper：SITL 控制台读 stdin，ssh 断开 EOF 会静默退出（"幽灵死亡"真凶）
#     stdbuf 行缓冲：默认块缓冲让 ardu.log 滞后几分钟，tail 全是假象
setsid bash -c "sleep infinity | stdbuf -oL '$BIN' --model JSON --speedup 1 ... \
  --defaults 'copter.parm,gazebo-iris.parm,sr0.parm' > /tmp/ardu.log 2>&1" &

# [起 GZ] </dev/null 断开 stdin 继承，否则 ssh 跑完不退（09-11 挂账已收）
nohup gz sim -s -r -v2 cuadc_rescue_flight.sdf > /tmp/gz_sim.log 2>&1 < /dev/null &

# [自检] 成功判据一行：
echo "ardu=$(pgrep -c arducopter) gz=... p9002=... l5760=... c5760=$(ss -tnp | grep -c ':5760')"
#   c5760 非 0 = 5760 已被泄漏占用（抢槽前兆）
```

**fc_task.sh——任务模式统一入口（09-13）**：`fc_task.sh [mission|m3|m2] [秒]`，缺省 m3；exec 转发到三个底层脚本。模式开关本质 = 任务节点的 `m1_no_vision_mode`（m1=true / m3m2=false）与 `sim_release_bridge`（m3m2=true 判分桥）。

**fcu_ready.py——FCU 就绪门禁 v2（09-13 升级）**：三层判据——①**双端口探活**（5762 优先，5760 空闲即用：手动跑门禁时 mavros 未起、5760 空闲直连最快；任务脚本内 5760 被 mavros 占用自动跳过。5762 监听在多次连接后会消失，双端口免疫）；②心跳稳定窗（任意消息连续 --window 秒不断档，--gap 断档重新计窗）；③**GPS fix≥3D 校验**——长时间空转后耦合会僵死（心跳/姿态照常流但 GPS 卡 0，旧版只探心跳会误放行、任务卡死 WAIT_NAV_STABLE）。**自动自愈**（默认开）：GPS 卡 0 超 --gps-timeout(60s) 且 SITL 在跑 → 自动重启 gz 服务端重握手（SITL 不动、不进长等待）最多 4 次，一般 1~5min 就绪；`--no-heal` 可关。退出码 0/1 可接脚本门禁。

**fc_sitl_mission.sh——全任务七步**：见 03 操作模块 §5.2。

**fc_sitl_m3.sh——M3 仿真投放判分闭环（09-12 新增）**：在 fc_sitl_mission 七步之上，[4] 步多起两个节点——`cuadc_rescue_sim virtual_drop_judge_node`（虚拟判定，桶真值参数化默认 = generated_scene.yaml，target_bucket_id 留空按最近桶判 A/B 区）+ `cuadc_perception scene_truth_perception_node`（场景真值感知替身：读 generated_scene.yaml + odom 反变换 + 下视相机可见性门控 → 契约 PoseArray）；任务节点以 `m1_no_vision_mode:=false -p sim_release_bridge:=true` 起跑 → SEARCH 真锁定 → ALIGN/RELEASE×2（舵机干跑）→ fire 同步调 `/drop_controller/release` 判分。收尾汇总 `judge.log` 的"累计="得分行。验收目标：**投放判定 2/2（争取 A 区）+ 总时长 ≤180s**。真机/正常无视觉演练仍用 fc_sitl_mission.sh。

**fly.py——起飞冒烟**（三修后的完整口径）：

```python
# 修 1：直连 + 数据流请求——裸 SITL 只发心跳，没人要数据就零流
m.mav.request_data_stream_send(..., MAV_DATA_STREAM_ALL, 10, 1)

# 修 2：起飞高度按 ABOVE-HOME 传——
#   Copter 把 NAV_TAKEOFF param7 解释为"相对家点高度"。旧代码传 AMSL+8，
#   SITL 家点海拔 584m → 目标 ~592m，30s 观察窗 + 宽松判据把 51.6m 爬升
#   掩盖成"验证通过"（09-10 的 55.8m 爬升 bug 同源）。修后直接传 8.0：
m.mav.command_long_send(..., MAV_CMD_NAV_TAKEOFF, 0, 0,0,0,0, 0,0, 8.0)

# 修 3：落地判定用时间窗——recv_match 一次迭代只吃一条消息，按循环次数限时长
#   在 10Hz 流下 ~5s 就耗尽，下降未完即误报。改 90s 时间窗轮询 + FLIGHT_OK 判据
#   加 max_rel<20 且 landed；只在确认落地后才发 disarm（空中绝不发）。
ok = max_rel > 5.0 and max_rel < 20.0 and landed
```

### 5.7 ZD550 机架适配（09-12 完成）

iris（1.5kg）→ ZD550（8kg）改两份 model.sdf：

| 参数 | 原 (Iris) | 新 | 依据 |
|---|---|---|---|
| 整机质量 | 1.75 kg | 8.00 kg（base 7.75） | 09-09 "~8 kg 级" |
| 惯量 base | 0.008/0.015/0.017 | 0.061/0.114/0.129 | 质量×轴距比例放大 |
| 惯量 桨 | 9.75e-6/1.667e-4 | 1.735e-5/2.97e-4 | 随桨径² ×1.78 |
| LiftDrag area/cp | 0.002 / ±0.084 | 0.00356 / ±0.112 | 桨径 1.334 倍缩放 |
| multiplier | ±838 | ±656（6264 rpm） | 满油门单桨 29.5 N，T/W=1.50 |
| cmd_max | ±2.5 | ±4.0 | 满转速阻力矩 2.65 N·m，原值会饱和 |

- 推导过程见 04 算法模块 §15；**cmd_max 饱和是隐形坑**：稳态力矩超上限时静默转不到目标转速（转速差 -4% → 推力差 -8%），必须先算阻力矩再定上限；
- 电机位按 CAD 实测 ±0.2196m（⚠️ 与标称 550 轴距推算的 ±0.195 不一致，待实机核对桨保干涉）；mesh 产出固化在 `scripts/make_zd550_meshes.py`（全细节外观 + 机体凸包 + 4 box 起落架碰撞，着地面 -0.2895）；
- **换机架必须按"脚底贴地"重标出生高度**（0.195→0.29 共 5 处），否则出生插地 9.5cm 物理剧烈弹开；
- D435i 相机位保住 (0,0,-0.08) 不动：机体中柱底面距相机仅 1.5mm，小于 near clip 50mm 被裁剪，画面不受污染；
- 验证：fly.py FLIGHT_OK；悬停 PWM 1764（cmd 0.830）vs 推力模型预测 0.816（差 1.7%）；四电机 PWM 全等 = 对称出力实证；悬停油门 83% 是 T/W≈1.5 重载规格的固有结果，不是参数错误；
- ⚠️ 姿态内环（ATC_*）仍是 SITL 通用值——1.5kg 与 8kg 不可互转，贴近实机需按实机整定。
