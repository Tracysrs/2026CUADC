# 04 · 外设链路（数传 / RTK / GPS / 激光定高）

> **本册索引**：§1 总则 → §2 数传（远航 3DR Radio X6） → §3 RTK（CUAV C-RTK 3 X20P，09-20 起主链；09-22 单RTK） → §4 GPS（NEO-3 已拔除转备份） → §5 激光定高（微空 MT-01P） → §6 自查题。
> **分工**：每设备三段——安装（指针级位置，接线卡在 [02_装机接线](02_装机接线.md) §9）→ 参数配置（权威表在 [03_飞控配置与校准](03_飞控配置与校准.md) §2.2）→ **本册：连接、验收分级、日常操作、排障速查**。错误案例全量在 [11_错误与经验总结](11_错误与经验总结.md)。

## 1. 总则

- 家规：**任何新线缆上电前万用表两头逐针**；所有串口 TX/RX 交叉 + GND 共地；
- 两段无线电互不重叠：FS-i6 **2.4G** / 数传 **915M**（09-23 起主用 915 对，433 对上行断转备件。RTK-01 的 900M LoRa 随 09-20 退役消失；X20P 改正走数传同链路，注入期须实测带宽）；
- 排障心法：链路活性 → 口的身份 → 配置协议，分层判别（"无法配置"≠"链路坏了"）。

## 2. 数传（远航 3DR Radio X6，**915MHz** SiK 协议/X-Rock 4.0 固件；09-23 起主用 915 对）

> 数传 = 飞控↔地面笔记本之间的无线"串口线"。三件事：实时监控 / **侦察回传填单主通道** / 地面指令备份。三个"不是"：不传图像（空口 ~57.6kbps 只够遥测；图传上场前必须报备裁判）、不是遥控（控飞机的是 PPM 链路）、不参与飞控计算（纯透传）。

### 2.1 安装与连接

1. 机载版（带 GH 插头/裸 TTL 的那只）接 **TELEM2**（接线卡见 02 册 §9.4；09-24 定案；**TELEM1 现接 MT-01P**——电台插 TELEM1 时代"下行通上行死"经 09-24 翻案=电台内部速率与口波特率不匹配，**口收路径健康**，勿再按"口故障"排障）；**天线先拧紧再上电**（无天线发射可能烧功放——唯一易真损坏操作）；
2. 天线朝下或朝侧**露出机架边缘**，别贴碳板、别与电源线捆扎；
3. 地面版（USB/CP2102 驱动）接笔记本，认出 COM 口（本机固定 COM10）；
4. MP 右上角：选 COM10 → 波特率 **57600** → 连接；**一对出厂同 Net ID，无需配对**；
5. 验收：HUD 出姿态、地图出位置、RSSI 百分比显示。

### 2.2 验收分级（逐步拉远）

| 级别 | 场景 | 通过标准 |
|---|---|---|
| ① 台架 | 飞控仅 USB 供电 | MP 能收数、参数页能读 |
| ② 整机 | 6S 供电全系统 | 同上，且舵机动作/电机解锁时数据不断流 |
| ③ 拉距离 | 场地目视范围 | 链路质量稳定，RSSI 衰减合理 |

（端到端验收：09-11 首通于 TELEM1+433；**09-23 双向贯通 + 空中 RTCM 注入压测 180 帧零丢于 TELEM2+915**；09-24 复测上行间歇（TELEM2 插头压实/换线定位中）。09-24 晚翻案：TELEM1 口收路径健康——MT-01P 同口收数畅通实证，电台单向死定性=电台内部速率与口波特率不匹配，详见 11 册 §4。）

### 2.3 电台参数与频点（平时零维护）

- **日常无需配置**：出厂配对完好，只有赛场撞频才动手（改 **Net ID**，两端同步）；
- ⚠️ **MP 1.3.83 的 SiK 电台页对本电台定案不可用**：即使口/波特率/静默全对，"加载设置"必崩——页面全空、异常弹窗都是这一个原因，与链路健康无关；
- **改参数正解（静默配置四步法）**：
  1. 给机载端**断电**（链路静默是前置——X-Rock 固件进配置要 `+++` 前后 ~1s 串口静默，心跳每 0.97s 一帧永远打断它）；
  2. MP 电台配置页**必须选 COM10 且不点"连接"**（COM5 是飞控 USB，选错=AT 指令发给飞控）；
  3. 跑 `check_radio.py` 核身：`ATI` 应答 **X-Rock 4.0** = 电台活着、AT 通道可进；
  4. 改参数用 **3DR Radio Config** 独立工具；**严禁发 ATI5**（固件挂死全哑，重插 USB 恢复）。

### 2.4 比赛角色：侦察回传填单链路

```
机上 Jetson 判读桥 recon_gcs_bridge（判读话题→STATUSTEXT）→ mavros
  → FC(USB /dev/cuadc-fc) → 路由跨口转发 → TELEM2(@9600，09-24 定案)
  → 机载数传 —915MHz→ 地面数传(USB COM10@57600) → Mission Planner 消息栏「侦察V…」行 → 组员填单
```

- 判读文本三类（单行 ≤50 字节，MAVLink v1 上限也安全；格式/去重见契约 §5）：
  `侦察V13 #0 腐蚀品 c0.93`（确认，照抄类别名）/ `侦察V13 #1 留空(不足)`（可人眼
  补判）/ `侦察V13 #2 留空(混淆!)转人眼`（**必须留空 + 转人眼 FPV**）；
  留空 0 分、错填 −100，宁空勿错；
- 依据：STATUSTEXT 无目标字段 = 广播，ArduPilot 路由层自动跨口转发（源码
  MAVLink_routing.cpp 已核实），且不受 SRx 流控——9600 空口无压力；每侦察航点
  一窗一发，全架次约 20~30 行；
- 桥的拉起：`ros2 launch cuadc_perception recon_gcs_bridge.launch.py`（前置 =
  mavros 已起、判读服务在跑；systemd 化待拍板，比赛日手工拉起或并入
  cuadc_start_perception.sh）。全链核对：MP 消息栏出现「侦察V…」行 = 通；
- 备份通道：局域网内 `ros2 run cuadc_perception recon_viewer_node` 彩色判读表
  （05 册 §6.2），与数传桥可并存；
- 填单员分工：一人看链路与飞机状态，一人按消息填单；**不要盯着地面站"开飞机"**——飞机是自主的；
- 断链预案：`FS_GCS_ENABLE=0` 机载自主兜底；数传异常**不要急着重启折腾链路**，先保任务。

### 2.5 排障速查

| 现象 | 最可能原因 | 处理 |
|---|---|---|
| 下拉里没有 COM 口 | 驱动没装 / 换了 USB 口 | 装 SiLabs VCP 驱动 |
| 连接超时 | 波特率不是 57600 / 口选错 | §2.1 核对 |
| 连上但 HUD 全空 | 机载版没插 TELEM2（TELEM1 现接 MT-01P，非数传口）/ 天线没装 | 查插口与天线 |
| **单向通**（地面能注入、心跳回不来） | **TX/RX 没交叉**；实案二=机载台插 TELEM1 时"下行通上行死"（09-24 翻案：非口故障，=电台内部速率与口波特率不匹配，数传定案 TELEM2 后此象即消）；实案三=TELEM2 插头接触不良（09-24 实测间歇 43 发 5 回） | 地面注入 PARAM_REQUEST_READ，飞控在 USB 口应答正常 = 半根线通；对调信号线秒通；核对插口在 TELEM2 后压实/换线复测（目标读参往返 5/5） |
| **SiK 电台页全空** | 口选错（COM5）+ MP 与 X-Rock 不兼容 | 别用 MP 电台页；走 §2.3 四步法 |
| **电台对一切 AT 全哑** | 被不支持指令挂死（ATI5） | 重插地面 USB 棒恢复；只用白名单指令 |
| RSSI 很低 | 天线被碳架遮挡 / 与电源线捆扎 | 重走线，天线露出机架外 |
| 一会儿断一会儿好 | 邻场同频干扰 | 改 Net ID 错开 |
| 拉远就断链 | 超链路余量 | 任务半径 300m 内标称 2km 有大余量，先查天线 |

## 3. RTK（CUAV C-RTK 3 X20P 基站+移动端，09-20 起主链）

> ⚠️ **换代定案（2026-09-20）**：瑞杰 RTK-01-B/R **退役封存**（rover 串口输出损坏存疑），比赛 RTK 链路由 C-RTK 3 X20P 一对承接。定位策略=**验收达标后转正**：过本节门槛前比赛定位维持纯 GPS+视觉，达标后 SSOT §3.2 改「RTK 主用 + 纯 GPS 自动降级兜底」；任务流程任何时候不依赖 Fixed 硬性成立。设备规格见 `02_飞控与硬件/设备参数/C-RTK3X20P.md`；RTK-01 档案在同目录 RTK-01.md。

### 3.1 架构（改正链经数传，非自包含）

```
地面 X20P 基站 --USB--> 笔记本 Mission Planner（RTK Inject）
    --RTCM3X（MSM4 最小消息集）--> 915 数传（TELEM2/SERIAL2，09-24 对齐）--> 飞控 --> X20P 移动端（09-22 单RTK 拍板、09-23 起 CAN 总线；GPS2/SERIAL4 串口口径随之弃用留作回退）
```

与 RTK-01 的 LoRa 自包含不同：**零新增无线设备，但占数传带宽**——注入期间 NAV30 不得出现 >50ms 空洞（§3.3 带宽联测项）。

### 3.2 配置要点

| 端 | 操作 |
|---|---|
| 基站 | 独立架设（不接飞控）：**长按 MODE 键切基站模式**（LED 常绿）或 LGC 设模块参数 `GPS_TYPE=1`（0=单点/1=基站/2=流动/17/18=MovingBase）；收敛精度/时长 = 模块参数 `GNSS_SVIN_ACC_M/SVIN_DUR_S`（默认 3.0m/30s，**LGC 收紧并记录实际收敛值**，HIT 教训 2.49m 勉强过线；⚠️ QGC 不支持 X20P、MP 配不了收敛项只做注入）；收敛坐标可固化复用（`GNSS_BASE_MODE` 1=ECEF/2=LLH）；`GNSS_RTK_MSM_VER` 出厂即 MSM4 档，注入期仍实测 NAV30；天线架高 1.5~2m、天顶开阔、远离反射面；**上架后全程禁动** |
| 移动端 | 接 **CAN 总线**（4P：5V+/CAN_H/CAN_L/GND，与 PMU 共总线；09-23 起主路线。UART2→GPS2 为回退口径：接线卡 02 册 §9.3，**6P 针序 09-22 官方图已核，万用表实测后再插，勿套 RTK-01-R 循环移位**） |
| 飞控 | **CAN 四钥匙（09-23 落机）**：`CAN_P1_DRIVER=1`、`CAN_D1_PROTOCOL=1`、`GPS1_TYPE=9`、`GPS_AUTO_CONFIG=2`（官方 CAN 指南口径）；回退串路口径=`GPS2_TYPE=2`(UBX)+`SERIAL4_BAUD=230`+`GPS2_AUTO_CONFIG=0`；**勿设 GPS2_TYPE=3**（NMEA 驱动本 beta 已删） |

⚠️ 参数配置走 `rtk_setup.py`（**09-20 已修 WANT 表为 X20P 口径**；旧 RTK-01 版进 git 历史）；改参数后**必须重启并回读**（不重启就判无数据=09-14 外场误判「接线存疑」教训）。

> **刷新率（09-22 实测定性）**：X20P 出厂输出 5Hz = 官方默认（模块参数 `GNSS_RATE_MS=200ms`，范围 25~500ms，40ms=25Hz），**非异常**；飞行维持 5Hz（官方 ArduPilot 指南即按 5Hz 给参）；25Hz 仅作台架吞吐验证——UBX 直配被固件 NAK（u-center/脚本直配不可行），唯一路径 LGC 改 40ms，验毕回归 200ms。

### 3.3 验收分级与转正门槛（每次记录 Fix 收敛时间）

| 级别 | 场景 | 通过标准 |
|---|---|---|
| ① 台架 | 窗口/楼顶，基站架好 | MP status=Fixed，记录收敛用时（≥3 次，分钟级） |
| ② 静态对比 | 已测基准点 | Fix 后读数与基准差 < 数 cm，10min 无漂移（防「Fixed 但整体偏移」） |
| ③ 机上单RTK | 同点位与单点解对照（09-22 单点基线 CEP50=61cm 留档） | Fix/Float 读数与单点解同点位自洽、EKF 无告警、无整体跳变 |
| ④ 带宽联测 | RTCM 注入 + NAV30 + 任务流共存 | NAV30 无 >50ms 空洞（分位间隔统计），修正龄期稳定 |

**转正门槛（四组测试，达标才改 SSOT §3.2）**：固定点静置 / 同点断电重启 / 开阔慢速移动 / 地面中断修正——另加「开 O4 + 舵机动作」耦合项；记录 Fix 率、收敛时间、修正龄期。

### 3.4 比赛启用条件（缺一即维持纯 GPS）

- [ ] 四组测试全过且收敛分钟级（≥3 次实测）
- [ ] 基站场地条件确认（可提前架设完成 survey-in 并固化坐标）；基站卡已建
- [ ] 与已知基准点/单点解静态对比无整体偏移（"Fixed 但偏了"比 Float 更危险；NEO-3 已拔除，对照物=已知点或 09-22 单点基线）
- [ ] RTCM 注入期 NAV30 带宽实测通过；数传频点与邻场错开
- [ ] 基站架设/看护专人（全程禁动）；任务状态机按「纯 GPS 也能完整跑」设计（自动降级）

### 3.5 排障速查

| 现象 | 最可能原因 → 处理 |
|---|---|
| CAN 无数据（fix=0） | 模块侧四嫌疑：CAN1 5V 供电 / H-L 对调 / 插件虚接 / LGC 侧 FD 模式（09-24 通断检测口径）；串口回退路线才查 UART2 6P 针序（TX/RX 交叉）+ `rtk_setup.py` 回读 |
| 有单点无 RTK（Float 不 Fix） | 基站未发 / MP 未注入 / 数传拥堵 → 看 MP Inject 计数、NAV30 空洞统计、基站 SVIN 状态 |
| 长浮不动 | 多径/遮挡 → 基站挪开阔处、架高 |
| Fix 后整体偏移 | survey-in 质量差或基站被动过 → 复位重 survey-in，对基准点复测 |
| 注入期 NAV30 出现空洞 | 数传带宽不足 → 降 MSM 速率/减消息集；仍不足则 RTK 只用于台架标定与起飞前基准 |
| 收敛慢 | 按分钟级预期；对照 HIT 3h37m 教训先查基站视野与多径，不急于改参数 |

## 4. GPS（CUAV NEO-3——09-22 单RTK 拍板后已拔除，转台架备份）

### 4.1 安装与认知

- 装 GPS1 口（**10P 原配线 1:1 直插**，安全开关/蜂鸣器随线），上桅杆远离干扰，箭头同机头；
- 罗盘（⚠️ NEO-3 拔除后本项随件失效）：现役=**双板载 RM3100**（EKF compass 1 在用）；X20P CAN 罗盘升主挂账（前置=CAN 链修复+LGC 检查）；历史口径"IST8310 External 当主"随 NEO-3 下机作废；
- ⚠️ **NEO 3 Pro（M9N）物理不支持载波相位 RTK**——不存在"浮点升固定"路径，勿再追（真 RTK=C-RTK 3 X20P@GPS2，见 §3）；
- ⚠️ **fix_type 判读：0=没通信，1=搜星中**；室内 0 星属正常，勿误判坏件。

### 4.2 配置与验收

- 参数：`GPS1_TYPE=1`(AUTO)（NEO-3 时代；09-23 起现役=9 DroneCAN）。⚠️ 勿设 5(NMEA)——NEO-3 是 UBX 协议，NMEA 驱动互聋（SIH 台架残留曾致"10Hz 报文在流但 0 星"）；也勿设 3（本 beta 已删除该旧 MTK 驱动）；`GPS_AUTO_SWITCH=1`（"X20P@GPS2 双 GPS"口径随 09-22 单RTK 弃用，现 GPS1 位走 CAN）；
- 户外验收标准：**3D Fix + ≥8 星 + HDOP<1.5**；罗盘一致性复核与 GPS 出星同场做；
- 参数改动后回读核验并入全量备份（03 册 §2.2④）。

## 5. 激光定高（微空 MT-01P，TELEM1；09-24 实测定案）

- 设备：UART 激光 0.02~10m、精度 4cm（<2m 段）/2%（>2m）、LVTTL 串口 115200 固定；**出厂默认协议=MAVLink，即插即用，无需微空助手**（官方协议仅 Micolink/MAVLink/MSP 三种，**无 TFmini**——"切 TFmini+TYPE=20"旧方案 09-24 作废）；规格见 `02_飞控与硬件/设备参数/MT-01P.md`；
- 接口：**TELEM1**（SERIAL1，09-24 起；TELEM3 已随迁空置）；接线卡见 02 册 §9.6，TX/RX 交叉 + 共地；
- 参数（09-24 实测定案，14~24Hz 稳定出数）：`SERIAL1_PROTOCOL=1`、`SERIAL1_BAUD=115`、`SERIAL1_OPTIONS=0`（⚠️ bit0=出厂值 1 掐断输入、bit10=1024 被 PreArm 拒，都必须为 0；"禁转发"走 MAV1_OPTIONS bit1 挂账）、`RNGFND1_TYPE=10`（25 是 I2C 版勿混）、`RNGFND1_ORIENT=25` 下视、`RNGFND1_GNDCLR` 按实装高度改（当前 0.1m 占位）；
- 作用：`EK3_RNG_USE_HGT=4` 时激光 4m 以下辅助定高（气压计在 2~5m 桨风下 ±0.5m 跳变不可靠）；并作 PLND 末段距离源与着陆确认（≤0.30m 判据）依据；
- 验收：**卷尺四点比对（0.3/0.6/1.3/2.0m，<2m 段 ≤4cm）通过后恢复 EK3_RNG_USE_HGT=4 并两遍导入** + 强光/草地/俯仰偏置记录 + 系留对比纯气压定高抖动。

## 6. 自查题

1. 数传"完全无数据"第一步查什么？（单向通——注入测试定位，TX/RX 对调）
2. 电台配置为什么必须断机载端电？（X-Rock AT 门控要 +++ 前后 ~1s 静默，1Hz 心跳永远打断它）
3. X20P 流动端现在怎么接？（09-22 拍板单RTK 走 CAN：CAN_P1_DRIVER=1/CAN_D1_PROTOCOL=1/GPS1_TYPE=9/GPS_AUTO_CONFIG=2 四钥匙；UART2→GPS2 6P 针序为回退口径，勿套 RTK-01-R 循环移位——旧规则直通=5V 撞 GND）
4. NEO-3 能跑 RTK 吗？（不能——M9N 物理不支持载波相位；"浮点"实为 DGPS）
