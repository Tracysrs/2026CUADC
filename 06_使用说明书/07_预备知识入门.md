## 1. 四旋翼无人机是怎么飞起来的

### 1.1 升力与布局

- 螺旋桨旋转把空气往下推，空气把桨往上推，这就是升力。**四个电机的总升力 > 整机重量**才能飞起来。
- 本机：4 × YH 4120 电机（KV340）+ 14 寸桨 + 6S 电池，单桨最大拉力约 2.8~3.2 kg，
  总拉力 11~13 kg，**整机控制在 9 kg 以内**（拉重比 ≥1.24 才够机动余量，≥1.5 更好）。
- KV 值 = 每伏转数：KV340 × 6S（22.2V）≈ 7500 转上限（带负载后打折）。KV 低配大桨 = 效率高、载重大，这就是 8kg 级用 KV340 而不是穿越机 KV1700 的原因。
- **正反桨**：四旋翼不需要尾桨，靠 2 支正桨（CW）+ 2 支反桨（CCW）让反扭矩互相抵消。
  装错旋向飞机会疯狂自旋——所以装机后有"电机方向验收"这一步。

### 1.2 Quad X 布局与电机编号（本机定案，ArduPilot 体系）

俯视机头朝前，本机 `FRAME_CLASS=1 / FRAME_TYPE=1`（Quad X）：

| 输出口 | 位置 | 旋转方向（俯视） | 桨 |
|---|---|---|---|
| M1 | 前右 | 逆时针 | 常规桨 |
| M2 | 后左 | 逆时针 | 常规桨 |
| M3 | 前左 | 顺时针 | 反桨（R） |
| M4 | 后右 | 顺时针 | 反桨（R） |

规律：**对角同向、相邻反向**。控制原理：想往右滚 → 减右侧两桨升力、加左侧两桨；
想偏航 → 加一对顺时针、减一对逆时针。这些由飞控自动完成，你只管发"往前飞 2m/s"。

### 1.3 控制链路（从你的指令到电机）

```
你的意图（模式/航点/速度）
   ↓ 飞控按模式换算成姿态目标（想要 15° 倾角）
姿态内环（角速度环 + 角度环，几百 Hz，PID）
   ↓ 电机混控（mixer：姿态差动 → 四个电机各转多快）
电调（ESC）按 PWM 信号驱动无刷电机
   ↓ 传感器闭环：IMU（陀螺+加计）/气压计/磁力计（罗盘）
EKF3（扩展卡尔曼滤波）：把十几个传感器的读数融合成"我现在在哪、姿态多少、速度多少"
```

新手需要记住的三件事：
1. **姿态内环参数（ATC_*）与机重强相关**——仿真里 Iris 1.5kg 的调参不能搬到我们 8kg 真机上；
2. **EKF 需要"位置源"才有位置估计**：GPS / 视觉里程计（VIO）/ 动作捕捉。真机没 GPS 时
   `GUIDED` 任务模式直接拒绝解锁（`Arm: Need Position Estimate`），这是固件强制层，绕不过；
3. **多旋翼的一切"自主"都建立在位置估计之上**——项目里"等 GPS 户外出星"卡的就是这个。

## 3. 飞控与 ArduPilot 体系

### 3.1 固件与模式

- **固件** = 飞控里跑的软件。ArduPilot 是开源飞控固件之一（另一个主流是 PX4，我们 09-01
  曾做过 PX4 初版，后整体切到 ArduPilot——冠军队同路线、PLND/生态成熟）。
- **飞行模式**（本机常用五个）：

| 模式 | 干什么 | 位置估计要求 |
|---|---|---|
| STABILIZE | 手动，飞控只稳姿态 | 无要求（桌面验证解锁用它） |
| AltHold | 定高，杆控水平 | 有高度估计即可 |
| **GUIDED** | 由机载电脑实时发目标（本项目任务模式） | **必须有位置估计** |
| RTL | 自动返航 | 有 |
| LAND | 原地降落 | 有 |

- **解锁/上锁（arm/disarm）**：电机从怠速待命到允许转动的开关。解锁前飞控做
  PreArm 自检（电压、罗盘、加速度计、RC、电机参数…），任何一项不过报
  `PreArm: xxx` 拒绝——排障就照着报错逐条清。

### 3.2 失效保护（Failsafe）——比赛安全的一半

| 参数 | 本机值 | 含义 |
|---|---|---|
| FS_THR_ENABLE | 5(RTL)，**上场前改 0** | 遥控断链时自动返航（调试期安全网） |
| FS_GCS_ENABLE | 0 | 数传断链不动作（自主兜底，地面断链不慌） |
| BATT_FS_LOW_ACT | 2(RTL) | 低电 21.6V 自动返航 |
| BATT_FS_CRT_ACT | 1(Land) | 严重低电 21.0V 原地降落 |
| RC6_OPTION | 31 | CH6 急停拨杆（细则 5.8 的"紧急停止"） |

### 3.3 精准降落（PLND）

ArduPilot 内置的"视觉对准降落"模块：机载电脑检测降落标识后发 `LANDING_TARGET`
消息，飞控自动修偏。参数 `PLND_ENABLED=1 / PLND_TYPE=0`——**0=伴飞计算机方案**，
1=IR-LOCK 红外信标（架构不同，勿改）。

## 4. 通信基础（排障 80% 在这一节）

### 4.1 串口（UART）

三根线就够用：**TX（发）、RX（收）、GND（地）**。两条铁律：
1. **TX 接 RX，RX 接 TX——必须交叉**。直通线 = 单向通或完全不通（项目里数传排障
   实锤案例：地面能注入请求、心跳回不来，就是没交叉）；
2. **必须共地**。另外若线缆没有流控线（CTS/RTS），参数必须关流控
   （`BRD_SER2_RTSCTS=0`），否则完全不通。

**波特率** = 每秒比特数，两端必须一致。本机串口地图：

| 飞控口 | 接什么 | 波特率 | 参数 |
|---|---|---|---|
| TELEM1 | 数传 | 57600 | SERIAL1_PROTOCOL=2 / BAUD=57 |
| TELEM2 | Jetson | 921600 | SERIAL2_PROTOCOL=2 / BAUD=921 |
| TELEM3 | TFmini | 115200 | SERIAL5_PROTOCOL=11 / BAUD=115 |
| GPS1 | NEO-3 | 自动 | — |
| GPS2 | RTK rover（测试） | 921600 | GPS2_TYPE=3(NMEA) |
| USB | 台架调试（Windows COM 口 / Jetson ttyACM0） | 115200 | — |

⚠️ 本固件串口映射：SERIAL0=USB，SERIAL1=TELEM1，SERIAL2=TELEM2，SERIAL4=GPS2，
SERIAL5=TELEM3，SERIAL6=UART4。查参数先对这张表。

### 4.2 MAVLink

飞控与世界对话的协议。一帧帧"消息"：心跳（HEARTBEAT）、姿态（ATTITUDE）、
电池（BATTERY_STATUS）、参数（PARAM_SET/PARAM_VALUE）……
- **ArduPilot 见到 GCS 心跳才开始流送遥测**——mavros 不冒充 GCS，所以要开
  `gcs_url` 桥 + 心跳泵（详见 05 系统模块 §3），这是"连上了但没数据"的头号原因；
- 新版 ArduPilot（4.7）没有 SR0_* 流送参数，要用 `set_message_interval` 逐条订阅；
- Windows 上用 **pymavlink**（Python 库）直接对话：项目里 `02_飞控与硬件/调试工具/` 全部
  脚本（check_fc / motor_test / verify_params…）都是它写的。

### 4.3 接收机信号制式

| 制式 | 特点 | 本机 |
|---|---|---|
| PWM | 一通道一根线 | — |
| **PPM** | 一根线串 8 通道 | ✅ iA6B 用这个（接 PPM IN 专用座） |
| SBUS | 串口制式，需对应口 | iA6B 没有（曾经的场误会） |
| CRSF | ELRS 用的串口制式 | 已砍掉（省 ¥300+） |

⚠️ PPM IN 座三针 = GND / **信号（中间）** / 5V；接收机三针 = S / **VCC（中间）** / GND
——**针序镜像，直通杜邦线 = 电源反接**（"信号线一碰接收机就掉电"的根因）。

### 4.4 通道规划（比赛定案）

CH1~4 = 摇杆（油门/偏航/俯仰/横滚）；**CH5 = 飞行模式**（SWA 拨杆）；
**CH6 = 急停**（SWC 拨杆，RC6_OPTION=31）。

## 5. 机载计算：Jetson + ROS 2 + MAVROS

### 5.1 Jetson

NVIDIA 的机载电脑板，带 GPU（CUDA），能跑 TensorRT 神经网络推理。系统是
JetPack（Ubuntu 22.04 底座）。本项目它负责：相机取流 → 神经网络检测 → 解算筒位 →
任务状态机 → 通过 MAVLink 指挥飞控。日常通过 `ssh jetson`（局域网 10.66.24.217）远程操作。

### 5.2 ROS 2（Humble）

机器人中间件：程序拆成**节点（node）**，节点之间靠**话题（topic）**传消息。

- `ros2 topic list` 看有哪些话题；`ros2 topic echo /xxx` 看内容；
- 消息类型如 `geometry_msgs/PoseArray`（一组位姿）；
- **QoS**：`best_effort`（丢帧优于堵塞，图像/检测流用）vs `reliable`（一条不丢，
  结构化结果用）；
- 本项目话题契约见 `03_机载软件/接口契约.md`：检测流
  `/perception/drop_buckets_body`、心跳 `/perception/heartbeat`、任务状态
  `/cuadc/mission_state`；
- `colcon build` = 编译工作空间；`~/cuadc_ws/src` 放各功能包。

### 5.3 MAVROS

把 MAVLink 翻译成 ROS 话题/服务的桥：飞控的姿态变成 `/mavros/local_position/pose`
话题，"起飞"变成 `/mavros/cmd/takeoff` 服务。任务状态机（`cuadc_mission` 包）就是
通过 MAVROS 控制飞机的。

⚠️ 新手最常被坑的三条：① 判断 MAVROS 通没通**别用** `ros2 topic echo --once`
（DDS 发现慢会假阴性），看任务节点日志过没过 `WAIT_FCU`；② MAVROS 参数列表同步
约 17s，之前 set 参数静默失败；③ 多网卡机器加 `ROS_LOCALHOST_ONLY=1`。

## 6. 视觉与深度学习基础

### 6.1 相机与坐标

- **内参** (fx, fy, cx, cy)：镜头的几何属性，标定一次用很久。像素坐标 (u,v) 和
  物理角度的关系全靠它；
- **外参**：相机相对机身的安装位姿（偏置+旋转）；
- **单目测距**（本项目核心公式）：已知真实物体高 H（筒 0.30m）、像素里量出 h_px：
  `距离 Z = f_px × H / h_px`，横向 `dx = (u−cx)·Z/fx`。像越小的物体越远；
- **帧率 FPS**：每秒处理帧数。检测 ≥25FPS 才算实时（本机 TensorRT 实测 52.8）。

### 6.2 YOLO / 训练 / 部署

- **YOLOv8**：单阶段目标检测模型。`-seg` 版还能输出像素掩码（用来量筒口直径），
  `-det` 版只出框（标识分类用它）；
- **训练**：喂数据集（图 + YOLO 格式标签 `类别id x y w h`）跑几百轮，产出 `best.pt`
  权重。训练在云端 4090（AutoDL 约 ¥2/时）做；
- **TensorRT**：NVIDIA 的推理加速引擎。`.pt` 权重在 Jetson 上导出成 `.engine`
  （FP16 半精度），速度快数倍。⚠️ engine 与"权重+设备"**双绑定**：换权重必须重导，
  比赛日绝不可现场构建（本机导出一次要 9min46s）；
- **mAP50**：检测精度指标（交并比阈值 0.5 下的平均精度）。项目验收线：逐类 ≥0.90。

### 6.3 拒识（本项目的关键设计）

分类模型输出"各类别置信度"。规则：**top1 < 0.7 或 top1−top2 < 0.3 → 拒识留空**。
因为比赛规则"错一个 −100，不填不扣"——**留空是合法答案**。这是"宁可少得分不能倒扣"
的工程化表达。

## 7. 坐标系（全项目最大坑，提前建立概念）

| 坐标系 | 定义 | 本项目用途 |
|---|---|---|
| ENU（本地系） | x 东 y 北 z 上 | 飞控 odom 世界系；筒位地图建在这里 |
| 机体系 FLU | x 前 y 左 z 上 | 感知输出目标在这里（契约 frame_id=`cuadc_body_flu`） |
| 机体系 FRD | x 前 y 右 z 下 | 飞控部分消息（LANDING_TARGET）用 |
| 罗盘航向 | 磁北为 0° 顺时针 | 换算：`yaw_ENU = 90° − compass_hdg` |

三个由血泪换来的规矩（HIT 冠军队翻车两个月的坑）：
1. **起飞前记录任务原点**（EKF 原点 ≠ 起飞点）；
2. **起飞前锁航向**，整个任务不转机头（状态机 `LOCK_FRAME` 独立态：2s 内航向变 ≤2°
   才锁坐标系）；
3. 所有视觉测得的位置要**先插值补偿时间延迟**再转世界系（2m/s × 100ms 延迟 =
   20cm 误差，比对准门限 10cm 还大）。

## 8. 仿真体系

| 名词 | 是什么 |
|---|---|
| SITL | 软件在环：ArduPilot 固件编译成 Linux 程序跑，"假飞控" |
| Gazebo | 3D 物理仿真器：给 SITL 提供虚拟世界（重力/碰撞/相机） |
| ardupilot_gazebo 插件 | 把 Gazebo 里的无人机和 SITL 连起来（JSON 端口 9002/9003） |
| MAVROS | 同真实飞行一样接 tcp 5760 |
| sim-to-real | 仿真和实机共用同一套 `/perception/*` 接口 = 同一份任务代码两边都能跑 |

**项目铁律：每一版任务代码先过 SITL 再上真机。** 仿真里还要做异常注入
（冻结 SITL 进程模拟定位断流），比真机安全一万倍。
保真度边界：任务层（航线/时序/状态机）仿真可信；**姿态内环参数不可从仿真搬到实机**
（Iris 1.5kg vs ZD550 8kg）。

## 9. 本项目核心概念速查（听懂行话）

| 行话 | 意思 |
|---|---|
| 白筒 | 投放目标桶，三种直径 15/20/25cm（15cm 是 500 分那只，最难的） |
| 危化标识 | 贴在侦察桶上的 12×12cm 贴纸，附件 11 规定 10 类 |
| H 圆 | 着陆点的 ø80cm "H" 标识（着陆分 + PLND 用） |
| 18 态状态机 | 任务代码的主循环：WAIT_FCU→…→TAKEOFF→SEARCH→ALIGN→RELEASE→…→DONE |
| 锁定五步 | SEARCH 段确认三个筒的流程（5 帧确认→独立性→直径对号→排名稳定→冻结） |
| 八门控 | 投放前必须全过的 8 项检查（误差/速度/倾角/新鲜度…） |
| CEP | 圆概率误差：一半投放落点半径 < CEP。冲 15cm 小桶要求 CEP<5cm |
| 两步法标定 | 铅垂线静态偏置 + 真实试投修正（投放准不准的物理根基） |
| 契约 | 感知↔状态机的消息格式约定（字段复用+版本哨兵+fail-closed） |
| 懒加载参数 | 功能没开启的参数在固件里不存在 → 参数必须导入两遍（中间重启） |
| 启动不稳定窗 | reset 后飞控 sketch 反复重启的分钟级窗口，过门禁再开飞 |
| 心跳泵 | 伪装 GCS 发心跳，骗 ArduPilot 开始流送遥测的脚本 |
