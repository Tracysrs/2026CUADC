### 2.2 参数体系（4.7-beta 两大特性 + 基线全文）

**① 新一代参数命名（SI 单位后缀）——写旧名会被静默忽略**（回读应答超时而非报错）：

| 旧名（资料/老固件常见） | 本固件实名 | 说明 |
|---|---|---|
| WPNAV_SPEED | `WP_SPD`（m/s） | GUIDED 速度也归它管（GUIDS_* 整组取消） |
| LAND_SPEED | `LAND_SPD_MS`（m/s） | |
| FS_GCS_ENABL | `FS_GCS_ENABLE` | |
| BATT_LOW / BATT_CRT | `BATT_LOW_VOLT` / `BATT_CRT_VOLT` | 写旧名静默失效 |
| GUIDS_ANGLE | `ATC_ANGLE_MAX` | **单位已改"度"**：写旧值 3500 触发 PreArm "must be >= 10 and <= 80"，应写 35 |

另：这版**没有任何 `COM_` 前缀参数**（`COM_RC_IN_MODE` 不存在）。全参数快照 `03_工具/飞控调试/_param_dump.txt`（09-09 改动**前**的快照，对账时注意），查参数名以它为准。

**② 懒加载参数组 → 参数必须导入两遍（中间重启）**：`RNGFND1_*`、`PLND_TYPE` 等在功能开启并重启前**不存在**于参数表；反向也成立（`RNGFND1_TYPE=0` 时其子参数从表里消失，参数总数 1086→1071 是这个原因，对账遇计数差异先想到懒加载，不是丢参数）。

### 2.3 电池与解锁电压（6S 专属，电压体系表见 02 结构模块 §1.3）

- 出厂默认 3300mAh/10.5V 是 3S 值；本机 6S 8000mAh；
- 三级阈值：低电 21.6 → **RTL**；严重 21.0 → **Land**；解锁门槛 `BATT_ARM_VOLT=22.5`；
- **22.5 的区间推理**（为什么不设 24.5 也不设 21.8）：
  - 下限 = 低电阈值 21.6 + 悬停带载压降（6S 8000 约 0.6~1.0V）≈22.5——低于它解锁后一上负载就跌进低电区，起飞即触发失效保护；
  - 上限 ≈23.8——再高短飞落地（静止 ~23.2-23.5）无法复飞（**首版 24.5 的教训：只有近满电能解锁**）；
  - 22.5 = 标称与存储之间：存储态 22.92V 可解锁；刚触发严重保护落地的电池（静止回升 ~22.0-22.2）拒绝解锁，**强制换电**——这是设计行为不是故障；
- 压降为估算值，系留试飞时看悬停带载电压校核，必要时微调。

### 2.4 电机测试（拆桨，未解锁也能测）

```bash
python 03_工具/飞控调试/motor_test.py COM5 [输出口]
# 全测 M1→M4；python motor_test.py COM5 3 只转 M3
```

**脚本内部三道核验**（09-11 严格化，防"看着按序实际点错口"）：

1. **机架换算表**：读 FRAME_CLASS/FRAME_TYPE 查内置表取"输出口→测试序列号"映射（四轴 +/X 两种，其他机架直接拒绝），不再硬编码；
2. **输出口绑定**：逐个读 SERVO1~4_FUNCTION，必须 = Motor1~4(33~36)，否则拒绝盲测——`DO_MOTOR_TEST` 按"电机"寻址，绑定不对时"按序"是假象；
3. **安全开关代解**：自动发 `MAV_CMD_DO_SET_SAFETY_SWITCH_STATE`(5300) param1=1 解**会话**安全锁（`BRD_SAFETY_DEFLT` 只管开机默认，会话内状态独立）。

其他行为约定：

- ⚠️ param1 是**测试序列号不是输出口**（Quad X 序列 = 前右→后右→后左→前左，直接发 1~4 表现为"顺时针绕圈"点亮，是固件设计行为别误判接线错）——脚本内置 `OUT2SEQ={1:1,2:3,3:4,4:2}`；
- 顺序强制：输出列表强制升序去重（传 3,1 也按 M1→M3 跑）；每台等满转 1s + 间隔 2.5s；中途被拒立即停（宁缺勿乱不跳号）；开跑前 3 秒倒计时，Ctrl-C 取消则一个信号都不发；
- ⚠️ **只插 USB 不接电池时电机测试无效**（电调无主电，FC 接受指令但电机不转，还触发电池失效保护）；
- 方向修正：对调该电机三根相线中任意两根（方向表见 02 结构模块 §5.2）。

### 2.5 校准（一律走 Mission Planner GUI！）

⚠️ 复用坑：本 beta 对裸 `MAV_CMD_PREFLIGHT_CALIBRATION` 回 COMMAND_ACK ACCEPTED 但**静默不执行**（无提示、参数不写）。**校准别用裸 MAVLink**——同一指令在 MP 会话里正常。

**① 无线电校准（RC）**——ESC 校准的前置：MP → 初始设置 → 必需硬件 → 无线电校准（前置 = PPM 链路已通）。

**② 加速度计 + 罗盘**（✅ 09-09 完成，09-12 NEO-3 上机后重校）：

1. MP 六面校准；完成后报 "requires reboot" → 重启加载生效（实测罗盘偏置落盘、姿态 roll +0.2°/pitch +0.9° 稳定）；
2. 验证：PreArm 的 Accel/Compass 告警消失；
3. 罗盘勾选：**RM3100（NEO-3 外置）勾 External 当主罗盘；IST8310（V6X 板载）取消 External**——勾反 = 板内受扰罗盘当主用 = 航向漂/EKF 拒定/炸机；改完 Reboot **必须重跑一遍校准**；
4. ⚠️ MP 校准进度条"满了归零重来" = 拟合拒绝自动重采（转太快/磁干扰），非故障；室内钢筋环境 Z 轴偏移可能偏大（RM3100 -396 / 经验值 <150），解锁一致性检查过了就能用，户外重校兜底。

**③ ESC 油门行程校准**（✅ 09-12 参数法定案，免 MP 向导，推荐固化）：

1. 前置：**无桨**、无线电校准已完成、机体压稳；
2. MAVLink 写 `ESC_CALIBRATION=3`（**等 5 秒刷存储**）；
3. 拔电池**并拔 USB** → 只接电池 → 电调自动学行程：听"音乐音 + 2 滴（学到满行程）→ 6 滴（6S 每芯）→ 1 长音（完成）"；
4. 参数自动归零，回读确认；
5. 验证：解锁慢推油门，四电机齐转、响应一致（可用 motor_test.py 复核）；
6. ⚠️ 校准完成后飞控自动重启一次可能**卡死（USB 枚举在但固件不应答，MP 写超时）+ 残留假 PreArm**（Baro not healthy / Battery failsafe）——**彻底断电复位 + 1 分钟预热一招清**，不是坏件。

（MP 向导路径等价：初始设置 → 可选硬件 → 电调校准 → 立即校准——原理同为写 ESC_CALIBRATION=3 后重上电。好盈 XRotor 40A 支持标准学习；安全开关步骤当前可跳过，因 BRD_SAFETY_DEFLT=0。）

### 2.6 解锁

**桌面 STABILIZE 解锁**（非位置模式，强制层豁免；✅ 09-12 MAVLink 解锁零拒绝）：

- 条件全绿：电压 ≥22.5V、加速计 ✅、罗盘 ✅、RC 健康、电机参数 ✅（MOT_SPIN 组）；
- 操作：左摇杆右下 2s 解锁（电机怠速），左下 2s 上锁；
- 排障（PreArm 拒绝逐条清；**抓拒绝原文要听满整个窗口**——COMMAND_ACK 比 STATUSTEXT 先到，只抓 ack 会误判）：

| 拒绝原文 | 根因 → 处置 |
|---|---|
| `Battery below min arming voltage` | 电压 <22.5V → 充电（存储态 22.9V 可解锁；刚触发严重保护落地的电池强制换电） |
| `Accels/Compass calibrated requires reboot` | 校准后没重启 → 断电重启 |
| `MOT_SPIN_ARM > MOT_SPIN_MIN` | 怠速参数孤儿值 → 成组写回 0.15/0.13 |
| `Motors Emergency Stopped` | 急停拨杆在触发位 → CH6 拨回低位 + 重新解锁 |
| `Compass not calibrated` | 重校罗盘（§2.5②） |
| `RC not found` / Radio failsafe | 接收机链路断 → 查 PPM 接线（02 结构模块 §6） |
| `Arm: Need Position Estimate` | **GUIDED 专属强制层**，桌面绕不过（见下） |

**GUIDED 任务链 = 另一回事，硬依赖位置源**：

- 4.7 固件强制层：`Arm: Need Position Estimate`（`AP_Arming_Copter.cpp:467`，mandatory 检查，ARMING_SKIPCHK=-1 也跳不过；旧固件 ARMING_CHECK=0 的"无 GPS 硬解锁"口子在 4.7 已收紧）；
- 状态机路径同样卡 `WAIT_NAV_STABLE`：真机无 GPS 时 mavros local_position/odom 不出流（与 SITL 的关键差异——SITL 有仿真 GPS）；
- 结论：**GPS 户外出星之前，GUIDED 全流程不可能真机跑**。别在桌面跟这条死磕（09-09 磕过一整晚：可跳过层五项全跳了，强制层仍拒；实验脚本 `fc_armrun.sh`/`fc_armtest.sh` 已把"临时改参数 + trap 自动恢复 + 回读校验"做成闭环）。

### 2.7 遥控器端配置（FS-i6）

- 通道规划：CH1~4 摇杆；**CH5 = 飞行模式**（SWA 三段，固件默认 FLTMODE_CH=5）；**CH6 = 急停**（SWC 两段，RC6_OPTION=31）；
- 开关分配在 AUX 菜单（本机曾疑刷 10 通固件菜单异常——CH5/CH6 均绑 VRB 改不动、拨杆零变化——最终 AUX 菜单完成分配）；**开关测试要做单开关单测**（混测+统计窗口曾把 SwA 余动作误判成 SwC）；
- ⚠️ **failsafe 必须改 No pulses**（RX SETUP → FAILSAFE；出厂"保持"会让飞控察觉不到断链）——挂账待做；
- 急停语义：SwC 高位(>1800) = 电机停转锁死；解除 = 拨回低位 + 重新解锁。即细则 5.8 的"紧急停止"。

## 3. 数传与地面站操作（远航 3DR Radio X6）

> 数传 = 飞控↔地面笔记本之间的无线"串口线"（433MHz 载波跑 MAVLink）。三件事：实时监控 / **侦察回传填单主通道** / 地面指令备份。三个"不是"：不传图像（空口 ~57.6kbps 只够遥测；图传上场前必须报备裁判）、不是遥控（控飞机的是 PPM 链路）、不参与飞控计算（纯透传）。

### 3.1 连接

1. 机载版接 TELEM1（参数 `SERIAL1_PROTOCOL=2 @ 57600` = SiK 出厂速率，**飞控侧一次性写入零维护**）；地面版 USB 接笔记本；
2. 驱动：地面电台为 CP2102（SiLabs VCP 驱动），认出 COM 口（本机固定 COM10）；
3. MP 右上角：选 COM 口 → 波特率 **57600** → 连接；
4. 验收：HUD 出姿态、地图出位置、RSSI 百分比显示。
上电顺序：整机上电 → 等自动建链（几秒）→ 地面站点连接。**一对出厂同 Net ID，无需配对。**

### 3.2 验收分级（逐步拉远，别一步到位）

| 级别 | 场景 | 通过标准 |
|---|---|---|
| ① 台架 | 飞控仅 USB 供电 | MP 能收数、参数页能读 |
| ② 整机 | 6S 供电全系统 | 同上，且舵机动作/电机解锁时数据不断流 |
| ③ 拉距离 | 场地目视范围 | 链路质量稳定，RSSI 衰减合理 |

（✅ 09-11 端到端验收通过：地面站 COM10 收到飞控心跳流，sysid=1，1Hz 全链通。）

### 3.3 电台参数与频点

- **日常无需配置**：一对出厂同 Net ID，链路 09-11 验收通过后零维护。只有赛场撞频才需要动手；
- **⛔ MP 1.3.83 的 SiK 电台页对本电台定案不可用（09-12 实锤）**：即使 COM10 + 57600 + 链路静默全对，点"加载设置"也必然抛 `InvalidOperationException: 端口被关闭`（其 RFD900.TSession 进命令模式失败后自身流程崩溃）。页面全空、异常弹窗都是这一个原因，与链路健康无关；
- **正解（要改参数时）**：
  1. 给机载端断电，只留地面 USB 棒插电脑（链路静默是前置条件——X-Rock 固件进配置要 `+++` 前后 ~1s 串口静默，心跳每 0.97s 一帧永远打断它）；
  2. 跑 `03_工具/飞控调试/check_radio.py` 核身：`ATI` 应答 **X-Rock 4.0** = 电台活着、AT 通道可进；
  3. 改参数用 **3DR Radio Config** 独立小工具（CSDN 有下载，界面与 MP 电台页相同）；**严禁给 X-Rock 发 ATI5**（固件挂死，全哑，只能重插 USB 恢复）；
- 两个易混口别搞反：**COM5 = 飞控 USB**（MAVLink 连接/调参用），**COM10 = 地面数传**（只用于电台配置）——在 COM5 上开电台配置页必然全空；
- **频点错开**（上场检查项）：邻场同频改 **Net ID**；同场多对数传必做（按上面静默流程操作，改完两端同步）。

### 3.4 比赛角色：侦察回传填单链路

```
机上 Jetson(TELEM2 @921600) → 飞控 MAVLink 桥接 → TELEM1(@57600)
  → 机载数传 —433MHz→ 地面数传(USB) → Mission Planner → 组员填单
```

- 填单员分工：一人看链路与飞机状态，一人按消息填单；**不要盯着地面站"开飞机"**——飞机是自主的，地面站职责 = 监控、填单、必要时 SWC 急停；
- 断链预案：`FS_GCS_ENABLE=0`，机载状态机自主兜底；数传异常**不要急着重启折腾链路**，先保任务；
- 433MHz 与 FS-i6 的 2.4G 不同频段互不干扰；真正要防的 2.4G 干扰源是 GoPro WiFi（02 结构模块 §4）。

### 3.5 排障速查

| 现象 | 最可能原因 | 处理 |
|---|---|---|
| 下拉里没有 COM 口 | 驱动没装 / 换了 USB 口 | 装 SiLabs VCP 驱动 |
| 连接超时 | 波特率不是 57600 / 口选错 | 核对 §3.1 |
| 连上但 HUD 全空 | 机载版没插 TELEM1 / 天线没装 | 查接线与天线；验 SERIAL1 两参数 |
| **单向通**（地面能注入请求、心跳回不来） | **TX/RX 没交叉** | 对调两根信号线——09-11 实锤排障法：地面注入 PARAM_REQUEST_READ，飞控在 COM5 应答正常 = 半根线通，改线秒通 |
| **SiK 电台页全空/读不出** | MP 电台页与 X-Rock 固件不兼容 + 口选错（COM5 是飞控口）——两个坑都指向同一现象 | **别用 MP 电台页**（1.3.83 对此电台必崩）：选 COM10、机载端断电静默后跑 check_radio.py 核身（应报 X-Rock 4.0），改参数用 3DR Radio Config 工具 |
| **电台对一切 AT 指令全哑** | X-Rock 固件命令解析器被不支持的指令挂死（如 ATI5） | **重插地面 USB 棒**即恢复；以后探测只用脚本白名单指令（+++\r、ATI~ATI4、ATO） |
| RSSI 很低 | 天线被碳架遮挡 / 与电源线捆扎 | 重走线，天线露出机架外 |
| 一会儿断一会儿好 | 邻场同频干扰 | 改 Net ID 错开 |
| 拉远就断链 | 超链路余量 | 任务半径 300m 内标称 2km 有大余量，先查天线再怀疑距离 |

## 4. RTK 操作（瑞杰 RTK-01，备用/测试链路）

> ⚠️ **定位策略**：SSOT 定案主定位 = NEO-3 GPS + 视觉 + 激光（冠军队 Fix 收敛 3h37m、基站日志早停 2 分 21 秒的教训）。本设备**只做测试/备份**，比赛是否启用默认否，启用须过 §4.4 五条件。

### 4.1 架构（与教科书 RTK 不同）

改正链路**自包含**：基站 RTK-01-B --LoRa 890~915MHz--> 机载 RTK-01-R --NMEA @921600--> V6X GPS2。教科书式"基站→笔记本→数传注 RTCM"不适用——基站独立工作（供电即 survey-in，完成后自动发改正，**全程不需笔记本**）；433 数传零占用；三段无线电（433/900LoRa/2.4G）互不重叠。

### 4.2 配置

| 端 | 操作 |
|---|---|
| 基站 B | 天线拧上，架高 1.5~2m、天顶开阔、远离反射面（**多径是 Fix 收敛慢第一杀手**）；Type C 供电（充电宝可带 260mA）；**上架后全程禁动**（"Fixed 但整体偏移"比 Float 更危险——EKF 会自信地信错位置） |
| 机载 R | 接 GPS2（接线坑见 02 结构模块 §7.2）；指示灯：LORA 亮 = 改正收到；RTK 灯 = Fix 状态；PPS 闪 = 时钟锁定 |
| 飞控 | GPS2_TYPE=3(NMEA)、GPS_AUTO_SWITCH=0（**只看不切**）；⚠️ 这版固件无 GPS2_BAUD 参数——GPS 口波特率跟底层串口 SERIAL4（改 SERIAL4_BAUD，GPS 口固件默认 230=230400）；罗盘第三只 QMC5883 设 **Yaw315°** 再校（规格书 ArduPilot 指定值） |

### 4.3 验收分级（每次记录 Fix 收敛时间——上场与否的决策数据）

| 级别 | 场景 | 通过标准 |
|---|---|---|
| ① 台架 | 窗口/楼顶，基站架好 | RTK 灯 Fix（或 MP status=Fixed），记录收敛用时 |
| ② 静态对比 | 已测基准点上放 R | Fix 后读数与基准差 < 数 cm，10min 无漂移 |
| ③ 机上对比 | 与 NEO-3 并跑 | GPS1/GPS2 位置一致，EKF 无告警，全程 AUTO_SWITCH=0 |

（验收看 MP：GPS 2 面板 status=RTK Fixed/Float，HDOP<1.5、VDOP<2.0。）

### 4.4 比赛启用条件（SSOT 决策输入，缺一即维持纯 GPS）

- [ ] 台架收敛时间稳定在分钟级（≥3 次实测），非小时级
- [ ] 基站场地条件确认（赛前可提前架设完成 survey-in）
- [ ] 与 NEO-3 静态对比无整体偏移（"Fixed 但偏了"比 Float 更危险）
- [ ] 赛场 900MHz 环境实测无压制（LORA 灯常亮不闪断）
- [ ] 基站架设/看护专人（全程禁动）

### 4.5 排障速查

| 现象 | 最可能原因 → 处理 |
|---|---|
| GPS2 无数据 | 线序反 / TYPE 没配 → 万用表重测 6P（02 结构模块 §7.2 映射） |
| 有 GPS 无 RTK（Float 不 Fix） | 基站没发 / LoRa 不通 → 看 B 供电与 R 的 LORA 灯 |
| LORA 亮但长浮不动 | 多径/遮挡 → 挪基站到更开阔处、架高 |

| 波特率扫描全零别当结论 | "死模块"期间的扫描结果不算数——供电修好后按实际波特率重测定稿 |

## 5. 仿真日常操作卡（统一入口）

> 环境从零装见 05 系统模块 §5；任务参数权威在 Jetson `~/cuadc_ws/src/cuadc_mission/config/mission_params.yaml`。脚本 SSOT 在仓库 `03_工具/仿真环境/jetson/`（**完整操作手册 = `jetson/操作手册.md`**：六步流程/排障速查/红线），与 Jetson `~/sim_scripts/` 同份，**改哪边记得同步另一边**。

### 5.1 标准流程（四步，模式可选）

```bash
ssh jetson
python3 ~/sim_scripts/randomize_scene.py  # ⓪ 可选：随机布景（桶/标识随机摆，真值+判分自动联动；
                                          #    只重启 gz 不动 SITL，无长等待；加 --seed N 固定布局）
bash ~/sim_scripts/reset_sim.sh           # ① 重置全栈（~30s）
bash ~/sim_scripts/start_gzgui.sh         # ② 挂画面（可选，可重复执行重挂；右键 iris → Follow 跟机）
python3 ~/sim_scripts/fcu_ready.py        # ③ 就绪门禁 v2：双端口+GPS 3D 校验+耦合僵死自动重启 gz
                                          #    自愈（一般 1~5min 过；打印"FCU 就绪：稳定窗+GPS 3D ✓"才继续）
bash ~/sim_scripts/fc_task.sh m3          # ④ 跑任务到 DONE 并输出"完成事项"（模式见下表）
```

**任务模式**（fc_task.sh 第一参数，缺省 m3）：

| 参数 | 底层脚本 | 感知 | 预期 |
|---|---|---|---|
| `mission`（m1） | fc_sitl_mission.sh | 无（演练） | 飞完整链 DONE，投放 0/2 属预期 |
| `m3` | fc_sitl_m3.sh | 场景真值替身 | 投放 2/2 A 区（判分 400），125~142s |
| `m2` | fc_sitl_m2.sh | CV 相机真感知 | 视觉在环验收（gz 渲染世界须在跑） |

成功判据（reset_sim 末行）：`ardu=1 gz=1 p9002=1 l5760=1 c5760=0`（p9002=飞控↔Gazebo 耦合口，l5760=SITL MAVLink 监听，c5760 非 0 = 有泄漏进程抢槽）。
**验收门**：状态轨迹 `WAIT_FCU→…→TAKEOFF→SEARCH→RECON_SURVEY→RETURN_HOME→LAND→DISARM→DONE`；任务结束自动输出"**完成事项**"（各段耗时/投放明细误差与分区/拍照确认/总时长/判分累计）。

### 5.2 任务脚本内部步骤（理解用，排障对号）

[0] **强清残留**（僵尸任务节点会共享 mavros 发 disarm 把新任务在空中打下来，09-13 实证）→ 自检 5760 未被占（`ss -tnp` 查，命中即 ABORT 并打印占用者——SERIAL0 单客户端）→ 起 MAVROS(tcp 5760) → **FCU 就绪门禁 v2**（`fcu_ready.py`：双端口探活 5762/5760 + 心跳连续 30s 稳定窗 + **GPS fix≥3D 校验**——心跳流≠耦合健康；GPS 卡 0 自动重启 gz 自愈，最多 4 次，一般 1~5min 过）→ set_message_interval ×7（message_id 1/30/32/33/74/147/245 @10Hz）→ 启动状态机（auto_arm_on_guided + m1_no_vision_mode + mission_params.yaml）→ **外部切 GUIDED 作放行扳机**（状态机不自己切模式 = 飞手确认语义，比赛时由遥控器做，脚本等价）→ 每 15s 快照 /cuadc/mission_state，DONE/节点退出即提前收尾 → 清理 + 轨迹统计报告。

### 5.3 飞行冒烟（30 秒级 sanity check）

```bash
python3 ~/sim_scripts/fly.py tcp:127.0.0.1:5760
```

参数自检 → 请求数据流 → GUIDED → 解锁 → 起飞 8m → 降落 → `RESULT: FLIGHT_OK`。**改了机架/耦合参数后先跑它，再跑全任务。**

### 5.4 常用变体

| 想干什么 | 命令 |
|---|---|
| 限时干跑（不解锁，验证链路） | `bash ~/sim_scripts/fc_sitl_dryrun.sh 120` |
| 栈活着时直接重飞 | 直接跑 ③（飞机已落地/上锁即可） |
| 全部推倒重来 | ① 后重跑 ②③ |
| 中途停止 | Ctrl-C（自动清理，飞机留空中可 reset） |
| 重新随机布设场地 | 本机：`python scripts/generate_scene.py`（改 seed 换布局） |

### 5.5 三条铁律

1. **顺序**：先 SITL 后 gz server（ArduPilotPlugin 连接超时假定 SITL 已起）——reset_sim 已封装，手动起别颠倒；
2. **5760 独占**：MAVROS 与 fly.py 勿并行；泄漏的客户端会自动重连抢槽 → 下次任务全程 `mode:''`（09-12 实锤）——reset_sim 已顺带清泄漏，任务脚本起跑前还自检；
3. **GUI 随挂随拆**：GUI 只是旁观客户端，崩溃不影响仿真本体；跨机 GUI 不可行（Harmonic 8 vs Jetty 10 transport 不互通），远程看画面走 VNC 或 MP TCP 5760 看 HUD（与 MAVROS 错峰）。

### 5.6 仿真坑速查（完整表见 06 坑清单 §9）

| 症状 | 原因 → 处置 |
|---|---|
| 任务全程 `armed:false mode:''` 空转 | ① 启动不稳定窗（mavros.log 见 Accels inconsistent / TM: Time jump，分钟级自愈）② 5760 被泄漏抢占 → 双门禁自动拦；手动跑先 `python3 ~/sim_scripts/fcu_ready.py`；**勿反复 reset**（每次 reset 重新进窗） |
| ardu.log 停在 "Waiting for connection" | 假信号：那是 SERIAL0 等 TCP 客户端（AP_HAL_SITL/UARTDriver 打的），与 Gazebo 握手无关；判联机一律 `fcu_ready.py --window 10` |
| `gz sim -g` 报 EGL 警告没窗口 | 首挂初始化偶发失败 → 原样重跑一次 |
| fly.py 卡 "no heartbeat" | 用了 14550 但没 MAVProxy → 加 `tcp:127.0.0.1:5760`；或 5760 被 MAVROS 占用 |
| fly.py "no GPS fix" | 裸 SITL 只发心跳 → fly.py 已内置 REQUEST_DATA_STREAM |
| 起飞后一直爬升不停 | 起飞高度被当 ABOVE-HOME（误传 AMSL+8）→ 已修；新脚本 CommandTOL param7 直接给相对家点高度 |
| `gz topic -e` 无输出（Windows 本机） | conda-forge 包 CLI 消息收发全废（已知问题），验证走 GUI + 话题列表 |
| 世界加载后模型全缺席 | `GZ_SIM_RESOURCE_PATH` 尾部留了空分号 → 条件追加（bat 已修）；探针 `gz topic -l \| grep d435i` |
| 仿真"穿地自由落体" | 场地模型无碰撞体 → 飞行 world 内联碰撞地面（jetson/cuadc_rescue_flight.sdf 已修） |

## 7. 比赛规则要点与上场操作

### 7.1 得分模型

| 项 | 满分 | 说明 |
|---|---|---|
| 起飞分 | 50 | 带两瓶水飞越起飞线即可 |
| 空投分 | **800** | 两瓶分别投中 1 号筒(500) + 2 号筒(300)；投同一 A 区只算一次 |
| 侦察分 | 300 | 3 个标识全对；**错一个 −100，不填不扣** |
| 着陆分 | 50 | 螺旋桨停转 + 轴心投影落 ø80cm 圆内 |
| 时间分 | 200 | `200×(300−T)/300`，只有**完赛**才有 |

- 理论上限 ≈**1400**；T=150s 高分线 1250~1300（冲奖目标 1250+）；
- **完赛硬门槛**（缺一项时间分归零）：起飞 + 空投分 ≠0 + 侦察至少对 1 个 + 着陆成功 + 停表前交成绩单；
- → **侦察不是加分项，是通行证；宁可空着不能错填**（拒识策略存在的理由）；
- 分档：保底 ~330（一瓶 B 区 + 侦察对 1 + 落回）｜及格 ~600（一瓶 A 区 + 侦察对 2）｜冲奖 1250+（1 号筒 + 2 号筒 + 全对）；
- **1300 与 900 的差距就是 15cm 小桶**（HIT 区赛最高 1328/73s，稳定 900+ 卡在小桶）——冲奖前提是投放标定 CEP<5cm 做实。

### 7.3 上场 1 分钟流程（全程 ≤60s，不敲命令）

**提前做**：Jetson 预加载模型 → 黑帧推理自检/预热（TensorRT 首帧秒级初始化）→ suspend；电池充满（>22.5V，刚触发严重保护落地的强制换电）；舵机两路地面动作测试 + 装瓶。

**上场 60 秒**：

```
放机 → 装瓶 → 按计时器 → 开机唤醒 → 报备图传电源（如用）→
当裁判演示总开关断电/复位（5.7）→ 飞手待命 → 切 GUIDED（程序启动的最终确认）→ 手动解锁
```

### 7.5 故障处置预案（原则：程序退让，人工只做紧急停止）

| 情形 | 动作 |
|---|---|
| 程序行为异常 | 飞手切出 GUIDED → 状态机立即 PILOT_OVERRIDE 停发退让 → 人工接管（Stabilize/AltHold） |
| 飞行中紧急停止 | SWC 拨 CH6 高位 → 电机停转锁死；复位 = 拨回低位 + 重新解锁 |
| 一切失控 | 反火花总开关（飞控日志完整保留，利于复盘） |
| 低电 | 自动的：21.6V RTL / 21.0V Land |
| 断数传 | FS_GCS_ENABLE=0 不动作，机载自主兜底 |

## 9. 自查题

1. 刷机后怎么确认固件版本没刷错？（心跳 MAV_TYPE_QUADROTOR + flight_custom_version=dbe79216 与存档一致）
2. 参数导入后 verify_params 报 5 项"不存在"，是丢参数吗？（懒加载反向：TYPE=0 时子参数从表里消失，预期行为）
3. 解锁门槛为什么是 22.5V 不是 24.5 也不是 21.8？（24.5 只有近满电能解锁；21.8 解锁后带载即跌入低电区）
4. 电机测试"顺时针绕圈"点亮是接线错吗？（不是——DO_MOTOR_TEST param1 是测试序列号，脚本已换算）
5. ESC 校准后飞控卡死怎么办？（断电复位一招清，不是坏件）
6. 桌面能把 GUIDED 任务模式解锁跑起来吗？（不能——强制层 Need Position Estimate，等 GPS 户外出星）
7. 地面站连上但 HUD 全空，最可能的两个原因？（机载版没插 TELEM1/天线没装；或波特率不是 57600）
