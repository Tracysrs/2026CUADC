## 1. 任务规格（规则原文 → 感知指标）

### 1.1 白筒检测（细则 3.1.2）
投放区 8×5m，3 个白色圆筒高 30cm、筒口直径 **15/20/25cm**，位置随机且**禁止赛前
预标定**（细则 7.3.2）→ 只能机上实时检测。感知指标：

- 搜索高度 2.0m（4.2m 检不出桶——HIT 实测）下三筒全检出率 ≥95%（独立现场验证集）；
- 筒口直径反算误差：对号容差 ±0.035m 内命中 {0.15, 0.20, 0.25}；
- 稳态 ≥25FPS（Jetson 实测线），位置抖动由消费端 EMA/中位窗消化。

### 1.2 危化判读（细则 3.1.3）
侦察区 5 筒中 3 筒内 12×12cm 标识，附件11 十类；拒识留空 0 分、错填 −100 →
**留空是合法答案**。已在生产（mAP50=0.963；刺激性 0.853 / 放射性 0.858 待 v3 补数）。

### 1.3 H 圆检测（细则 3.1.1）
起降区 ø80cm 圆 + H 标识，固定位置但**每次进场的降落偏差是随机的** → 视觉闭环才有
着陆 50 分的把握。指标：≥10Hz 连续有效目标；漏检时普通降落兜底（fail-safe）。

## 3. 公共基座设计

### 3.1 相机内参（新增关键件）
- **现状缺口**：真机从未标定，此前沿用仿真 hfov=1.5rad 推 fx；
- **datasheet 推导（1080p 16:9 裁剪）**：H FOV 81.8° → fx≈1108；V FOV 66° → fy≈831
  （4:3 全幅方像素 fx≈fy≈1500，裁剪后各向异性——**16:9 下必须 H/V 两角分开算，
  方像素假设会让 fy 高估 34%**）；
- **棋盘格标定**（`scripts/calibrate_camera.py calibrate`）：9x6 内角点、方格 25mm、
  15~25 张姿态多样 → fx/fy/cx/cy/畸变 + RMS；RMS>1.0px 打回重拍；产出
  `camera_calib.yaml`（含 image_width/height，供节点加载与分辨率不一致时等比缩放）；
- **已知尺寸快检**（`calibrate_camera.py check`）：已知直径白圆 @已知高度 →
  fx 反算，与标定/推导值交叉核对（偏差 >5% 复查）；
- **正交性校验**（工程五件套之三）：fx/fy 比 ∈[0.5,2]、c/cy 中心带 [0.3w,0.7w]、
  k1 量级，异常抛 `CalibrationError` **阻断启动**；无标定文件时 datasheet 兜底 +
  显式告警，比赛模式 `allow_uncalibrated: false` 强制已标定。

### 3.2 坐标与装订约定
- 机体 FLU（x 前 y 左 z 上）；图像映射默认**"图像上=机头、图像左=机体左"**，
  装订旋转参数 `mount_rot_deg` 覆盖 90/180/270 安装——**首次悬停"偏置目标"实验
  标定一次，两个节点共用**；
- LANDING_TARGET 用 FRD（y、z 取反）——`flu_to_frd`，坐标系陷阱单点收口；
- 高度只用飞控相对高度（TFmini 4m 以下辅助），气压 2~5m 桨风 ±0.5m 跳变不可用。

### 3.3 单目解算（对 SSOT §4.2 的一处明确修正）
- **主用 odom 高度**：`h_m = odom_z − ground_z − plane_z`；桶口平面 plane_z=0.30m，
  H 圆贴地 plane_z=0。`x = (u−cx)·h/fx`（按装订旋转先转 du/dv），`z = −h_m`；
- SSOT §4.2 的 `Z = f·H/h_px`（H=筒高）在正下视**画面中心区域无定义**（看不到筒
  侧壁），只在边缘斜视角可用——降级为 sanity，不作为主测距；
- 直径：椭圆两轴**分别**按 fx/fy 折算再平均（16:9 各向异性下 fy≠fx，均值近似
  是为保持与单焦距公式的量级一致）；
- 感知端同样需要取帧时刻的 odom 高度 → 内置 P0.4 同款插值夹逼（延迟 1.5s /
  未来戳 0.05s / 断流 gap 0.2s / 历史窗 3s，违反即本帧发空检测，绝不外推）。

### 3.4 时间戳与契约（不变，v1.3 仅增补）
- `header.stamp` = **取帧时刻**（相机驱动回调瞬间），空帧照发、≥25Hz、best_effort、
  心跳与检测同节奏、停发 = fail-closed（契约 v1.3 §1/§2 原文有效）；
- v1.3 新增：`/perception/heartbeat_land`（H 圆节点心跳）+ §4 LANDING_TARGET 流
  语义（质量门控不过不发目标）。桶检测字段/哨兵**不变**。

## 4. 白筒感知（M2 核心）——`bucket_perception_node`

### 4.1 双通道
| 通道 | 实现 | 定位 |
|---|---|---|
| 主 | YOLOv8n-**seg** 单类 barrel，TRT FP16 imgsz=640；`masks.xyn` 多边形 → 全分辨率 fitEllipse | 常规通道，模型待训 |
| 副 | LAB：`L > max(l_min, 帧中位数+l_offset)` 且 \|A−128\|、\|B−128\| < ab_max → 开闭运算 → fitEllipse | 光照异常兜底，仿真已验证（09-12 标定 diam_comp=1.15） |

- 蓝地有效性：白桶 L 高且色度中性，蓝地 B 通道远离中性被天然排除；
- **分级上线**：engine 文件缺失 / SHA 不符 / 加载失败 → 自动降级 LAB-only
  （置信打 0.7 折），节点照常满足契约——数据缺口不阻塞真机链路先行；
- **融合**（`fuse_channels`）：IoU≥0.5 匹配，几何取主通道，置信
  `min(0.98, 0.55·main + 0.45·aux + 0.10)`（双独立证据一致给奖励）；单主 ×0.90、
  单副 ×0.70。权重全部参数化，实拍后可调。

### 4.2 后处理四件（SSOT §4.1，两处有意细化）
1. **同帧去重**：中心距 <2cm 合并（置信加权直径）——HIT"同桶拆两目标"；
2. **独立性门控**：感知端用**保守 AND 版**（距离 <0.20m **且**直径差 <0.025m 才
   判同筒）——消费端 BucketMap 用强 OR 版做终审；感知端在源头多合并会误杀真筒
   且无从恢复，两端不对称是设计使然（对应 SSOT"判据必须真正生效"的三号坑）；
3. **直径物理先验**：反算直径 ∈[0.08,0.35]m，并对号 {0.15,0.20,0.25}±0.035
   （**容差内取最近**，0.18m 归 0.20 不归 0.15；对不上号照发、类号置空）——
   0.8m 起飞坪大白块与标线反光在源头被拒，拒绝原因计数入日志；
4. **时序平滑**：滑窗 5 帧中位数 + 贪心最近邻关联（门 0.25m），窗内抖动 std 折入
   置信度。**只平滑不确认**——连续帧确认/EMA/排名稳定/拉黑全在消费端 BucketMap，
   两端都确认会叠出 10 帧（333ms）无谓延迟（对 SSOT §4.1"感知端 5 帧确认"措辞的
   有意细化：确认权唯一化）。

### 4.3 性能预算（Orin Nano，待上机实测确认）
| 项 | 预算 |
|---|---|
| JPEG 解码（1080p，libjpeg-turbo） | ~10ms |
| LAB 通道（cvtColor+阈值+形态学+椭圆） | ~8ms |
| TRT seg 推理（FP16 640） | 2~5ms |
| 后处理 + 发布 | ~2ms |
| **合计** | <25ms → ≥30fps，验收线 25FPS |

三消费者同框预算：recon（65ms/帧，仅侦察态满载）+ bucket（~20ms）+ h_circle
（~15ms）≈ 2 个 A78 核，`active_states` 参数可把桶/H 圆节点限在相关状态进一步省
CPU（非激活态仍发空检测+心跳保契约）；**上机前置项：nvpmodel MAXN + jetson_clocks
锁定（当前无任何功耗模式记录）**。

## 5. H 圆感知与精准降落（M4 提前实现）——`h_circle_node`

### 5.1 检测
- 后端参数 `backend: yolo | hough | both`（默认 both；engine 不可用自动 hough）：
  - **Hough 兜底通道**：半径窗由高度动态推算 `r = 0.40m·fx/h`（±35%），Canny+
    累加器阈值 (120, 40)，**H 图案验证打分**（Otsu 少数派掩码 → 左右竖带能量
    对称性 × 存在性门，白底黑 H 制式——采集卡即按此定案）过滤假圆；
  - **YOLO 主通道**：单类 h_marker det（数据 ~200 张待采；helipad 公开集可做
    预训初值），xywh → 椭圆候选；
  - both 时 IoU 融合（主几何、副兜底，同桶节点语义）。

### 5.2 质量门控（不过**不发**目标）
1. 直径-高度一致性：反算直径 ∈ 0.80±0.25m（Hough 半径窗已隐含，YOLO 框必须复检）；
2. 连续帧确认 ≥3 帧才首发；丢失即清零——防单帧误检直接驱动 PLND；
3. 心跳照发（节点活性），目标质量另按门控走——PLND 无目标 = 自然普通降落，
   **fail-safe 天然成立**（PLND_STRICT 保持 0：无目标不拒降，保命优先于 50 分）。

### 5.3 LANDING_TARGET 发布与飞控侧
- `mavros_msgs/LandingTarget` → `/mavros/landing_target/set`，≥10Hz（30fps 帧率
  下限 20Hz 节流）；字段：`frame=BODY_FRD(12)`（与 BODY_NED 轴序相同，参数可切）、
  `angle_x/y = atan2(横/前偏移, 高度)`、`distance`、`position(x右 y下 z下)`、
  `size = 直径`、`type=VISION_FIDUCIAL`；非核心字段 hasattr 防御（MAVROS 版本差异）；
- 飞控参数（**勘误后口径**）：`PLND_ENABLED=1`、`PLND_TYPE=1`（**1=CompanionComputer
  MAVLink**；0=Never、2=IRLOCK——04_算法模块 §11 旧文把 0/1 含义写反，已同步勘误）；
- mission_node LAND 态**零改动**：`/mavros/cmd/land` → LAND 模式 → PLND 检测到
  有效目标自动接管横偏修正；SSOT/04_算法模块旧文的"1.5m 发
  MAV_CMD_NAV_LAND_TARGET"存疑（MAVLink 无此命令，疑为笔误）——主链路 = LAND+
  PLND 接管，待上机对照 ArduPilot 4.7 文档核verify后回填文档；
- 上机待查：apm.launch 是否默认加载 landing_target 插件；`ros2 interface show
  mavros_msgs/msg/LandingTarget` 核对字段。

## 6. 相机标定与装订验证流程（外场操作序）

1. 棋盘格标定（`calibrate` 模式）→ `camera_calib.yaml` 入 `~/cuadc_models/`；
2. 已知尺寸快检（`check` 模式，ø15 筒口 @2m）偏差 <5%；
3. **悬停偏置目标实验**（5 分钟）：悬停 2m，画面中心放一标识，读 `/perception/
   drop_buckets_body` 的 x/y 与真值差 → 确定 `mount_rot_deg`（0/90/180/270 中

5. SITL/实飞对准验证 → `perception_probe.py` 录检测质量。

## 10. 自查题

1. 为什么感知端独立性门控用 AND、消费端用 OR？（源头多合并=误杀真筒无从恢复；
   消费端强判据防"两瓶投一点"，两端不对称各司其职）
2. 为什么时序确认只做一次、且在消费端？（双重确认叠 333ms 延迟；确认/EMA/排名
   本来就是 BucketMap 的职责，感知端只做平滑）
3. `Z=f·H/h_px` 为什么降级？（正下视中心看不到筒侧壁，h_px 无定义；主测距用
   odom 高度，直径先验做一致性校验）
