# 比赛日上场操作流程（自贡航空产业园）

> 本文档是**总流程时间线**，只管"到上场那一刻按什么顺序做什么"。
> 具体操作不在此重复：
> - 上电解锁检查 → 《[现场操作_上电到遥控手动飞行实施步骤.md](现场操作_上电到遥控手动飞行实施步骤.md)》（下称《清单》）
> - 命令调用 → `02_飞控与硬件/调试工具/ops.py`（`python ops.py` 看菜单）
> - 场地地理数据 → `site_geo_check.py`（CONFIG 区）
> - 安全铁律 → 总体方案与执行计划.md（SSOT）§7

---

## 0. 角色分工（建议三人）

| 角色 | 职责 |
|---|---|
| 飞手 | 解锁/接管/降落；全程手指不离模式开关；**切走 GUIDED 即人工接管（SSOT 铁律）** |
| 地面站操作员 | Mission Planner / ops.py 命令、PreArm 报错判读、模式与状态监控、**念报 MP 消息栏「侦察V…」判读行**（04 册 §2.4，填单员照行抄写，宁空勿错） |
| 机务 | 电池轮换、装拆桨、Jetson 链路（dryrun/日志）、计时员 |

## 1. 出发前（家里/酒店，前一晚）

- [ ] SITL 全流程再过一遍（`run_sitl.sh` → `m1_sitl_accept.sh`），确认代码与参数当前可跑
- [ ] Jetson 工作区 pull 到最新、`colcon build` 通过；`fc_dryrun.sh 90` 干跑通过
- [ ] 电池全部充满（满电 25.2V）并编号；备用桨、工具、扎带清点
- [ ] 参数基线备份核对：`python ops.py params-diff ../V6X_ardupilot_params.param`
- [ ] **全套校准出发前做完**（加速度计六面/遥控/电平/ESC；换场地另加罗盘，见 §2.7）+ `ops.py params-export` 留底——**上场 1 分钟窗口内零校准（§5）**
- [ ] 打印《清单》与本流程；确认笔记本 MP、数传、ops.py 都能连

## 2. 到场勘察（落地后第一件事，约 30 分钟）

> **规则已把场地定死（细则 3.1）**：投放区=起降点前 30m（8m 长×5m 宽）、侦察区=投放区前 20m 即距起降点 55m（同尺寸）、起降点=ø80cm H 圆、起飞线在起降点前 2m。
> **`mission_params.yaml` 现值就是按这三条写的**（搜索 X 27.5~32.5 / Y±4，侦察 X 52.5~57.5 / Y±4）——勘察是**核对微调，不是从零测量**，参数一字不改也能对上标准布场。
> **细则 3.1.4：任务区各规定尺寸可能存在误差，以现场实际情况为准**——布场是人工摆的，30m 实际可能是 28.5m；搜索带 X 向窗口只有 5m，整体偏 1.5m 就漏一条带（1.6m 带距）。
> **方位对正比测距更关键**：航线 x 轴=起飞时机头方向，机头偏 5° → 30m 处横移 2.6m，±4m 横向覆盖直接偏出投放区——目测摆正很难稳在 5° 内，这一项是勘察里最值钱的一步。

- [ ] 2.1 安全评估：风速（**阵风 >8 m/s 暂停放飞**）、人群隔离区、周边障碍、GNSS 天空视野
- [ ] 2.2 **方位对正（免费且必须，没有卷尺也要做）**：定出场地中轴（起降点→投放区→侦察区连线），装机时**机头沿中轴对准搜索区方向**——借地面标线/H 圆边线/贴胶带拉直线，不要纯目测。**坐标系约定：原点=起飞点，x 朝起飞时机头方向**（route_logic 用罗盘换算），此步做正它才成立
- [ ] 2.3 跑 `python ops.py geo` 就地测试：GPS/罗盘/EKF 正常后，**`python ops.py geo here`** 把实测坐标粘贴进 `site_geo_check.py` CONFIG 区（覆盖自贡占位值）；严禁用高德 GCJ-02 坐标
- [ ] 2.4 核对场地几何（有卷尺 5 分钟；没有就 GPS 测距/数步）：
  - 起飞点→投放区近边规则值 **27.5m**（远边 32.5）；→侦察区近边 **52.5m**（远边 57.5）；横向半宽规则值 4m；对照实际
  - **偏差 ≤1m：参数不动**（规则值可信，别引入手测误差）；**偏差 >1m：** 改 `mission_params.yaml` 场地几何段 `search_x_min/max_m`、`search_half_width_m`、`recon_x_m`、`recon_half_width_m`、`recon_lanes`
  - 高度/速度参数不动，除非规则有变
- [ ] 2.5 布局方向目检：对照规则图 1/图 2——H 点位置、起飞线朝向、投放区→侦察区是否同轴前进方向，防"横着搜"
- [ ] 2.6 与裁判确认：任务时长（5 分钟 → `mission_timeout_s=240` 是否要改）、判分口径、投放顺序
- [ ] 2.7 **现场罗盘校准（当天一次，装机不再变动后做）**：放在勘察时段完成；此后每次上电窗口内禁止再校准（口径见 §5），一致性报警先挪干扰源、不拉校准

## 3. 架设（约 30 分钟）

- [ ] 3.1 摊垫布摆装备：机身、桨叶检查（裂纹/缺口）、工具定位
- [ ] 3.2 Jetson 上电 → `python ops.py dryrun 90`（无桨）：mavros 连接 + STATUSTEXT 无 PreArm 报错 + 状态机正常推进 → **链路证明通过**
- [ ] 3.3 数传链路：笔记本连 COM 口 → `python ops.py radio` 诊断（只读；注意严禁 ATI5）
- [ ] 3.4 装桨（按《清单》阶段 3：先拔电池、旋向对应）；机身**机头朝场地前进方向**摆放
- [ ] 3.5 轮次电池编号上架，充电宝/备用电池就位

## 4. 每轮次飞行前（轮到上场前 15 分钟）

按《清单》走，不跳步：

- [ ] 4.1 《清单》阶段 1：装电源上电（先遥控器后电池）
- [ ] 4.2 《清单》阶段 2：门禁七项（GPS ≥8星/HDOP<1.5、EKF、模式、RC、失控保护、安全开关、参数）
- [ ] 4.3 《清单》阶段 2B 地面解锁测试（**仅当该机当日未飞过/动过线才重做**）
- [ ] 4.4 首轮或换了新场地后：先做一次《清单》阶段 4 手动三段验证（Stabilize/AltHold/Loiter），确认场地无干扰再进任务模式

## 5. 校准纪律与上场 1 分钟并行时间线

> **核心口径：校准全是"一次性和存参"，1 分钟窗口（细则 5.7：进准备区→上电→演示安全开关→检查完毕→举手"准备完毕"）内零校准、零敲命令。** 每次上电都被迫校准 = 流程有偏差，不是常态——陀螺零偏和 EKF 对齐本来就是上电自动做的，其余校准项目掉电不丢、只需一次。

**校准时机表（哪些动作不许出现在窗口里）**：

| 动作 | 性质 | 何时做 |
|---|---|---|
| 陀螺零偏、EKF 对齐 | 上电自动（静止数秒，别碰机身） | 无需操作 |
| GPS 搜星 | 自动 | 热启动秒级（X20P 实测 4s 3D fix）；冷启动分钟级 → **当天早开机一次存星历**，之后都是热启动 |
| 加速度计六面/遥控/电平/ESC | 一次性存参，掉电不丢 | 出发前全套做完 + `ops.py params-export` 留底；摔机/刷机/换件才重做 |
| 罗盘校准 | 一次性存参 | 换场地**勘察时段做一次**（§2.7）；装机大改（电机/线束）后重做 |
| 罗盘一致性报警 | 多为布置/干扰 | **先挪干扰源**（电池/大电流线/金属件/模块贴身），不拉校准（09-24 案例：桌面 162mG 超差=布置干扰，未复现） |

**60s 并行时间线（全员实测口径，满打满算 ≤30s 可举手）**：

| t | 飞控侧 | Jetson 侧（并行） | 人 |
|---|---|---|---|
| 0s | 上电，放平不动 | suspend→开机唤醒 | 摆正机头（§2.2 口径） |
| ~5s | GPS 热启动 3D fix（4s 实测） | systemd 就绪 9s（实测） | 向裁判演示安全开关 |
| ~15s | EKF 对齐、prearm 全绿 | 唤醒到首帧 <10s（黑帧已预热） | `prearm_diag` 快检口头过 |
| ≤30s | 就绪 | 就绪 | **举手"准备完毕"** |

比赛时间开始后（细则 5.8）：放至起降点 → 装瓶 → 按计时器 → 起飞（自动流程见 §6）。

**纪律**：窗口内报错按《清单》附录 A 速查**根因**（多数是挪位/等待可解）；真修不好的当场弃轮保安全，赛后修流程——校准只能堵在勘察和出发前，绝不上场补。

## 6. 任务轮次执行（GUIDED 状态机，比赛 5 分钟）

> 前置：`mission_params.yaml` 里 `m1_no_vision_mode: false`（正式飞行）、`sim_release_bridge: false`、
> `enable_release_output: true`（实弹）。起飞前让机务口头复述这 3 项。

**Jetson 端（赛前一次启动，多轮复用）：**

```
# 链路（同 fc_dryrun 的 [1] 步，若 dryrun 进程还在可直接复用）：
ros2 launch mavros apm.launch fcu_url:=/dev/cuadc-fc:115200 gcs_url:=tcp-l://0.0.0.0:14550 &
nohup python3 ~/gcs_pump.py &
# 正式任务节点（参数按 2.4 修订后的 yaml）：
ros2 launch cuadc_mission mission.launch.py
```

**每轮时序：**

| 时刻 | 动作 | 责任人 |
|---|---|---|
| T-3min | 上电 → 《清单》阶段 1/2 快检 → 地面站确认 state=STANDBY、odom 视觉起飞门禁 ≥3 帧 | 全员 |
| T-0 | 地面站切 **GUIDED**（`fc_dryrun` [4] 同款 set_mode）→ 飞手**手动解锁**（`auto_arm_on_guided: false`） | 操作员+飞手 |
| 起飞 | 自动 CommandTOL 起飞至 4m → SEARCH 沉降期 8s → 弓字形搜索 | 监控 `/cuadc/mission_state` |
| 中段 | 锁定 3 筒 → ALIGN 对准 → RELEASE 投放 ×2 → 侦察段 6 航点拍照（MP 消息栏出「侦察V…」判读行，照行填单；留空(混淆)=留空+人眼 FPV） | 机务盯电池电压 |
| 返航 | RTL 3m → 落地确认（≤0.3m + 稳定 1.5s）→ 自动 DISARM | 飞手随时准备接管 |
| 异常 | **任何不对劲：飞手立即切走 GUIDED 人工接管**（节点自动退让停发目标）；低压立即就近降落 | 飞手 |
| T+落定 | 拔电池 → `python ops.py log list` 记下日志名，轮次间隙再 `log get` | 机务 |

## 7. 轮次之间（复盘 5 分钟）

- [ ] 拉/看日志：状态机轨迹、STATUSTEXT 报错、投放时刻位置
- [ ] 复核：投放是否判中（问裁判/看落点）、视觉锁定帧数、电池用掉多少
- [ ] 下一轮只换电池 + 快检（4.1~4.2），**没动过的东西不要重新配置**

## 8. 撤场

- [ ] 电池放电至存放电压（~22.8V）或装入防爆袋
- [ ] 拉全部 dataflash 日志归档（`python ops.py log get x.BIN`）
- [ ] 参数再导出一份 `params-export` 存 02_飞控与硬件/参数备份/（标注场地与日期）
- [ ] `site_geo_check.py` 修订后的场地坐标提交 git，写工作日志
