## 1. 组件架构（定案）

```
Windows（SSH 远程）
   ▼
Jetson
 ├─ arducopter SITL（裸起，eeprom 每轮重置）──JSON 9002/9003──► gz server（无头）
 │        │                                        （物理+ArduPilotPlugin+飞行world）
 │        └─ tcp 5760 ◄── MAVROS ◄── cuadc_mission 状态机（auto_arm_on_guided）
 ├─ gz GUI（gz sim -g，独立进程挂到活 server）──► :0 显示器
 └─ fly.py（30 秒级起飞冒烟，直连 tcp 5760，不依赖 MAVProxy）
```

- **MAVProxy 层全部砍掉**：只当转发器还挑链接状态，裸跑 SITL（`arducopter` 二进制 + `--defaults` 参数链）反而稳定；MAVROS fcu_url 用 `tcp://127.0.0.1:5760`（MAVROS2 不认 udpin://）；
- 裸 SITL 只发心跳 → 一切消费端必须自己要数据流（MAVROS 走 set_message_interval，pymavlink 走 REQUEST_DATA_STREAM）；
- 端口地图：9002/9003 = 飞控↔Gazebo JSON；5760 = SERIAL0 MAVLink（**单客户端**）；5762/5763 = SERIAL1/2 第二三出口（探活/旁听用）。

## 3. 标准流程（四步，模式可选）

```bash
ssh jetson
python3 ~/sim_scripts/randomize_scene.py  # ⓪ 可选：随机布景（真值+判分自动联动；只重启 gz 不动 SITL；
                                          #    加 --seed N 固定布局）
bash ~/sim_scripts/reset_sim.sh           # ① 重置全栈（~30s）
bash ~/sim_scripts/start_gzgui.sh         # ② 挂画面（可选，可重复执行重挂；右键 iris → Follow 跟机）
python3 ~/sim_scripts/fcu_ready.py        # ③ 就绪门禁 v2：双端口+GPS 3D 校验+耦合僵死自动重启 gz
                                          #    自愈（一般 1~5min 过；打印"FCU 就绪"才继续）
bash ~/sim_scripts/fc_task.sh m3          # ④ 跑任务到 DONE 并输出"完成事项"（模式见下表）
```

**任务模式**（fc_task.sh 第一参数，缺省 m3）：

| 参数 | 底层脚本 | 感知 | 预期 |
|---|---|---|---|
| `mission`（m1） | fc_sitl_mission.sh | 无（演练） | 飞完整链 DONE，投放 0/2 属预期 |
| `m3` | fc_sitl_m3.sh | 场景真值替身 | 投放 2/2 A 区（判分 400），125~142s |
| `m2` | fc_sitl_m2.sh | CV 相机真感知 | 视觉在环验收（gz 渲染世界须在跑） |

成功判据（reset_sim 末行）：`ardu=1 gz=1 p9002=1 l5760=1 c5760=0`（p9002=耦合口，l5760=MAVLink 监听，c5760 非 0 = 有泄漏进程抢槽）。
**验收门**：状态轨迹 `WAIT_FCU→…→TAKEOFF→SEARCH→RECON_SURVEY→RETURN_HOME→LAND→DISARM→DONE`；任务结束自动输出"**完成事项**"（各段耗时/投放明细误差与分区/拍照确认/总时长/判分累计）。

## 4. 任务脚本内部步骤（理解用，排障对号）

[0] **强清残留**（僵尸任务节点会共享 mavros 发 disarm 把新任务在空中打下来，09-13 实证）→ 自检 5760 未被占（命中即 ABORT）→ 起 MAVROS(tcp 5760) → **FCU 就绪门禁 v2** → set_message_interval ×7（message_id 1/30/32/33/74/147/245 @10Hz）→ 启动状态机 → **外部切 GUIDED 作放行扳机**（状态机不自己切模式 = 飞手确认语义，比赛时由遥控器做）→ 每 15s 快照 /cuadc/mission_state → DONE 提前收尾 → 清理 + 轨迹统计报告。

## 5. 飞行冒烟（30 秒级 sanity check）

```bash
python3 ~/sim_scripts/fly.py tcp:127.0.0.1:5760
```

参数自检 → 请求数据流 → GUIDED → 解锁 → 起飞 8m → 降落 → `RESULT: FLIGHT_OK`。**改了机架/耦合参数后先跑它，再跑全任务。**

## 7. 三条铁律

1. **顺序**：先 SITL 后 gz server（ArduPilotPlugin 连接超时假定 SITL 已起）——reset_sim 已封装，手动起别颠倒；
2. **5760 独占**：MAVROS 与 fly.py 勿并行；泄漏的客户端会自动重连抢槽 → 下次任务全程 `mode:''`——reset_sim 已顺带清泄漏，任务脚本起跑前还自检；
3. **GUI 随挂随拆**：GUI 崩溃不影响仿真本体；跨机 GUI 不可行（Harmonic 8 vs Jetty 10 transport 不互通），远程看画面走 VNC 或 MP TCP 5760 看 HUD。

## 8. 脚本逐段讲解（关键段）

**reset_sim.sh——全栈重置**（关键三段）：

```bash
# [杀] 泄漏的 mavros/任务节点/fly.py 也必须清：泄漏的 mavros 会自动重连并抢走
# SERIAL0(5760) 单客户端槽，下一次任务的 mavros 就会永远 mode:''
pkill -9 -f "mavros"; pkill -9 -f "cuadc_mission"; pkill -9 -f "fly.py"

# [起 SITL] 三个关键参数：
#   rm -f eeprom.bin           → 每轮参数确定性
#   sleep infinity | stdbuf -oL arducopter →
#     stdin keeper：SITL 控制台读 stdin，ssh 断开 EOF 会静默退出（"幽灵死亡"真凶）
#     stdbuf 行缓冲：默认块缓冲让 ardu.log 滞后几分钟，tail 全是假象
setsid bash -c "sleep infinity | stdbuf -oL '$BIN' --model JSON --speedup 1 ... \
  --defaults 'copter.parm,gazebo-iris.parm,sr0.parm' > /tmp/ardu.log 2>&1" &

# [起 GZ] </dev/null 断开 stdin 继承，否则 ssh 跑完不退
nohup gz sim -s -r -v2 cuadc_rescue_flight.sdf > /tmp/gz_sim.log 2>&1 < /dev/null &

# [自检] c5760 非 0 = 5760 已被泄漏占用（抢槽前兆）
echo "ardu=$(pgrep -c arducopter) gz=... p9002=... l5760=... c5760=$(ss -tnp | grep -c ':5760')"
```

**fcu_ready.py——FCU 就绪门禁 v2**：三层判据——①**双端口探活**（5762 优先，5760 空闲即用；5762 监听在多次连接后会消失，双端口免疫）；②心跳稳定窗（连续 --window 秒不断档，--gap 断档重新计窗）；③**GPS fix≥3D 校验**——长时间空转后耦合会僵死（心跳/姿态照常流但 GPS 卡 0，只探心跳会误放行）。**自动自愈**（默认开）：GPS 卡 0 超 60s 且 SITL 在跑 → 自动重启 gz 服务端重握手（SITL 不动）最多 4 次，一般 1~5min 就绪；`--no-heal` 可关。

**fc_sitl_m3.sh——M3 判分闭环**：在七步之上多起 `virtual_drop_judge_node`（桶真值参数化，target_bucket_id 空按最近桶判 A/B 区）+ `scene_truth_perception_node`（真值感知替身：读 generated_scene.yaml + odom 反变换 + 可见性门控 → 契约 PoseArray）；任务节点 `m1_no_vision_mode:=false -p sim_release_bridge:=true` → 投放时同步调 `/drop_controller/release` 判分。⚠️ **换 seed 重新布景后 judge 真值参数需同步**（randomize_scene.py 已联动；手工 generate_scene 时要手动抄）。

**fly.py——三修要点**（防止旧坑复发）：

```python
# 修 1：直连 + 数据流请求——裸 SITL 只发心跳，没人要数据就零流
m.mav.request_data_stream_send(..., MAV_DATA_STREAM_ALL, 10, 1)
# 修 2：起飞高度按 ABOVE-HOME 传——CommandTOL param7 直接给相对家点高度（勿传 AMSL+8）
m.mav.command_long_send(..., MAV_CMD_NAV_TAKEOFF, 0, 0,0,0,0, 0,0, 8.0)
# 修 3：落地判定用 90s 时间窗轮询（recv_match 一次迭代只吃一条消息，按循环次数限会提前耗尽）；
#   FLIGHT_OK 判据 = max_rel 在 5~20 之间 且 landed；只在确认落地后才发 disarm
```

## 9. ZD550 机架适配（已完成，改参数时对照）

iris（1.5kg）→ ZD550（8kg）改两份 model.sdf：

| 参数 | 原 (Iris) | 新 | 依据 |
|---|---|---|---|
| 整机质量 | 1.75 kg | 8.00 kg（base 7.75） | 实机 ~8kg 级 |
| 惯量 base | 0.008/0.015/0.017 | 0.061/0.114/0.129 | 质量×轴距比例放大 |
| 惯量 桨 | 9.75e-6/1.667e-4 | 1.735e-5/2.97e-4 | 随桨径² ×1.78 |
| LiftDrag area/cp | 0.002 / ±0.084 | 0.00356 / ±0.112 | 桨径 1.334 倍缩放 |
| multiplier | ±838 | ±656（6264 rpm） | 满油门单桨 29.5 N，T/W=1.50 |
| cmd_max | ±2.5 | ±4.0 | 满转速阻力矩 2.65 N·m，原值会饱和 |

- ⚠️ **cmd_max 饱和是隐形坑**：稳态力矩超上限时静默转不到目标转速（转速差 -4% → 推力差 -8%），必须先算阻力矩再定上限；
- 电机位按 CAD 实测 ±0.2196m（⚠️ 与标称 550 轴距推算的 ±0.195 不一致，待实机核对桨保干涉）；mesh 产出固化在 `scripts/make_zd550_meshes.py`；
- **换机架必须按"脚底贴地"重标出生高度**（0.195→0.29 共 5 处），否则出生插地 9.5cm 物理剧烈弹开；出生朝向必须对齐场地延伸方向（"横着搜"90° bug 的守护断言在 route_logic 单测里）；
- 验证：fly.py FLIGHT_OK；悬停 PWM 对比推力模型预测（差 1.7% 正常）；悬停油门 83% 是 T/W≈1.5 重载规格固有结果，不是参数错误；
- ⚠️ 姿态内环（ATC_*）仍是 SITL 通用值——1.5kg 与 8kg 不可互转，贴近实机需按实机整定。

## 11. 排障速查

| 症状 | 原因 → 处置 |
|---|---|
| 任务全程 `armed:false mode:''` 空转 | ① 启动不稳定窗（mavros.log 见 Accels inconsistent / TM: Time jump，分钟级自愈）② 5760 被泄漏抢占 → 双门禁自动拦；手动跑先 `fcu_ready.py`；**勿反复 reset**（每次 reset 重新进窗） |
| ardu.log 停在 "Waiting for connection" | 假信号：那是 SERIAL0 等 TCP 客户端，与 Gazebo 握手无关；判联机一律 `fcu_ready.py --window 10` |
| `gz sim -g` 报 EGL 警告没窗口 | 首挂初始化偶发失败 → 原样重跑一次 |
| fly.py 卡 "no heartbeat" | 用了 14550 但没 MAVProxy → 加 `tcp:127.0.0.1:5760`；或 5760 被 MAVROS 占用 |
| 起飞后一直爬升不停 | 起飞高度被当 ABOVE-HOME（误传 AMSL+8）→ CommandTOL param7 给相对家点高度 |
| `gz topic -e` 无输出（Windows 本机） | conda-forge 包 CLI 消息收发全废（已知问题），验证走 GUI + 话题列表 |
| 世界加载后模型全缺席 | `GZ_SIM_RESOURCE_PATH` 尾部留了空分号 → 条件追加；探针 `gz topic -l \| grep d435i` |
| 仿真"穿地自由落体" | 场地模型无碰撞体 → 飞行 world 内联碰撞地面（jetson/cuadc_rescue_flight.sdf） |
| 门禁长时间 refused | GPS 耦合僵死（心跳照常 GPS 卡 0）→ 门禁 v2 自动重启 gz 自愈；手跑等"FCU 就绪"打印 |
| 节点活着但话题零到达 | SHM 被仿真栈搅乱 → fastrtps UDP-only profile（systemd 已固化） |

更多仿真坑见 [11_错误与经验总结](11_错误与经验总结.md) §11。

## 12. 自查题

1. 裸 SITL 连上但没遥测数据，三步排查？（是否要求数据流 / set_message_interval 订阅 / ROS_LOCALHOST_ONLY）
2. reset_sim 末行 `c5760=2` 说明什么？（5760 被泄漏进程占用，先清场再跑任务）
3. 为什么探活走 5762 不走 5760？（SERIAL0 单客户端，5760 留给 mavros）
4. 改了 model.sdf 的桨参数，怎么验证？（fly.py 冒烟 → 悬停 PWM 对比推力模型预测）
5. 换机架最容易漏的两处？（出生高度 5 处、cmd_max 阻力矩）
6. 状态机"卡"在 WAIT_NAV_STABLE 真机正常吗？（无 GPS 无 odom 流——设计行为；SITL 有仿真 GPS 所以能过）
