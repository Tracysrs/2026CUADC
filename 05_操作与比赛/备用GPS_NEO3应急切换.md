# 备用 GPS 应急切换卡：X20P → NEO-3（现场可用）

> **何时用这张卡**：机上 X20P 流动端无定位（零星/硬件故障），现场又必须飞行时。
> 判定依据见 `ops.py prearm`：报「EKF 无绝对水平位置」且 `ops.py gps` 拿不到 3D Fix。
> **前提自检**：手边有 NEO-3 模块 + 10P 原配线（台架备份件，09-22 拔除的那块）。
>
> **精度口径（先安心）**：NEO-3 是 M9N 单点定位（米级），**无载波相位**——但 SSOT §5.4 现行比赛口径本就是「纯 GPS+视觉」（RTK 过验收门槛前），任务流程不依赖 RTK Fixed，**切换对比赛科目零精度损失**；只丢 RTK 厘米级调试能力。

## 一、物理切换（约 3 分钟）

- [ ] 断电（拔电池）
- [ ] 拆下机上故障 X20P（记录它插的 CAN 座位置，回切时复原）；天线若完好留给基站/备件
- [ ] NEO-3 用 **10P 原配线**接 **GPS1 座**（10P 座带安全开关 I2C；针序见 06 册《02_装机接线.md》§9.2）
- [ ] NEO-3 天线竖直朝天、无遮挡；检查 SMA 拧紧
- [ ] 附带回归：安全开关+蜂鸣器随 NEO-3 回归（`BRD_SAFETY_DEFLT=0` 维持上电不锁，行为不变）

## 二、参数切换（约 5 分钟，两遍+重启红线）

- [ ] 断开 Mission Planner（占 COM 口红线）
- [ ] 导入参数片（自带两遍导入+每遍后重启）：
      `cd 02_飞控与硬件/调试工具 && python load_params.py COM17 ../V6X参数_备用GPS_NEO3.param`
      片内容就两行：`GPS1_TYPE,1`（UART 自动识别 UBX）+ `GPS_AUTO_CONFIG,1`（关闭 DroneCAN 自动配置，改 UART 口径）
- [ ] 片外不动：`CAN_P1_DRIVER/CAN_D1_PROTOCOL` 留着无害；`GPS_AUTO_SWITCH=1` 不动；`SERIAL3` 波特率走默认（AUTO_CONFIG=1 会把 NEO-3 配到口波特率）

## 三、验收（不达标不飞）

- [ ] `python ops.py gps COM17`：**3D Fix + ≥8 星 + HDOP<1.5**（NEO-3 室外开阔地冷启动 1~2 分钟内达标；09-20 同款流程实测过）
- [ ] `python ops.py prearm COM17`：EKF「绝对水平位置」转绿；**罗盘一致性**重点看——NEO-3 的 IST8310 外置罗盘回归后罗盘列表会多一路（现役双板载 RM3100），若报罗盘一致性 ⛔，按 06 册《03_飞控配置与校准.md》重做罗盘校准
- [ ] 地面解锁测试一次过（操作卡《现场操作_上电到遥控手动飞行实施步骤.md》2B 段）
- [ ] 起飞前比赛日检查表照走（08 册）

## 四、回切 X20P（修好后）

- [ ] X20P 装回 CAN 4P 座，NEO-3 拔除（10P 线留 GPS1）
- [ ] 导回切片：`python load_params.py COM17 ../V6X参数_回切X20P_CAN.param`（GPS1_TYPE,9 + GPS_AUTO_CONFIG,2，恢复单RTK 终态四钥匙口径）
- [ ] 同 §三验收；RTK 基站链路另按 04 册 §3 走

## 五、坑与红线

- **两遍导入中间重启不能省**（懒加载参数组红线）
- NEO-3 **不支持 RTK**（M9N 物理限制），别试图接改正链
- 切换期间 GPS_AUTO_SWITCH 保持 1：若故障 X20P 仍插在 CAN 上，它会作为第二路 GPS 空跑（零星无解不干扰），不必专门拔 CAN 线——但建议拔掉防接触不良摇摆
- 导参数前 Mission Planner 必须断开（COM 口红线）
