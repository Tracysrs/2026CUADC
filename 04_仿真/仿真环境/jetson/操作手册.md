## 1. 每次开机的标准流程（六步）

### ① 重置全栈

```bash
bash ~/sim_scripts/reset_sim.sh
```

做什么：杀干净所有残留（SITL/mavros/任务节点/fly.py——**泄漏的 mavros 会抢
SERIAL0 单客户端槽**）→ 全新 eeprom 起 SITL → 无头 Gazebo 起 `cuadc_rescue_flight.sdf`
（带 Sensors 渲染，相机可出图）。
验收：末行自检 `ardu=1 gz=1 p9002=1 l5760=1 c5760=0`（c5760 非 0 = 有泄漏，重跑本脚本）。

### ② 就绪门禁 v2（必做，跳过=任务必败）

```bash
python3 ~/sim_scripts/fcu_ready.py
# 快速确认（栈已稳时）: python3 ~/sim_scripts/fcu_ready.py --window 10 --timeout 60
```

为什么：reset 后有分钟级"启动不稳定窗"（gz→SITL 传感器耦合逐步建立）；且长时间
空转后耦合会**僵死**——心跳/姿态照常流但 GPS 卡 0，旧版门禁只探心跳会误放行，
任务卡死在起飞前。v2 三层判据：

1. **双端口探活**：5762 优先，5760 空闲即用（手动跑门禁时 mavros 未起、5760 空闲
   直连最快；任务脚本内 5760 被 mavros 占用则自动跳过）；
2. **心跳稳定窗**：任意消息连续 30s 不断档；
3. **GPS fix ≥ 3D** 才算真就绪（心跳流 ≠ 耦合健康）。

**自动自愈**（默认开）：GPS 卡 0 超 60s 且 SITL 在跑 → 自动重启 gz 服务端重握手
（SITL 不动、不进长等待），最多 4 次——一般 **1~5 分钟**就绪。

- 打印"**FCU 就绪：稳定窗 + GPS 3D ✓**"→ 继续；
- 自愈 4 次仍失败 → 查 gz 日志 / 重跑 ① reset（此时才是 reset 的正确时机）；
- `--no-heal` 关自愈；`--ports 5762` 强制单口；参数向后兼容，任务脚本无需改动。

### ③ 挂 Gazebo 观察画面（可选，随时可挂/重挂）

```bash
bash ~/sim_scripts/start_gzgui.sh
```

前提：Jetson 接显示器（X 在 :0）或 VNC 进桌面。**右侧操作要点**：
- 模型树右键 `iris_d435i` → **Follow** = 跟机视角（否则飞机飞到 28m 外看不见）；
- GUI 关掉/崩了不影响仿真，重跑本脚本即重挂；
- Windows 上的 Gazebo **不能跨机连**（gz 版本不互通），看画面只能 Jetson 本机或 VNC；
- GUI 占负载 → RTF 略降、任务变慢，属正常，不影响任务逻辑。

### ④ 跑任务（统一入口，模式见 §2）

```bash
bash ~/sim_scripts/fc_task.sh m3        # 或 mission / m2；缺省 m3
```

### ⑤ 看结果

任务脚本结束会自动打印：状态轨迹（去重计数）、仿真投放判分（A/B 区+误差+累计分）、
mission.log 关键行。日志目录在打印的 `=== 完成，日志目录: /tmp/cuadc_sitl_m3_* ===` 里：

```bash
tail -f /tmp/m3*_run.log                        # 实时跟踪最新一轮
grep -aE '目标集冻结|仿真投放判定|任务结束' /tmp/m3*_run.log   # 关键结论
```

### ⑥ 异常兜底

一切不对劲（飞机乱飞/任务卡死/端口异常）→ 回到 ① reset 重来，并接受重新等不稳定窗。

## 2. 三种任务模式（脚本②④步替换）

| `fc_task.sh` 参数 | 底层脚本 | 感知来源 | 用途 | 预期结果 |
|---|---|---|---|---|
| `mission`（m1） | `fc_sitl_mission.sh` | 无（M1 演练） | 纯飞行链路回归：预设航线+侦察+返航 | 状态链 DONE，投放 0/2、拍照 0 属预期 |
| `m3`（默认） | `fc_sitl_m3.sh` | 场景真值替身 | M3 判分闭环基准（真值多轮 2/2 全 A 区实证） | 投放 2/2 A 区，误差 4~8cm，125~142s |
| `m2` | `fc_sitl_m2.sh` | **CV 真感知**（gz 相机→LAB 分割→单目解算） | M2 视觉在环验收 | 终验收进行中，见工作日志 09-13 会话三 |

模式开关本质是任务节点的 `m1_no_vision_mode`（m1=true，m3/m2=false）与
`sim_release_bridge`（m3/m2=true，判分桥）两个参数，脚本已替你预设。

三个脚本同构七步：[0]强清残留 → [1]mavros → [2]就绪门禁 → [3]消息流订阅 →
[4]判定节点+感知节点（带看门狗重启） → [5]任务节点 → [6]外部切 GUIDED →
[7]跟踪 → [8]清理+汇总。**一架飞机同时只跑一个**；开新任务前确认旧任务已收尾。

参数覆盖（M2 脚本已内置）：`search_speed_m_s:=1.2`（CV 检出需要慢速）、
`search_degrade_timeout_s:=120`。要改其他参数，直接在脚本 [5] 步追加 `-p`。

## 3. 判分与验收线

- 判分输出两处：`judge.log` 的 `release=N target=drop_X ... zone=A score=S (累计=T)`
  与 mission.log 的"仿真投放判定: success=1 ..."；
- **验收线**：投放 2/2、双桶 A 区（误差 < 桶半径：15cm 桶 0.075 / 20cm 桶 0.10 /
  25cm 桶 0.125m），总时长 ≤180s（M4 线），任务总超时硬上限 240s；
- 无视觉/判读节点不在时：投放 0/2、拍照确认 0 属预期（1s 超时兜底放行，不阻塞）；
- **随机布景**：`python3 ~/sim_scripts/randomize_scene.py [--seed N]`——投放桶/
  侦察桶/危化品标识在任务区内随机摆放（保最小间距），三处真值自动联动
  （飞行世界 + generated_scene.yaml 真值替身 + judge 判分参数），只重启 gz
  不动 SITL（无长等待）。跑完任务脚本会输出结构化"完成事项"（各段耗时/
  投放明细/误差/判分/拍照确认）。

## 4. 飞行前/后检查（对齐 SSOT §7 铁律的习惯）

起飞前：
- `pgrep -af _node` —— 确认没有僵尸任务节点/别的控制器在操纵飞机
  （残留 DISARM 态节点会每秒发 disarm 把新任务在空中打下来——09-13 实证）；
- FCU 状态 disarmed、模式 STABILIZE/待切；
- 飞机在起飞坪上（上轮异常降落会停在场地里 → 下轮 home 错，必须 reset）。

结束后：脚本自动收尾清理；若 ssh 断连导致清理没跑完，手动：
```bash
pkill -f "cuadc_mission_[n]ode"; pkill -f "mavros_[n]ode"
pkill -f "bucket_cv_[p]erception"; pkill -f "virtual_drop_[j]udge"
# ⚠️ pkill -f 的模式必须用 [x] 转义写法——明文写会匹配自己的命令行自杀（老坑）
```

## 5. 排障速查表

| 症状 | 原因 | 动作 |
|---|---|---|
| 任务全程 `mode:''` 空转 | 跳过了门禁（旧版误放行 GPS 卡 0） | 用 v2 门禁重跑② |
| 门禁 refused（5762/5760） | 不稳定窗；或 5762 监听消失 | v2 自动改探另一端口；一般 1~5min |
| `ABORT: 5760 已被占用` | 泄漏的 mavros/fly.py 抢槽 | reset_sim.sh（它杀得干净） |
| 空中莫名 DISARM | 残留任务节点共享 mavros 发 disarm；或 GCS 断连 | 查 /tmp/sniffer.log（抓包定责）；跑前清场 |
| GPS 一直 (0,0) | 不稳定窗 / 耦合僵死（空转数小时后） | v2 自动重启 gz 自愈；自愈 4 次仍 0 → 查 gz 日志 |
| `start_gzgui` 说看不到窗口 | X 不在 :0 / GUI 没起完 | 重跑一次；`tail /tmp/gz_gui.log` |
| 相机无帧 / 全画面发白 | gz 服务端渲染未起 / 光照 | 确认世界带 Sensors 插件；本手册配套世界已修 ambient=0.4 |
| `pkill` 命令自己死了(ssh 255) | pkill -f 自匹配 | 模式改 `[x]` 转义写法 |
| ssh 连不上 | IP 变了（换热点常见） | `ssh ~/.ssh/config` 改 HostName；扫网段定位 |
| 任务"已武装"启动即失败 | 上轮残留飞行未落地/未上锁 | 紧急 disarm：`ros2 service call /mavros/cmd/arming mavros_msgs/srv/CommandBool '{value: false}'`；再 reset |

## 6. IP 变更处理（换热点/换网必读）

`~/.ssh/config`（Windows 侧）的 `jetson` 别名固定了 IP。换网后：

```bash
# 1) 本机 ipconfig 看新网段 → 2) 扫 22 端口定位 Jetson（10 秒）：
python -c "import socket,concurrent.futures as cf;
probe=lambda ip:(lambda s:(s.connect((ip,22)),ip)[1] if s.connect_ex((ip,22))==0 else None)(socket.socket())
...
"   # 或任何扫段工具；也可在手机热点设备列表里直接看 Jetson 的 IP
# 3) 改 ~/.ssh/config 的 HostName → 4) 首连接受新 host key：
ssh -o StrictHostKeyChecking=accept-new jetson
```
