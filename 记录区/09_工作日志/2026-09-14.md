## 二、RTK 线：四坑收口，参数维度穷尽排除

### 1. rtk_setup.py 四坑（全部当日修复，文件已改）

1. **写参数成功回读正确 → 跳过重启**：而 SERIAL4_BAUD/GPS2_TYPE 均需重启生效——
   09-13 外场"写了 921 复验挂起"的真正根因（当晚回读 57 证实从未保住）；
2. **重启指令枚举名错误**：`MAV_CMD_PREFLIGHT_REBOOT` 在 pymavlink 中不存在
   （正确为 `MAV_CMD_PREFLIGHT_REBOOT_SHUTDOWN`）→ 重启路径从未跑通过，一跑就
   AttributeError；
3. **盯梢请求报文 ID 116 是错的**：GPS2_RAW=124（GPS_RAW_INT=24）→ 60s 盯梢从未
   请求过 GPS2，"全程无报文"判定含假阴性（修复后实测 GPS2_RAW 流正常在出）；
4. （流程坑）**参数改动后不重启直接判 rover 无数据**，与坑 1 叠加造成外场误判
   "接线存疑"——实际参数当时根本没生效。

### 2. 实测排除表（修复后跑）

| 维度 | 组合 | 结果 |
|---|---|---|
| 波特率 × NMEA | 921600/115200/57600/38400/230400/9600（每档写入+重启+盯 GPS2_RAW） | 全 0 星 |
| 协议 @921600 | NMEA(TYPE=3) + UBX(TYPE=1) | 全 0 星 |
| 串口挂载 | SERIAL4_PROTOCOL=5 / OPTIONS=0 | ✓ 正确 |
| 报文流 | 124 修复后 GPS2_RAW 每秒到 | 驱动活、解析空 |

- **结论定案：飞控侧无可挑剔，数据在物理层断（6P 线/针序/TX-RX 未交叉），
  或 rover UART1 根本没在输出**。参数维度已穷尽，后续排查不必再回头怀疑参数；
- rover 侧佐证：三 LED 亮（中间蓝=LORA、两侧绿闪），rover 本体与 GNSS 有解；
  USB(CH340, COM11) 插电脑四波特率零字节——与 RTK-01.md "USB=供电+调参" 相符
  （NMEA 标称在 UART 口），不能据此定罪 rover；
- rover 供电注意：USB 插电脑时 LED 亮不算飞控侧供电证据，测针序前先拔 USB；
- 当前参数终态已恢复定案值：SERIAL4_BAUD=921 / GPS2_TYPE=3 / PROTOCOL=5 /
  AUTO_SWITCH=0（脚本内已含恢复逻辑，扫描失败自动回写）。
