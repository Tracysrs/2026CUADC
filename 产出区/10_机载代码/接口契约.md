坐标系约定（全体遵守，SSOT §10.2-1）：本地系 = 飞控 odom 的 **ENU**（x 东 y 北 z 上）；
机体系 = **x 前、y 左、z 上**（与 ENU 同手性）；罗盘航向换算 `yaw_ENU = 90° − compass`；
任务全程锁头不转机头，任务原点 = 起飞瞬间 odom（EKF 原点 ≠ 起飞点）。

## 1. 检测话题 `/perception/drop_buckets_body`（核心契约）

`geometry_msgs/PoseArray`，每个 Pose = 一个白筒候选，**机体系**：

| 字段 | 复用含义 | 单位/范围 | 说明 |
|---|---|---|---|
| `position.x/y/z` | 筒口中心机体系坐标 | 米；z 通常为负（筒在飞机下方） | x 前 y 左 z 上 |
| `orientation.x` | **筒口直径估计** | 米，物理先验 0.08~0.35 | 感知端反算，状态机用来对号 15/20/25cm 筒号 |
| `orientation.y` | **置信度** | [0,1] | 后处理四件之后的质量分 |
| `orientation.z` | **契约版本哨兵** | 当前 `1.0` | 所有 pose 必须一致；不一致 = 契约违约，接收方拒用 |
| `orientation.w` | 保留 | 固定 0.0 | 未来扩展 |
| `header.frame_id` | 帧哨兵 | 固定 `cuadc_body_flu` | 接收方校验，不符拒用 |
| `header.stamp` | **取帧时刻** | 见 §3 | 不是发布时刻！ |

硬性要求：
- **频率 ≥25Hz**（Jetson 实测，SSOT §4.1 验收线）；**空帧也必须发**（0 个 pose 的
  PoseArray = "这帧没看到"），接收方靠新鲜度判故障，**停发 = 故障 = fail-closed**；
- 单帧 pose 数 ≤8（去重后；超限视为感知异常）；
- 同帧去重在感知端完成：中心距 <2cm 合并（SSOT §4.1）；
- 发布端 QoS best_effort（SensorDataQoS），丢帧优于堵塞。

## 2. 心跳 `/perception/heartbeat`

`std_msgs/Header`：`stamp` = 最近一帧图像的取帧时刻，`frame_id` = 节点名。
**每处理一帧发一次（含空帧）**，与检测话题同源同节奏。
消费规则（状态机/安全监控）：`now − stamp > 1.5s`（SSOT §5.3 视觉心跳超时）
→ 判感知故障 → **禁投** + 走丢目标保护；恢复自动解除。
fail-closed 原则：感知端崩溃/卡死的表现就是心跳停，接收方不需要显式"故障消息"。

## 3. 时间戳约定（P0.4，详见 时间同步设计.md）

1. `header.stamp` 必须 = **图像取帧时刻**（相机驱动回调瞬间），推理/排队/发布耗时不算；
2. 感知管线总延迟上界 `perception_max_delay_s = 1.5s`，未来戳容差 `0.05s`；
3. 状态机用 odom 历史对帧时刻做**插值夹逼**得到取帧瞬间位姿，包围两帧间隔
   >0.2s（odom 断流）时该帧丢弃，**绝不外推**；
4. 时钟类型统一：所有节点读写 stamp 前换到本节点时钟类型（`use_sim_time` 场景的
   rclcpp::Time 相减异常坑，已写死在 mission_node.cpp）。

## 4. 侦察握手（M1 已实现，M4 联调）

- 状态机到达每个侦察视点 → 发 `capture_request`：`point.x` = 视点序号（0 起），
  `point.y/z` = 该视点的 x/y 坐标（取证用）；**只发一次**；
- 侦察节点 → 发 `capture_done`：`data` = 同一序号。**语义 = "该视点证据窗口
  已开启"，绝不等价于"判定完成"**——判读结果经 §5 话题异步发布，不得让状态机等它；
- 状态机等确认，超时 `recon_photo_timeout_s = 1.0s` 兜底放行（不阻塞任务）；
- 序号去重：同一序号重复 ack 只记一次。

## 5. 侦察判读话题 `/cuadc/recon/classification`（v1.1 新增）

消息定义在 `cuadc_interfaces` 包（`ReconClassification.msg` + `ReconMarker.msg`），
与本文同步维护：

| 字段 | 含义 | 约束 |
|---|---|---|
| `header.stamp` | **融合窗口末帧的取帧时刻** | 不是发布时刻（§3 同源约定） |
| `viewpoint_seq` | 对应 `capture_request` 的 `point.x` | 判读异步产出，可晚于 capture_done 任意久 |
| `markers[].marker_index` | 物理标识稳定序号（首现顺序，0 起） | 跨窗口复用同一 id |
| `markers[].class_id` | **0..9 = 附件11 十类；-1 = 拒识留空** | 类别顺序与训练集 data.yaml 一致，勿用标准 GHS 表 |
| `markers[].confidence` | 融合窗口内该类置信度**中位数** [0,1] | 单帧值禁止直出 |
| `markers[].margin` | top1−top2 中位数（类别竞争度） | 火焰三件套/白底三类的主要拒识依据 |
| `markers[].frames` | 支持该结论的帧数 | |
| `markers[].ambiguous` | true = 两类票数竞争被拒识 | 地面站须醒目提示 → 转人眼 FPV 备份 |
| `markers[].evidence_path` | 证据目录（机载相对路径） | 可空串 |

判定规则（实现：`cuadc_perception/recon_fusion.py`，SSOT §4.4）：
帧级 top1 < 0.7 或 margin < 0.3 丢弃，灰区 ROI 全分辨率放大重推一次；
标记级 ≥5 帧同意 + 置信中位数 ≥0.8 + 票数 ≥3× 次高类才确认；两类竞争 → 留空。
**留空是合法答案**（留空 0 分，错填 −100），阈值逐类标定后只收紧不放松。

真判读节点 = `cuadc_perception/hazard_recon_node.py`（2026-09-12 上机）：
Image → TensorRT engine → 帧级门控（灰区 ROI 放大重推）→ MarkerFusion 窗口融合
→ 本话题。**帧级门控在 det 模型上的口径**：top1 = 该框置信度；runner-up = 同位置
竞争框（IoU ≥ 0.45）中异类最高置信度——det 每框单类，类别竞争体现为同位置异类
框的置信度对峙。模型 SHA-256 强校验（不符拒启）、黑帧预热、心跳 `/perception/
heartbeat_recon`、证据落盘（1s/张 JPEG + 结论 JSONL 原子写，磁盘 <512MB 停证）。

QoS：Reliable(10)——低频结构化结果，一条都不许丢（与检测流 best_effort 相反）。

## 6. 精准降落 LANDING_TARGET 流（v1.3 新增）

发布者 = `cuadc_perception/h_circle_node`（M4 全链落地）；**消费方是 ArduPilot PLND
模块（经 MAVROS landing_target 插件），不是状态机**——mission_node LAND 态零改动。

- 话题：`/mavros/landing_target/set`，`mavros_msgs/LandingTarget`，Reliable(10)；
- 语义：H 圆（ø80cm，起降区）在**机体系**中的位置与尺寸，质量门控通过才发布；
  **门控不过不发目标**——PLND 无目标 = 自然普通降落兜底（fail-safe；PLND_STRICT
  保持 0，无目标不拒降）；
- 帧约定：`frame = BODY_FRD(12)`（默认，参数可切 BODY_NED(8)，轴序相同）；
  节点内部把契约 FLU 经 `flu_to_frd`（y、z 取反）换算——坐标系陷阱单点收口；
- 字段：`angle_x/y = atan2(右/前偏移, 高度)`、`distance`（斜距）、
  `position(x右 y前 z下)`、`size_x/y = 直径(m)`、`type = VISION_FIDUCIAL(1)`；
  非核心字段 hasattr 防御（MAVROS 版本差异，上机以 `ros2 interface show` 核对）；
- 频率：≥10Hz（PLND 要求），节点按 `max_rate_hz=20` 节流；`header.stamp` =
  取帧时刻（§3 同源约定）；
- 质量门控：直径-高度一致性（0.80±0.25m）+ 连续 ≥3 帧确认（丢失清零）；
- 心跳：`/perception/heartbeat_land`（§2 同款规则：每帧照发、停发 = fail-closed）；
- 飞控侧参数（勘误后口径）：`PLND_ENABLED=1、PLND_TYPE=1`（1=CompanionComputer
  MAVLink；0=Never、2=IRLOCK——04_算法模块 §11 旧文 0/1 含义写反已勘误）。

## 7. 契约校验（可执行的部分先自动化）

```bash
# 终端 1：起假感知（30Hz，3 个模拟筒，默认 0 延迟）
ros2 launch cuadc_perception fake_perception.launch.py

# 终端 2：跑契约校验（10 秒窗口，逐项 PASS/FAIL，退出码可接 CI）
ros2 run cuadc_perception check_vision_contract.py --ros-args \
  -p duration_s:=10.0 -p min_rate_hz:=15.0
```

校验器当前覆盖（= 契约的机器可查子集）：心跳存活（≤1.5s）、检测频率下限、
frame_id 哨兵、契约版本哨兵一致性、置信度 [0,1]、直径物理边界 [0.05,0.50]m、
坐标有限性与单帧上限 8、stamp 延迟/未来戳容差、同帧 <2cm 疑似未去重（告警级）。
**契约校验不过 = 感知端不许上机**（对齐 SSOT §4.6 工程五件套）。

## 8. 变更规则

- 任何字段语义/类型/QoS/频率变更 → 本文版本号 +1，哨兵 `orientation.z` 同步 +0.1；
- 新增自定义消息（SafetyStatus / 侦察判读）时在本文件补全定义后再写代码；
- 契约校验脚本与本文同步维护，**本文与脚本不一致时以本文为准并立即修脚本**。
